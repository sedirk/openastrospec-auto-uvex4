# 观测资料库与数据生命周期设计草案

日期：2026-10-24。状态：原地光谱项目库已实现；本次增加确认后受控清理。
用户已选择“先做原地资料库，归档盘以后选”；归档搬迁仍不在本版范围。
用户新增授权是实现真实清理能力并先给出预览，不是执行当前历史资料的清理授权。

用户要求在自动采集与后期处理之间增加类似 Adobe Bridge 的资料库，统一
光谱、测光成果和日志的回看、筛片、删除、归档。本草案不授权对当前原始
数据执行删除/移动，也不修改冻结采集基线、相机所有权、原预算或观测策略。

## 1. 当前存储情况

本机元数据只读盘点，不读取全部 FITS 像素、不遍历重解析点；数字为逻辑
文件长度，不等于压缩/稀疏文件的物理占用。容量单位 GiB。各行根目录互不重叠。

| 已核对的项目数据根 | 容量 | 主要内容 |
|---|---:|---|
| ProgramData 中的 QHY 数据/服务工作目录 | 162.86 | 10,004 张 FITS 约 156.19，10,000 张 PNG 约 6.61 |
| LocalAppData 中的 UVEX-ADV 工作目录 | 65.79 | observations 61.92，main-focus 1.49，star-detection 1.38，maintenance 0.90 |
| 源码仓库及本地生成物 | 约 19.7 | output 13.00、tmp 3.44；不是 Git 本身占大头 |
| N.I.N.A. 保存目录 | 11.63 | 756 张 FITS；目录来自本机 Profile，不写入公开配置 |

以上合计约 260 GiB，不是整盘所有项目相关数据的穷尽证明。C 盘总量约
475.84 GiB，盘点时可用约 78.80 GiB；未发现另一个固定数据盘。归档介质
尚待用户选择；同一 C 盘复制一份并不能释放空间。

QHY 文件名角色粗分：`PHOTOMETRY-R` 8,873 张约 138.99 GiB，`PHOTOMETRY`
28 张约 0.44 GiB，`ACQUISITION` 1,103 张约 16.77 GiB。9,984 条 frame index
记录交叉计数与文件数存在 20 张差异，必须保留为待对账项。角色名不证明
光度质量合格；但也不能把标记为测光的原始序列当作定位缓存删掉。
observations 中 15,600 张 `.fit` 约 60.30 GiB，多为 G3 取场/导星证据。

正式 observations 根有 41,041 个直接运行子目录。有限抽样确认模拟测试
记录混入正式根：`SIM-NIGHT`、SIM 相机身份、`SIM_STAGE` 事件和测试目标名
同时存在。源码 `ObservationRunPersistenceSession.CreateAsync` 固定使用
LocalApplicationData/UVEX-ADV/observations，未提供独立存储根，是明确的隔离
缺口；不能据此宣布全部目录都是测试或可删。测试隔离应先于下一轮大规模回归。

## 2. 产品位置：独立入口，共用离线组件

工作流为：Auto 采集 → Library 资料库 ↔ Spectral Studio 后期处理。

- 独立资料库窗口/快捷方式，不把管理逻辑塞进 N.I.N.A. 的实时控制线程。
- 复用现有离线 Python 3.11 环境、Tk 图像浏览组件、FITS Inspector、光谱
  产品读取和 `.astroproj`，不复制提取/定标引擎，不升级固定科学依赖。
- SQLite 保存可重建文件索引，以及不可从原片重建的人工标签、引用；原地
  建库，不为了“导入”再复制原片。缓存按需生成且有容量上限。
- 本版预览仅驻留内存、不生成持久缩略图；人工标签应随库文件备份。
  归档位置映射/执行事务属于后续阶段，未在首版伪装为已支持。
- 库程序不提供设备连接、曝光、导星、调焦、屋顶或串口命令。
- 前期继续按既有格式写数据；库增量读取。活动运行可看，不能由库搬移或
  清理正在写入的数据。未知/损坏元数据不能误判为活动，也不能直接判可删。

## 3. 第一屏及核心工作流

左侧：观测夜、目标、通道、真实/模拟/未知、成功/部分完成/失败、留片状态。
中央：目标/运行卡片与帧缩略图或列表；可按容量、时间、曝光和质量排序。
右侧：2D 原图、已标明 pixel/波长轴的 1D 光谱、光变曲线、元数据和来源。
下方：目标执行时间线、失败原因、选中帧的原始/派生链路及相关日志。

必须把以下概念分开：

1. 采集系统判定接受/拒绝；
2. 后期处理的输入接受/拒绝；
3. 操作员的留片/弃片、星级与备注；
4. 文件在本机、归档盘、离线介质或已明确删除。

“弃片”默认只改库标签，不改 FITS Header、不移动文件；失败目标也可以有
值得保留的帧，成功目标也可以包含坏帧。提供同目标跨夜比较、失败原因筛选、
未处理/已处理/已交付视图和批量标记。光谱和测光原片角色不得混入同一提取组。

## 4. 数据合同与真实交接

索引器消费现有合同，不仅从文件名猜测：

- 整夜 journal → outcomes → observation run/continuation segments；
- `ObservationRunManifest` 的 plan/snapshot/gates/counters/evidence/journal；
- ATR evidence 中 captureId、role、qualityAccepted，以及 FITS 的 OBSRUNID、
  UVEXCID、UVEXSTG；完整目标名按现有编码处理；
- QHY `frames.jsonl` 为长期帧主索引，manifest 的窗口不能冒充完整序列；
  容忍正在写的末行，保留 role、曝光时间窗和时间不确定度；
- reduction manifest 中 inputs/frameSelection/artifacts/trace/wavelength/warnings；
- `.astroproj` 和共享校准/生产局部双镜模型的来源引用。

同一物理文件可被多个运行/成果引用，容量与操作清单只计一次。失联文件
标“缺失/介质离线”，不静默删库；相同文件名不代表同一帧，哈希按需计算。

### 精确选片必须贯穿后期两条入口

审计时 Studio 会在 load_project 后重新 `scan()`，保存时重建 parameters；
快速入口用 ObservationGroup.files，但还会 glob LED 平场；完整预设入口
再次按 TOML glob 发现输入。因此只加一个媒体过滤器或传 dataRoot 会让弃片
重新进入处理，不能作为完成的库→后期交接。

首版已在现有 schema-1 的 parameters 中增加 versioned `librarySelection`：
每帧带绝对路径、SHA-256、target 和明确 role；归档位置解析留待后续阶段。
旧工程保持兼容；保存/加载保留该字段。库工程不再按目录重新发现选定角色；
快速处理和完整 workflow/flat trial 均接受显式输入 overrides。
“未提供选择”与“显式选择为空”不同；空清单、缺失、哈希变化不能回退全目录。
所选光谱/标准星/校准角色在用户确认后才传给现有处理引擎。

## 5. 删除与归档必须解决引用，不只是操作目录

现有 evidence、QHY frame index、后期 manifest、工程和局部双镜模型广泛
保存绝对路径。直接搬走一晚的数据，会破坏后期、日志复盘、历史回归甚至
生产模型来源。现有 `organize_outputs.py` 会改写内部 JSON，不能拿来当
通用原始观测归档器。

资料库维护独立 location 映射和操作日志，不改写原始归档 JSON 或 FITS。
归档：规划精确文件/依赖 → 检查空间与目标路径 → 复制 → 逐项哈希验证 →
提交归档清单/映射。目标不能落在源树内；失败可续作，不先删源。
原始生产读者尚未支持映射时，被运行时标定/模型直接引用的证据保留在原位。

清理分三类：

- 可重建的缩略图、派生预览、旧构建/测试产物：显示精确范围和可释放容量，
  在不触及当前使用版本/工作目录的情况下允许独立清理。
- 归档后释放本地副本：核对归档完整性与引用可解析性后，显示实际删除清单，
  由用户确认。保留归档位置和恢复/读取能力。
- 用户主动放弃的原片：另行明确确认不可恢复后删除，并保留删除记录及
  断开的成果引用；不能用“任务失败”代替用户删除决定，也不能假装仍可重跑。

标记、回收站、永久删除不是一回事。移动到同盘回收区不会释放空间。活动
写入、未结停止/运动责任文件和共享校准必须被明确识别；人工单次确认不
变成今后自动删片授权。库索引器不能跟随符号链接/目录联接扩大清理范围。

## 6. 分阶段交付与验收

1. **先止住无效增长并建原地库。** 测试存储与真实档案隔离；存储仪表盘、
   真实/模拟分类、run/帧/成果/日志关联、人工筛片、按需预览和清理 dry-run。
   这一步不搬动历史文件，不自动执行删除。
2. **选片实际进入后期。** 精确清单保存/重开一致，验证快速与完整处理两条
   路线的实际 inputs 都不包含弃片；共享校准不被隐式剔除。
3. **归档与受控释放。** 外置盘/NAS 选择后做复制、校验、映射、离线介质
   显示、恢复/读取及删除计划确认。验证断电/取消/空间不足/重复执行。

必须用现有真实历史 manifest 和帧作只读兼容测试；破坏性用例只用独立生成
夹具。覆盖坏 JSON、半行 JSONL、损坏 FITS、重名、多目录、路径变化、共享
引用、续段、多种科学角色、零帧、离线盘和写入中的运行。回归固定科学环境。
不能把“界面里看不到弃片”当成“处理引擎确实没用弃片”。

## 7. 本轮边界

首版代码在 `reduction/src/uvex_reduce/library_{catalog,ui,preview,selection,lifecycle}.py`。
它与 Studio 共用现有固定 Python 环境，新增 `uvex-library` / `python -m
uvex_reduce.library_ui` 入口，桌面和开始菜单通过 `install-library-shortcut.ps1`
创建。`--index-only` 可无窗口增量更新已登记目录（新库采用已存在的常规数据根）。

已实现：原地/增量/分页索引、通道与真实/模拟/未知分类、文件/运行/证据/后期
输入输出关联、留弃/星级/备注、容量统计、按需 2D/1D/测光 CSV/文本预览、精确
后期工程交接，以及仅供审阅的清理/归档计划。实际保留/拒绝质量与人工筛片独立。
FITS 身份与侧车冲突如实显示；QHY job 不覆盖主运行的终态；字符串 False 不会
被当作已接受。预览有界采样不参与质量计算，光谱单位/掩膜/二级风险不被隐藏。

首版不是完整 Adobe Bridge 克隆：使用分页列表与选中预览，尚无缩略图墙、跨帧
叠加比较、后台自动清理、归档复制/释放/恢复、通用测光处理交接或新测光算法。
光谱 science-only 工程可回看，但原后期校准仍需合适的 standard 与配置；不匹配
历史完整预设时明确提示，不能拿未选文件凑齐流程。

本轮未删除、移动、归档实际观测数据，未修改采集/设备程序，未重启设备所有者，
未开始观测或真实后期批处理。测试写入正式 observations 的隔离缺口已记录，但
尚未修复；本轮新增 Python 破坏性/界面测试均使用临时夹具，不增加模拟观测档案。

回归：Python `ruff` 通过，完整 `pytest` 212 passed / 2 skipped（宿主 Windows
符号链接创建权限；重解析点保护另有回归），冻结设计 4 文件校验通过。包含实际
quick/full resolver 输入、隐藏 Tk 控件/交接、保持原片、坏文件/半行、身份冲突与
主运行状态归属测试。历史只读兼容样本为 943 文件/458 FITS/9 run，第二次解析数 0。
界面已重新整理为筛选、文件列表与预览分区；星级备注/选片篮按需打开。
容量窗口默认显示摘要卡片、类型比例条和目录，原始 JSON 仅留在技术详情。
新增映射窗口的尺寸/DPI/颜色/关键控件可见性回归，详见
`docs/library-ui-visual-checks.md`。通过 computer-use 检查了新版 1100×720、
125% 下的主界面/展开下拉框，以及 900×660、125% 的容量页真实截图；
并正常重开新版资料库，对正式索引与历史帧预览做只读截图检查。
不是跨机器逐像素黄金图比较，也不宣称覆盖未检查的显示器/DPI 组合。
未改 C# 采集代码，本轮未重跑 .NET 硬件侧完整构建。

## 8. 光谱项目层：由运行与后期合同组织，而非只按文件夹

用户追加要求参考 Athenaeum，并允许必要时配套调整前后期代码。本次不引入
另一套提取或定标引擎，也不把相机/屋顶控制带进资料库。直接消费已有合同：

- 整夜 outcomes 的目标结果、saved observing-night、retainedScience 和显式
  segmentRunIds；一个目标恢复的续段可关联，不按名称自动合并不同运行。
- 运行 manifest 的阶段/质量门、recentEvents、evidence 和 counters。失败的
  零帧目标仍作为项目展示，流程完成不等于谱质已通过。
- 原始 SCIENCE/PROBE、同步测光和盯缝证据分组。最终试拍明确以
  effectiveStageRole=SCIENCE 留用时只按同一物理文件计数一次；记录里汇总的
  acceptedFrames 与索引查到的文件数分开保存，出现差异要提示，不相加。
- 后期 `*_run.json`、`*_calibration.json`、`full_workflow.json` 和 `.astroproj`
  用明确输入/输出引用建立链路。没有自动观测 run ID 的旧手工后期成果也可浏览。
  共用 bias/dark/flat 不会把两个科学目标并成同一项目。
- 已有 `LibrarySelection` 的逐文件 SHA-256 清单、AstroProject、Studio 和
  quick/full pipeline 输入解析继续复用。项目的“科学帧 → 后期”选择明确合格、
  未人工排除、未缺失的光谱科学帧；其他试拍/未知质量帧可经文件页人工复核加入。
  打开工程不等于运行提取；不能为凑齐校准自动抓取未选文件。

主页分为“项目与运行”和“文件浏览”。项目可按观测夜、目标、结果、后期进度和
来源分组；真实/模拟/未知与运行结果均可筛选。观测夜优先用保存的日程，旧记录
回退到明确的北京时间中午至次日中午，不使用文件修改日。分组作用于当前分页，
搜索与计数作用于索引结果；不把分页小计冒充全夜总量。

项目检查区分为光谱预览、项目文件、运行与质量、后期与来源。复用有界原始2D、
一维光谱/CSV 和测光曲线预览；原始ADU、像素/波长轴、掩膜与定标状态保持区分。
预览只能显示已有数据，不私自重新运行提取。项目容量按关联文件身份去重；
跨项目共享文件的容量不可把各卡片简单相加当作整库占用。

新增 `.astroproj` 只登记那个明确文件，不自动扫描用户选择的整个父目录。
刷新会检查已经登记的工程是否改动；新成果仍需要登记其数据目录并更新索引。
原始记录可重建为索引，人工标记仍独立保存；数据解析版本更新后需要一次增量
重读元数据，不能把旧版错误归类的 OFFLINE-* 回归记录继续冒充真实天空数据。

### 8.1 不采用、缺失与实际删除必须可见地区分

项目层首版不提供物理操作；下文第 9 节增加独立确认执行器。界面“不采用 / 撤销”仍仅操作
资料库标签，明确提示：未删除、未移动、未进入系统回收站，释放空间 0 B。
它不改变前期质量判定，也不改变已经存在的后期工程及成果。

每个选中成员显示完整可复制路径，并提供直接“定位源文件”。文件存在时用
Windows Explorer 选中原文件；路径缺失时只打开最近存在的上级目录，并说明
这是回退定位。缺失/离线不等于已删除、更不能猜成已进回收站。项目日志无原片
时仍提供源 manifest 路径。物理清理使用独立操作回执，不能复用人工筛选标记
表示物理结果；原位存在、历史清理回执与操作员标记分别显示。

参考审计与历史实例见
`docs/reports/2026-10-24-spectrum-library-integration-audit.md`。此改动是离线消费层
和后期交接适配，没有改变冻结设备所有权、采集质量门、停止/天气安全链。

### 8.2 历史资料回放与性能验收

正式库升级前使用 SQLite backup API 保存一致性备份（包含已提交 WAL 数据），
随后原地重读 177,926 个文件的元数据、5 个登记目录。文件数和逻辑大小保持
177,926 / 254,122,480,614 bytes（236.67 GiB），未删除、搬移或改写原片。
在这一台机器上的首次全量版本升级为约 760 秒；这不是后续增量扫描耗时承诺。
项目列表的首次历史查询约 3.6 秒，查询与预览放在后台，Tk 线程只应用结果。

实测发现项目上下文/恢复段按 source_file_id 清理缺少索引，已补两项索引及
EXPLAIN QUERY PLAN 回归，要求 DELETE 走 SEARCH 而非逐文件全表 SCAN。
已登记工程变更只检查该 .astroproj，不顺带扫描整个父目录。

历史 HD 18552 运行 UVEX-20261021T182813Z-73b715bb6c9343b 与整夜日志核对：
观测夜 2026-10-21、科学帧 2 / 合格 2、有效角色之外的试拍 4、科学帧积分
1,200 秒，自动交接可选原片 2 张。明确留用的最终试拍按同一物理文件只算一次；
运行日志汇总与索引无差异警告。历史 Regulus 的原 Header 与处理目标差异和
旧后期产品链另由真实只读样本及独立合同回归覆盖，不改写旧 FITS 来消除冲突。

真实库还包含历史 .NET 测试写入的运行记录，不能只因为位于 observations
目录、宣称 Completed 或填写了预期相机名，就把它当真实观测。来源必须基于

## 9. 按项目清理：预览、明确确认、逐项回执

本次实现离线清理能力，但对用户当前历史资料只生成预览。没有收到具体清单、
具体方式的确认，不执行回收或永久删除；实现代码或点击“预览”不是删除授权。
不控制 N.I.N.A.、PHD2、设备服务，也不自动终止任何写入者。

### 9.1 三种操作不能混用

| 方式 | 文件影响 | 当次预计释放空间 |
|---|---|---|
| 仅标记不采用 | 只改资料库 review，不变动物理文件 | 0 B |
| 移入系统回收站 | 通过 Windows Shell 回收，不是自建隐藏目录或永久删除 | 0 B；同盘回收站仍占容量 |
| 永久删除 | 只删除已预览、已确认且仍通过复核的明确文件 | 单独显示估计值，不等同于逻辑文件长度或保证值 |

本功能不清空系统回收站，也不把回收失败改为永久删除。网络盘、不可回收路径、
系统拒绝或结果不确定时停止，保留具体结果。恢复/清空可在应用外发生，因此
“上次已回收”只说明当时的回执，不保证文件现在仍在回收站。

### 9.2 保护与候选范围

- 所有科学原片、测光原片、试拍 FITS、校准文件、后期科学产品默认保护，
  包括质量未通过、被人工标记不采用或处于失败项目的文件。
- 保留项目/运行日志、帧索引、`.astroproj` 和依赖证据；后期输入、共享校准、
  运行时模型引用不因目标失败或“可以重新拍”而放行。
- 本版可执行候选重点是已终止运行、有明确原片对应的冗余预览图。仅 PNG
  扩展名、文件年龄、目标名或用户不采用标记不构成可清理证明。
- 未知角色、缺失/离线、索引或依赖记录已变、活动/未确认终止的运行、符号
  链接/目录联接、多个硬链接、无法验证的路径保持保护。清单不得展开为递归删目录。
- 项目按已索引关联文件去重列出占用、候选、保护及原因；多项目共享文件在
  最终选择清单只计一次。未归属文件须单列，不能从总量中悄悄消失。

### 9.3 确认和执行边界

预览绑定操作方式、精确文件列表、目录范围、文件身份、大小和时间戳及摘要。
确认页再次显示数量、方式、估算和不可恢复提示，用户只需点击一个明确写出
操作方式的确认按钮，不要求输入口令或摘要。后台仍绑定同一精确计划。修改勾选或
操作方式后，旧确认失效。执行前重新检查依赖和文件状态；文件被替换、出现
新引用或不能证明仍为同一候选时，不使用旧预览继续删。

操作前持久记录意图，逐项记录成功、失败、取消或未知结果。遇到错误停止并
显示已经完成的部分，不能把部分成功说成全部完成或全部未动；重试不能把原
路径后来新生成的文件当成上次未完成的目标。索引保留墓碑/缺失和独立回执，
不销毁人工备注。永久删除不可由资料库撤销，撤销“不采用”也不能恢复文件。

### 9.4 验证范围

破坏性回归仅使用隔离临时夹具，覆盖确认缺失/不符、清单篡改、执行前变化、
新依赖、写入占用、硬链接/重解析点、取消、部分失败、回收不可用与不降级、
重复提交、已删除路径重新出现和物理状态/标签分离。历史档案验证只读，报告
是预览而非授权；既有原片字节、名称、路径及修改时间不因预览而变化。
