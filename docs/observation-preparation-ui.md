# 观测前准备界面

## 职责

“自动准备”用于回答：本轮有哪些已保存资料、还缺什么、应去哪里处理。
它不是第二套高级设置，也不执行设备连接、对焦、切缝或观测。
首页固定显示静态核对摘要，下面是两个始终可见的平级子页，不使用嵌套折叠。

## 日常使用（0.4.0.231 起）

“核对与入口”由七张重复职责卡收敛为三块：

1. **目标与曝光**：查看当前目标，直达目标定位策略和采集计划。
2. **当前设备与光学配置**：显示当前主控 Profile、实际保存的相机选择、设备所有者、
   已应用的安装标定与本夜配置。正常观测沿用安装记录，不必每晚选方案、填哈希或生成草稿。
3. **待处理项（具体原因）**：直接列出静态检查的失败原因；修改后点“重新检查当前配置”。
   无问题时明确显示没有静态阻断，不把它称为实机已就绪。

日常顺序是选择目标、确认曝光计划、查看准备摘要，再由操作者显式启动。
只有更换设备或光学配置时，才需要使用“更换安装标定…”和“核对本夜配置”。
重新检查只验证已应用配置，不会应用尚未加载的下拉框选择，也不会连接或操作设备。
关闭自动确认的旧 Profile 仍可通过该按钮主动执行同样的完整文件校验。

### 安装标定不是拍摄方案

历史 `DF-UVEX4-FIELD-…` 项是调试期间保存的安装、设备身份和运行参数记录，
不是深空目标列表或推荐曝光档位。下拉框现在用文件日期、狭缝、导星曝光摘要显示；
工程 ID 保留在说明中。默认只呈现自动配置项、当前选择和最新记录，其余通过
“显示历史调试方案”查看。历史文件不删除。

目录同时发现系统级和用户级 commissioning 记录，避免丢失用户目录中的已验证重绑定包。
浏览下拉框不持久化、不应用；只有加载才更改应用记录。新配置默认不在启动时自动覆盖
明确选择的安装包；既有显式“启动加载最新包”设置仍被尊重。

### 来源标签不代表设备所有者

候选项旁边的 Profile 名称只是该记录的来源。同一设备 ID 优先显示当前 Profile 的记录，
并标明来源，不把历史“测光”标签当成光谱主控归属。生产所有权不变：

- 光谱主控 N.I.N.A.：ATR585M 及共享设备编排。
- PHD2：G3 导星相机。
- 独立测光 N.I.N.A.：QHY 测光相机、滤镜轮和 GS350 测光电调焦。

光谱主控的原生相机选择若不等于绑定的 ATR，或仍选择了测光滤镜轮，准备页会显示明确错误。
不会为了通过准备检查而自动打开或热切换物理设备。发现候选只保留已有有效选择；
空值且候选唯一时才自动填入，多候选或未知既有身份不擅自替换。

| 内容 | 唯一主要入口 | 自动准备中的呈现 |
|---|---|---|
| 目标、定位策略、曝光预算 | 观测计划 | 目标摘要及直达按钮 |
| 已导入的本夜光学配置、期望狭缝 | 自动准备 → 本夜配置 | 当前选择、导入与下一轮期望值 |
| 波段、波长参考、滤镜安装意图 | 自动准备 → 本夜配置 → 准备草稿 | 明确仅写草稿 |
| 台站方案、设备候选、完整标定包 | 高级设置 → 设备绑定 | 状态摘要及直达按钮 |
| 监督方式、环境能力要求 | 高级设置 → 站点与模拟 | 当前策略摘要，不在核对页编辑 |
| 主镜对焦、狭缝 / M2 动作 | 设备手控 | 仅导航，不自动执行 |
| 本轮实际流程与证据 | 运行概览节点图、诊断与证据 | 仅导航 |

“设备绑定”保留原始引用的工程维护区，但正常配置优先加载整套方案或导入标定包。
加载方案和选择候选不构成连接成功，也不自动获得设备动作权限。

## 不能混淆的状态

- **静态资料齐全**：仅说明当前保存字段通过静态检查。设备连接、实际光学位置、实时安全及运行时身份仍需正式流程复核。
- **期望狭缝**：下一轮运行的要求，不是实时槽位读回；选择本身不转动机构。
  选择其他合法槽位不会改写已导入的锁定本夜配置；两者不一致仍会在启动复核时阻断，须导入对应的新配置。
- **准备草稿**：记录意图并汇总已有参数，不是锁定本夜配置；生成草稿不会使缺失的实测证据通过。
- **监督方式**：保存的运行策略，会影响下一轮环境检查及收尾方式。它不是草稿标签，也不是本次 N.I.N.A. 会话的真实控制授权。
- **运行中**：准备参数和设备候选不允许编辑，正在取消仍属于未结束；查看页面与导航不受此限制。

核对计数保留原静态运行条件，并纳入目标缺失与无效狭缝。待处理事项直接显示具体静态原因，
不再仅报告“有 N 项未通过”并要求操作者猜测高级分类。字段编辑仍保留在对应专业入口。

## 实现与验证边界

安装标定的文件校验与目标、原生设备选择等启动条件分离，避免目标未选等问题把完整标定误报为无效。
校验使用隔离配置快照，不临时给可变 Profile 写入通过标记；只有 preset 和锁定本夜配置的
哈希、内部引用、身份等原检查通过后才确认。界面中的确认标记只读，不能人工勾选冒充校验通过。

本次不更改 canonical stages、设备所有权、采集策略、运动预算、质量门、屋顶策略或真实会话授权。
前端入口仍使用同一生产编排器；没有新增准备执行引擎。

离线 WPF harness 直接实例化真实 XAML，覆盖两个子页、移入的高级分类、窄窗滚动、
按钮与参数禁用、中英文，以及静态核对文案。构建和离线渲染不能代替安装后
N.I.N.A. 原生面板实例化，更不能代替天空闭环测试。

## 手动接管后重开观测：旧入缝记录

若故障代码为 `PHD2_LOCK_RECOVERY_PRE_GUIDE_CALIBRATION_INVALID`，先看诊断中的
源运行、校准年龄和保存/当前导星速率。这是旧未结入缝的恢复门，不等于当前手动导星不稳定。
已人工接管并放弃旧自动恢复时：结束曝光、停止手动导星、取消旧自动运行，再点击
“清除导星相机旧状态”，明确确认接管。记录保留为未完成历史，不会回程、校准或开始曝光。
缺少空闲/身份读回、存在多个未结记录或清单校验失败时不允许接管。
“新开一轮”和“恢复”不会自动代替该确认；下一轮仍须正常验证校准和重新定位。
