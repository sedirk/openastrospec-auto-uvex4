# 双 N.I.N.A. 协同采集：程序实现与配置

更新：2026-09-10。采集首次实现：`0.4.0.139`；配对界面首次改进：`0.4.0.140`；
当前收口与已安装插件：`0.4.0.167`。
设计依据：[ADR-0014](adr/0014-dual-nina-coordinated-acquisition.md)。
首次使用先看[同步测光快速入门](photometry-collaboration-quick-start.md)：按两端角色逐步配置，
不必先理解内部 worker、命名管道或作业枚举。

本页描述已接入源代码的第一版，不是双实例天空联测通过报告。后续插件已按单独授权
安装并用于主控实测，但截至本次收口仍未迁移 QHY 所有者：当夜使用旧独立测光服务，
没有将第二 N.I.N.A. 的原生相机/轮子/调焦联测标记为完成。安装插件不会自动迁移 Profile
或启用 worker；单实例共享 runner 的成功不替代设备交接。完整后续路线见
[高级序列协同规划](nina-advanced-sequencer-coupling-roadmap.md)。

## 1. 设备边界

| 实例/进程 | 本版负责的设备 | 明确禁止 |
| --- | --- | --- |
| 光谱 N.I.N.A.：`SpectroscopyMaster` | ATR585M、C11 电调焦，以及赤道仪、屋顶/镜盖、环境设备和整台运行调度 | 直接打开 QHY、争用测光轮或 GS350 电调焦 |
| 测光 N.I.N.A.：`PhotometryWorker` | QHYminiCam8M、测光滤镜轮、GS350/ToupTek 电调焦 | 赤道仪、导星、屋顶、天气、安全监测、镜盖/平场装置、旋转器、开关以及 UVEX 控制 |
| PHD2 | G3M2210M；由光谱主控调度导星 | 作为 QHY 采集服务 |
| `UvexAdv.Service` | UVEX4 COM5；由光谱主控调度 | 扫描其他串口或被第二个串口拥有者同时接管 |

“主控调度”不改变 PHD2/G3 与 UVEX 服务/COM5 的实际唯一拥有者。未来新增测光相关
设备必须单独加受限能力；本版没有任意设备命令转发，也没有给测光端整台设备权限。

## 2. 已接通的生产路径

主控 Dockable 与主控 Advanced Sequencer 目标容器仍共享
`RealRunConfiguration → ObservationCoordinatorHost → RealObservationStageRunner`。
把主控 QHY 端点改为 `nina://<测光 Profile GUID>` 后，以下作业都走同一个 worker：

- QHY 广域定位见证、QHY/G3 同指向配对短曝光；
- 光谱曝光期间的单滤镜或多滤镜循环测光；
- 作业状态、预览、暂停、停止、租约续期和实际保存文件索引。

worker 复用 `QhyJobCoordinator` 的作业、质量分析、控制租约和幂等规则。设备适配器
只使用 N.I.N.A. 原生 camera/filter-wheel/focuser mediator，以及
`ImagingMediator` / `ImageSaveMediator`；不加载自己的 QHY SDK、不另开物理相机。
原生图像显示、保存及 worker 的“OpenAstroSpec 测光协同”面板都可见。

本版提供两种接收外观，采集实现相同：

1. 在测光协同面板中显式允许本次会话，直接接收主控作业。
2. 先在面板允许会话，再启动含一个“OpenAstroSpec 测光协同接收”项的原生高级序列。
   该项等待主控作业、显示实际状态，并在取消时停止和等待作业终态。

第二种使用原生序列实际持有的相机锁；第一种在拍摄准备/曝光期间取得并释放自己的
原生相机锁。不会因为高级序列已锁定相机而误判自身占用，也不会解除别的采集者的锁。

### 光谱定位优先，测光让路

QHY 的两种用途共用测光 N.I.N.A. 这个唯一拥有者，不由光谱实例另开一遍相机。
光谱需要新的广域见证或 QHY/G3 配对帧时，共用客户端串行化启动请求：

1. 如果本主控、本父运行的连续测光仍活动，先请求帧边界暂停。
2. 等待本帧曝光、原生保存和滤镜/调焦读回完成；`Pausing` 不当作释放。
3. 确认暂停后结束旧测光作业，写入 `owner.yield-to-acquisition` 事件和
   `YieldedToAcquisitionRequestId`。收到 `Cancelling` 也仍须等真正终态。
4. 主控重新检查现场准入和暂停状态、重新取得曝光前赤道仪读回，然后启动定位曝光。
5. 定位/入缝/导星恢复后，主控用新幂等子作业续测；不会在定位过程中自行抢回相机。

等待上限为三分钟，外层配对时效/取消期限更短时仍服从较短期限；不无限重试，也不把
过期 G3/QHY 配对放宽成有效证据。无法确认相机释放时不重叠开曝光。旧帧、覆盖缺口和
父运行焦点累计预算全部保留。其他运行、人工暂停/停止、手动接管优先级更高；普通
停止或故障没有让路标记，不自动当成测光续拍。主控顶部进度和测光面板显示让路状态。

### 高级序列的第一版边界

只接受一个 receiver、原生顺序容器与空的开始/目标/结束区。递归拒绝其他执行项、
并行容器、条件与触发器，执行检查点再次验证。不能直接塞入旧的深空拍摄模板，
也没有自动执行用户脚本、自动对焦扫描、抖动或独立翻转。需要的曝光/滤镜循环参数
由主控冻结的测光计划提供。

这是一条可见的受限高级序列接收路线，**不是完整的任意测光模板编辑/导入功能**。
全夜多目标原生条件、自动对焦扫描和跨侧联测屏障仍按路线图分阶段实现和验收。

## 3. 主控顶部“同步测光”总开关

- 位于自动观测主控台固定顶部，切换标签后仍然可见。
- 开启：科学阶段启动 QHY 并行测光；关闭：不启动、不恢复、不补开测光作业。
- 关闭记录为 `QHY_PHOTOMETRY_DISABLED_BY_OPERATOR / coverageStatus=not-requested`，
  不伪装成成功测光，也不作为“测光缺失”故障。
- **不影响定位所需的 QHY 短曝光。** 定位、光轴配对与连续测光不是同一个开关。
- 按 Profile 保存，默认开启以保留既有行为。只能在空闲/上一轮终态修改；启动后锁定，
  暂停中也不热替换。它进入不可变动作配置哈希，两个正式启动入口的语义相同。
- 若要中途停止，应使用暂停/取消工作流，而不是勾选后偷偷遗留一个旧测光作业。

## 4. 部署前准备与配置

以下是后续获得安装/设备授权后执行的步骤，不是自动执行的脚本。

1. 在无曝光、无未结运动义务的空闲边界备份两套 N.I.N.A. Profile、现用插件和
   commissioning / Night Setup 配置。两实例必须使用不同的 Profile GUID。
2. 停止旧 QHY 服务，确认它已释放相机及轮子，禁止其自动重连，再由测光 N.I.N.A.
   接手。本版检测到旧服务进程会拒绝新的 worker 设备动作，但不会代替操作员停服务。
   回滚也须先停止、释放测光端，再启动旧服务。没有运行中自动切换拥有者。
3. 两实例安装同一版插件。光谱实例保持 `SpectroscopyMaster`，ATR、C11 电调焦、
   赤道仪、PHD2、屋顶及其他公共设备继续只在这里配置。
4. 在测光实例新建/核对独立 Profile：只选择原生 QHYminiCam8M、测光轮、GS350 电调焦。
   其他设备必须选 `No_Device` / `No_Guider`，不能只保持“未连接”。
5. 关闭测光 Profile 的“换滤镜时暂停导星”。它在原生 N.I.N.A. 中可能通过轮子间接
   停止 PHD2，所以 worker 将此设置作为明确拒绝项。
6. 测光 Profile 配置原生输出目录与**未压缩 FITS、16 位全帧**。本版不接受 XISF、
   TIFF、压缩 FITS 或非零硬件 ROI；不自动替用户修改保存格式。
7. 打开测光协同面板，选择“测光端”。“连接设置”第 1 步点击“记录所选设备（不连接）”，
   第 2 步粘贴光谱主控“复制主控编号”得到的编号。绑定状态与连接状态分开；实际型号、
   设备 ID 保留在“运行状态 → 技术详情”。
8. 点击“复制测光端地址”，粘贴到光谱主控“连接设置”的第 2 步并点击“保存测光端地址”。
   编辑框是草稿，只有空闲时显式保存才写入配置；地址不能指向同一个实例。保存地址不代表
   已连接。原有设备 StableId、曝光/滤镜/轮位和读出参数仍需与测光端一致。
9. 核验 N.I.N.A. 实际加载的 QHY 原生驱动/`qhyccd.dll` 路径、版本与 SHA-256，将
   主控的预期 SDK 哈希更新为此次核验的值。worker 只读取已加载模块，不复制 DLL、
   更新 SDK 或固件。旧服务的 SDK 哈希不会被静默冒用为 N.I.N.A. 哈希。
10. 生成并审核新的 Night Setup。GS350 focus domain 的 `Owner` 必须为
    `N.I.N.A.PhotometryWorker`，`LogicalDeviceId` 必须等于测光端绑定的真实 focuser ID；
    保留实测 USB 身份/拓扑、起点、行程、单步/累计预算、方向和回差证据。
    旧 `ManualOperator` 包不能自动升级成可运动许可。不要直接修改一个已冻结运行的包。
11. 先在测光端第 3 步点击“开始接收主控任务”，再启动 receiver（如使用高级序列外观），最后由光谱主控的
    正式入口启动。开面板、绑定设备和启用接收本身不连接设备或拍摄；实际连接发生在
    主控经过准入后的设备检查点。

不同 Profile 的 worker 还会对三项设备 ID 建立进程级协作占用，阻止两个 worker 同时
声明同一绑定。这不能阻止其他未遵守协议的软件或任意第三方插件直接打开驱动；
真实句柄释放和互斥仍须受控交接验证。内置 QHY 轮与相机的原生 SDK 句柄关系也须实测，
不能由“同一个 N.I.N.A. 进程”推断它已经可靠。

## 5. 电调焦与滤镜焦点补偿

worker 连接和读回测光端电调焦，滤镜偏移通过原生 `ChangeFilter` 执行。它不会访问
C11 或 UVEX M2。动作前校验焦点起点、终点、回差中间点、单步与累计预算和最终接近方向；
预算先持久化，再调用设备。原生 `None` / `Overshoot` 可按实测策略使用，隐藏物理
偏移的 `Absolute` 回差模型在需要移动时拒绝使用。驱动内部补偿须在 commissioning 中核清。

持久预算位于 `%LocalAppData%\UVEX-ADV\photometry\<worker-profile>\focus-budgets\`。
重启或重发同一运行不会清零已用预算；未确认终点会保留 `Pending`，阻止追加运动或
换一个运行 ID 绕开义务。禁止删账本来“恢复”。本版不提供未结焦点义务的自动退役；
出现该状态须人工核验原生读回并走独立恢复流程，不能当成普通测光质量警告。

确认后的滤镜焦点位置允许不同于 Night Setup 初始位置，但必须是同一设备/同一父运行
的经过验证、在范围内的端点。不会因此把正常的滤镜焦点补偿判成旧手动焦点失效。

## 6. 协议、暂停和失败

- 同一 Windows 用户的命名管道：`OpenAstroSpec.Photometry.v1.<worker-profile-guid-N>`。
  `nina://` 是该本地管道的地址，不是网络服务。消息版本 1，最大 4 MiB。
- 仅提供 health、camera status/connect、acquisition/photometry start、job lookup/status/preview、
  pause/cancel/resume/lease renew。不存在任意设备、脚本、外部 API 或运动转发端点。
- 绑定精确双 Profile、进程/会话、插件与 SDK 哈希、设置、设备、已审核 receiver 契约、
  父运行与幂等请求 ID。worker 重启/配置改变后，本轮不会自动重新认领。
- 窄接口仍复用作业 owner token、request fingerprint、控制租约和歧义启动查询。
  请求接受不等于曝光完成；必须观察到帧/作业终态。
- worker 的租约用单调经过时间判定；主控每 5 秒尝试续期，当前标准租约 120 秒。
  在换滤镜/冷却之后、曝光之前重新检查许可。主控消失不会让 worker 无限开新曝光；
  已开始的曝光/原生保存按有界终态处理。心跳不是开顶证明或独立天气安全系统。
- worker 面板人工暂停/停止设独立的干预标记：自动恢复、续期和新作业不能覆盖它。
  主控读到人工干预会同步请求暂停。结束旧作业后，必须显式允许发起新作业。
- 可选测光质量不佳仍按既有规则降级，保留数据和质量标记；人工停止、设备身份错误、
  未结运动义务与物理安全不是可以自动降级的同一种事件。

## 7. 文件与时间证据

worker 将真实父运行、Night Setup、目标、帧 ID 和作业 ID 注入**保存前**的原生元数据；
原生 `ImageSaveMediator` 写出唯一原始 FITS。按 `QHYCID` 匹配 `ImageSaved`，校验实际
文件中的 `OBSRUNID` / `NIGHTSET` / 目标身份等，再索引路径、SHA-256、质量与预览。
`QhyRunStore` 不会第二次写一份 raw FITS；停止发生在保存中时，优先完成这张已采帧的索引。

任务索引和诊断在 `%LocalAppData%\UVEX-ADV\photometry\<worker-profile>\<session>\`；
原始 FITS 在测光 Profile 的原生保存目录。不可把任一产物提交到 Git。

时间使用 N.I.N.A. 给出的软件曝光开始时间，结束时间为开始加原生曝光时长；来源写入
frame record 与 `TIMESRC`，时间不确定度尚未测量时保持未知，不填 0。这是并行观测，
不是硬件同步触发或亚秒级光度计时保证。实际光谱/测光覆盖须按保留的曝光区间复算。
