# 历史计划兼容读取修复：PHD2_LOCK_MANIFEST_UNREADABLE（0.4.0.202）

日期：2026-09-14（UTC+8）。本次依 AGENTS.md 的同类阻断维护授权完成修复、验证、
安装和正常重启；没有重新发起设备观测。

## 现场原因

运行 `UVEX-20260914T144438Z-e4c301992c10451` 使用 .201，完成 G3 视场阶段后，
在 `PlaceTargetOnSlit` 的历史 PHD2 锁点账本检查中报错。
原始异常不是当晚图像质量不合格，而是读取
`UVEX-20260904T150634Z-603e62d25dbf444/manifest.json` 时得到
`Manifest plan identity or SHA-256 is invalid.`。

9 月 4 日计划含 `targetObservability`，但尚无后来增加的 `catalogMetadata`。
旧 reader 将文件反序列化到当前 `ObservationPlan`，再以新模型序列化计算哈希，
自动补入 `catalogMetadata:null`，因此把未被修改的旧计划误判为损坏。
出错账本已是 `SettledBudgetLedger`；程序先校验 manifest 再排除已结清历史，
所以这个兼容性错误会阻断后续新运行。

本轮 G3 阶段记录为 `G3_CATALOG_WCS_TARGET_PROJECTED`，采用目录/WCS 目标投影路线。
不能将这次走到阶段 5 解释成 .201 的 SEP 直接星像分支已完成天空验收。

## 修复范围

共享 `ObservationRunJournalStore` 保留当前格式的既有校验，对不匹配的旧格式增加有限兼容：

1. 仅允许原计划没有 `catalogMetadata` 且当前解释值为 null 的已知历史形状。
2. 使用历史**类型化序列化契约**重新计算原哈希，只移除新增的这一项；日期、枚举、
   数值和其他字段的序列化方式不变。不能改用任意 JSON 树重新编码作哈希：
   `DateTimeOffset` 的 `+08:00` 与普通字符串重编码的 `\u002B08:00` 字节不同。
3. 原哈希必须精确一致，且历史投影与文件中实际 JSON 结构和值相符。
   未知附加项、缺少安全字段、改变目标/运动/身份或错误哈希不会获得兼容放行。
4. 兼容只用于读取。保留原 PlanSha256，不改写旧记录；旧格式不能在普通更新或重新初始化时
   被隐式迁移成新计划。当前格式的写入、修订和不可变配置检查保持不变。
5. PHD2 原有 run ID、目标/站点/地平线/Night Setup/赤道仪恢复上下文、动作配置和
   commissioning 绑定继续检查。没有跳过历史扫描、删除账本、改变终态或恢复旧动作。
6. UI 对 `PHD2_LOCK_MANIFEST_UNREADABLE` 明确显示“锁点关联的运行记录无法读取或校验”，
   提示查看原始原因中的日期/文件，不再泛化成当帧导星质量问题。

所有使用该共享 journal reader 的前端、序列及后台入口都使用同一兼容规则。
没有增加后台专用成功条件，也没有放宽星点、导星或运动门限。
