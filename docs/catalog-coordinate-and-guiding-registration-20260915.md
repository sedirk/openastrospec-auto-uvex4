## 坐标契约：统一轴向，按来源与接收接口转换

目标计划继续保存赤经/赤纬度数，使用 **J2000 轴向的天体测量方向**。
不把 Stellarium 的“当前赤经/赤纬”直接写进 J2000 字段。
当前坐标是设备接口需要时的派生值，不是替换目录目标的第二套真值。

| 边界 | 处理 | 不做的事 |
| --- | --- | --- |
| 手工目录坐标 | 输入可信的 ICRS/J2000 目录位置 | 不根据名字猜历元，不自动把当前坐标当 J2000 |
| Stellarium RemoteControl | 核对同次选择、时间、观测星球及光行差/视差设置，读取 `raJ2000/decJ2000`，按其实现去除已加入的光行差 | 不认为字段名含 J2000 就等于原始目录坐标，不修改 Stellarium 全局设置 |
| 其他 N.I.N.A. 星图/构图接口 | 按接口携带的 `Epoch` 转成 J2000；已标为 J2000 时不额外套用 Stellarium 专用转换 | 不把其他星图假设为 Stellarium，不回写历史构图中心 |
| 计划、WCS 投影、入缝目录主目标 | 一律使用同一个 `ObservationPlan.Target` | 不让某个分支单独用另一次 SIMBAD/HIP 查询替换主目标位置 |
| 赤道仪接口 | 继续由 N.I.N.A. 按设备所需的坐标系转换 | 不预先转一次“当前”后又标成 J2000 导致二次转换 |

J2000 **轴向**不等于恒星的**位置历元一定回到 2000.0**。
若 Stellarium 已依据源数据处理自行或视差，本次保留该源时刻的位置；
没有实现任意目标的完整六维星表传播、距离反演或自行历元回退。
高自行近星和长时间复用的目标计划仍须重新取得适当时刻的可靠天体测量坐标。
旧 FITS、旧 manifest 和历史计划不被追溯重写；旧版导入的草稿需要重新导入。

### 为什么不能直接照抄 Stellarium 的 J2000 字段

已核对的 Stellarium 实现先取得固定天体方向，在启用光行差时加入地球速度与光速之比，
再归一化；`raJ2000/decJ2000` 是把这个方向表达在 J2000 轴向上。
因此“J2000”不保证已经去除了光行差。当前赤道坐标还涉及不同轴向，不能混填。

`StellariumCoordinateNormalizer` 对 `q = normalize(p + β)` 解逆变换：
`k = q·β + sqrt(1 - |β|² + (q·β)²)`，`p = kq - β`。
β 使用 N.I.N.A. 已部署的 NOVAS/JPL 星历计算地球质心速度，单位转换为 v/c，
而不是硬编码一个赤经/赤纬偏移。RemoteControl 的 `time.deltaT` 单位是**日**，
用 `jday + deltaT` 得到星历时参数。

导入前后检查设置与选择没有变化。只接受已支持的固定目录对象、地球观测点、
1900–2100 年以及非夸大的光行差/视差因子。缺失上下文、换目标、坐标与 N.I.N.A.
返回的目标不符、任意标记点或不支持的移动对象会明确拒绝本次导入，保留已有草稿。
星历不可用时不会悄悄照抄未经转换的值。

每次成功导入的目录资料携带 `TargetCoordinateProvenance`：原始坐标、来源接口、
星历时、光行差开关、修正量和位置语义。旧资料没有该字段时序列化仍省略它，
不因此改变旧 JSON 的表示。

## 截图阻断的实际原因

运行 `UVEX-20260914T163729Z-2c51d7284aa0447` 在目录路径中找到了 WCS 取样位置，
但后续三组导星窗口仍携带旧的 `CatalogWcsProjection`，没有由新图像测量目录点的位移。
这不能作为“新帧实测几何”进入已启用的有人监督精度警告路径。

原始证据中其实已经完成三组窗口：

| UTC | 导星残差（像素） | 原代码结果 |
| --- | --- | --- |
| 16:45:20.394 | 1.727 / 3.281 / 1.151 | 完整窗口，不满足所有样本 ≤ 2；也无新帧配准位置 |
| 16:45:28.184 | 3.408 / 1.906 / 0.896 | 同上 |
| 16:45:36.216 | 2.387 / 2.136 / 2.255 | 同上 |

第四组只有两个样本便到达原阶段截止时间。旧终态只突出最后一次窗口超时，
造成“根本没取得完整窗口”的误导。修复后：

- 没有任何完整窗口、且时间截止，才报告 `PHD2_FRESH_GUIDE_WINDOW_DEADLINE`。
- 已有完整但不通过的窗口，保留 `PHD2_GUIDE_WINDOW_NOT_STABLE`，并记录完整组数、
  最近完整测量和是否在等待后续窗口时截止。
- 不延长阶段时间，不清零运动、回程、次数或累计位移预算。
- 原始三组数据仍不称为“2 像素精度通过”；只有既有的监督警告授权和其他要求同时满足，
  才可按警告策略处理。导星残差和目标相对狭缝误差仍是两项独立检查。

## 目录取样点靠视场配准更新，不要求暗目标有可见星核

`CatalogFieldRegistration` 使用已经接入的 SEP 完整父分量，而不是重新制造局部峰检测器。
它从原始成功 WCS 帧建立参考星集合，并与选星帧、每张新导星残差帧匹配。
至少三颗独立、未饱和参考星一致支持有界平移，才把原始目录取样点传递到新帧。

- 对目标附近、狭缝附近、边缘、饱和区域和明显缺乏像素支撑的分量作排除。
- 使用 SEP 父分量，避免同一不规则星像上的多个峰充当多颗参考星；不要求圆形高斯 PSF。
- 匹配必须相互唯一；两套竞争解、参考星不足、不同视场或明显旋转不能授权定位。
- 只允许受限平移，不自由拟合旋转/缩放，不用已发出的锁点偏移代替光学测量。
- 同轮运行、连接时期、赤道仪侧位、探测器尺寸和原 WCS 帧保持一致。
- 目录模式使用离缝导星，不把目标附近的亮峰、星系核、伴星或亮结节吸附成目标。
- 新类型 `CatalogWcsRegisteredField` 明确表示“目录身份 + 新帧参考星位置”，
  不是声称暗目标自身被测出质心。目标通量标为不适用，不伪造目标信噪比。
- 每帧记录 `g3-catalog-field-registration`：源帧、参考点、匹配星数、平移量、
  配准离散度和 SEP 来源。配准失败仍在下一运动前停止。

双星目录对比可用于说明主星/伴星关系，但 `CatalogShortPosition` 不再将额外查询得到的
主星坐标替换计划目标，从而避免“选择、粗定位、短曝光、精调各用一套坐标”。
