# 自动观测操作员界面问题与验收规范

## 1. 目的和适用范围

本文是 `OpenAstroSpec Auto — UVEX4` 自动观测界面的耐久验收规范，用于指导界面重构、模拟截图复核和发布前人工验收。它记录 2026-08-18 用户提供的 1920×1080 N.I.N.A. 截图所暴露的问题，并把“界面是否可用”转成可以重复检查的通过标准。

本文适用于：

- 自动观测停靠面板的运行模式、状态和人工控制；
- QHY/GS350、G3 和 ATR 三路实时预览；
- 质量门、失败诊断、时间线和证据入口；
- 暗色主题、窄停靠栏、缩放/DPI 和键盘操作；
- UI 修改后的隔离模拟渲染与截图闭环。

本文不改变设备所有权、安全门、观测流程或实机 commissioning 规则。冻结设计记录和 ADR 仍是这些事项的权威来源。

## 2. 当前截图结论

当前界面具备主要功能入口，但仍是“把控件放进长页面”的调试界面，尚未达到夜间观测控制台的可用性要求。它不应以“UI 已验收”状态发布。

### 2.1 问题清单

| ID | 严重级别 | 当前问题 | 操作风险 | 验收方向 |
|---|---|---|---|---|
| UI-001 | P0 | 质量门列表显示为大块白底，浅色文字几乎不可读 | 破坏暗适应，关键诊断无法辨认 | 所有容器、列表、滚动条、选中态和禁用态完整适配暗色主题 |
| UI-002 | P0 | 模式、运行状态、暂停和取消会随长页面滚出视野 | 操作员查看图像时不能立刻确认模式或暂停自动动作 | 建立始终可见的固定状态/控制条 |
| UI-003 | P0 | “目前没有失败记录”仍使用红色故障卡 | 正常空闲被误判为严重故障，削弱真正告警的可信度 | 按无故障、警告、暂停待处理、故障四种状态条件渲染 |
| UI-004 | P0 | 外层页面和内层诊断列表同时纵向滚动 | 出现滚动陷阱，操作员无法预测滚轮作用域 | 每个可见页面最多只有一个纵向滚动上下文 |
| UI-005 | P1 | 主预览只是静态图，交互缩放和平移只能依赖另一个窗口 | 定位星点、狭缝和失败像质的路径过长 | 主预览直接支持光标中心缩放、拖动、适配和 1:1 |
| UI-006 | P1 | 没有图像时仍保留大面积黑框 | 关键状态和控制被推到屏幕外 | 使用紧凑、可解释、可操作的空状态；有帧时再展开预览 |
| UI-007 | P1 | 按钮前景、背景和禁用态对比不足 | 看不清标签，也无法判断能否点击 | 对比度、禁用态、主次动作和焦点态必须可区分 |
| UI-008 | P1 | “没有需要检查的失败图像”等状态句被做成按钮 | 状态和动作语义混淆 | 无资源时显示文本；资源存在时才显示相应动作按钮 |
| UI-009 | P1 | 空预览只写“等待数据”，没有说明等待原因 | 无法区分未启动、服务未连接、质量门阻断和设备故障 | 空状态显示数据源、连接、作业、最后一帧和具体原因 |
| UI-010 | P1 | 当前阶段、下一步、设备 owner 和最近动作不在同一视野 | 无法快速回答系统现在及接下来在做什么 | 固定控制条持续显示核心运行态和下一物理动作 |
| UI-011 | P2 | 等待中的质量门重复显示 `--`、`—` 和多行空信息 | 信息密度低，失败项难以找到 | 默认紧凑显示，当前/失败/选中项才展开细节 |
| UI-012 | P2 | 字号、间距、颜色层级不适合远距离夜间扫视 | 操作慢，且过度依赖细微色差 | 建立统一字号、间距、图标、文字状态和可访问性规则 |
| UI-013 | P1 | 完整真实模式启动缺项长期占据常用首屏 | 观测计划和目标字段被推到屏幕下方，日常操作必须滚动 | “运行概览”只保留状态摘要与入口；完整清单和 bindings 导入移至“高级设置” |
| UI-014 | P1 | 新增校准、鬼影和导星状态后又堆回同一长页面 | 标签存在但常用操作仍依赖滚轮，界面随功能增长持续退化 | 把状态与目标拆成独立一级标签；运行概览和观测计划禁止整页滚动，并用静态测试守住约束 |

P0 必须在进入真实设备验收前全部关闭；P1 必须在候选发布版前关闭；P2 可以分批改进，但不得破坏下述硬性验收标准。

## 3. 信息架构要求

界面必须由固定控制条和单个主内容区构成，不能继续扩展成一张无限增长的纵向表单。

```text
┌──────────────────────────────────────────────────────────────┐
│ 模式 | 运行状态 | 当前阶段 | 下一步 | 进度/新鲜度             │
│ [暂停] [恢复并复核] [人工接管] [取消并安全收尾]              │
└──────────────────────────────────────────────────────────────┘

[运行概览] [观测计划] [实时图像] [失败诊断] [质量与证据] [高级设置]

┌──────────────────────────────────────────────────────────────┐
│ 当前页签的唯一内容；常用页完整显示，诊断/高级页按需滚动      │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 固定控制条

固定控制条在界面处于空闲、运行、暂停待处理或故障状态时始终可见，并至少回答：

1. 当前为模拟模式还是真实设备模式；
2. 当前未运行、运行中、暂停待处理、人工接管、正在安全收尾还是故障；
3. 当前执行阶段；
4. 下一步自动动作，尤其是下一次可能发生的物理动作；
5. 当前可执行的人工动作；
6. 自动控制是否仍持有设备控制权。

强制要求：

- 模式必须同时使用文字和图标/形状表达，不能只使用颜色；
- 真实设备模式必须比模拟模式更醒目，但不得使用刺眼的大面积高亮背景；
- 运行期间不得允许无意切换模式；如需切换，必须先结束当前运行；
- `暂停` 和 `取消并安全收尾` 在运行期间不可被页签、滚动或窄布局隐藏；
- `恢复并复核` 仅在允许恢复时出现，并明确提示恢复前会重新检查安全门；
- `人工接管` 必须清楚说明自动控制是否已释放；
- 不得用仅有图标、无可见文字或无辅助名称的按钮承载上述关键动作。

### 3.2 主内容区

主内容区使用页签或等价的一层导航。每个页面只承担一种任务：

- **运行概览**：开始前阻断项数量摘要、PHD2 当前 active calibration 分级和目标定位辅助决定；使用两条自动高度的操作状态行，不用剩余高度拉伸状态卡，不显示 policy SHA、路线、缩放、完整适用性或权限契约，也不使用整页滚动；首页等级、模式和决定必须翻译为操作员可读的中文，不直接显示内部枚举或 gate code；
- **观测计划**：目标导入、名称、目录身份、J2000 坐标、Night Setup 和计划时长；使用固定分栏完整显示，不使用整页滚动；
- **实时图像**：QHY、G3、ATR 图像及图像元数据；
- **失败诊断**：当前告警/失败、实测与阈值、处理建议；
- **证据与时间线**：质量门、事件和证据文件；
- **高级设置**：完整真实模式启动条件、站点/地平线/模拟速度、commissioning bindings 导入、稳定身份、四槽位 LED 狭缝光学身份摘要、其他指纹和不属于日常操作的字段。狭缝身份只在这里显示紧凑摘要与最新 gate，不重新占据常用首屏。

切换页签不得丢失当前缩放、平移、选中质量门或诊断上下文。高级设置不得占据默认首屏。

## 4. 四个强制验收场景

以下四个场景都必须使用确定性的模拟数据独立渲染、截图并逐项通过。仅通过编译、单元测试或 XAML 静态检查不能替代视觉验收。

### 4.1 场景 A：空闲且尚未运行

模拟条件：已加载配置，没有活动运行，没有失败，没有任何图像或运行证据。

通过标准：

- 固定控制条显示 `空闲`，并明确显示当前选择的模式；
- 模拟/真实模式选择和模式解释在默认首屏可见；
- 只有一个与所选模式一致的启动动作；
- 选择模式本身不得伪装成“已经连接设备”；
- 不显示红色失败卡，不显示 `错误代码：--`、`数值：—` 等无意义占位符；
- 失败区最多显示一行中性状态，例如“当前没有失败或待处理质量门”；
- 无证据、无失败帧时不显示伪按钮；
- 三路预览的空状态紧凑显示，并说明“尚未启动，因而没有图像”；
- 不得出现大面积纯黑预览占位或大面积白色容器；
- 默认首屏能看到模式、启动动作和系统是否可启动，不能依赖滚动寻找。

### 4.2 场景 B：正常运行

模拟条件：模拟模式运行中，具有最新 QHY、G3 和 ATR 帧；当前阶段位于 G3 精解析，下一步为有界入缝；质量门持续更新。

通过标准：

- 固定控制条同时显示 `模拟`、`运行中`、`G3 精解析`、下一步和进度；
- `暂停`、`人工接管` 和 `取消并安全收尾` 始终可见；
- 模式选择在运行期间不可误触，且原因有明确提示；
- 实时图像页默认选择与当前阶段有关的 G3 预览；
- QHY/G3/ATR 页签显示新帧标记、最后一帧 UTC、曝光、增益、滤镜/光路和文件/证据标识；
- 过期帧必须显示“已过期”及年龄，不能继续以绿色“实时”状态展示；
- 质量门默认把当前阶段和最近变化项置于可见区域；
- 等待项目只占一行，不能用多行 `--` 填充；
- 无失败时不出现红色卡片；轻微趋势警告使用紧凑黄色状态条，并同时给出文字原因；
- 从任一主内容页切换后，固定控制条仍可操作。

### 4.3 场景 C：`PausedNeedsAttention`

模拟条件：G3 主焦点质量门失败，运行状态为 `PausedNeedsAttention`；保存失败帧、分析结果和运行目录；模拟实测 FWHM 超过阈值且星数足够。

通过标准：

- 固定控制条立即显示 `暂停待处理`，且视觉上与普通警告和永久故障不同；
- 当前阶段和“不会继续执行下一物理动作”必须明确显示；
- 失败诊断页自动成为推荐页，但不得用反复抢焦点打断键盘操作；
- 完整故障卡仅在此类有实际故障的状态出现；
- 故障卡显示阶段、稳定错误代码、简明原因、实测值、阈值/预期值和时间；
- 本场景必须显示 `实测 FWHM` 与 `允许上限`，不能只显示模糊的“拟合失败”；
- 明确推荐 G3 对焦/狭缝/导星预览，并显示 Star Focuser Pro/Gemini 是 C11 主焦点调焦 owner；
- `查看失败帧`、`打开分析证据`、`打开运行目录` 只在目标确实存在时启用；
- 失败帧直接出现在主预览，缩放和平移无需先打开独立窗口；
- `恢复并复核` 明确列出将重新检查的门；未满足恢复条件时显示具体阻断理由；
- `人工接管` 和 `取消并安全收尾` 始终可见；
- 告警不只依赖红色，必须同时有图标、状态文字和错误代码。

### 4.4 场景 D：窄停靠栏

模拟条件：复用场景 C，在宽 640 DIP 的可用内容区渲染；另以 150% Windows 缩放复核。若宿主可提供更窄宽度，还应对 560 DIP 做目标性检查。

通过标准：

- 不出现水平滚动条；
- 模式、状态、当前阶段和人工控制不被裁剪或移出可视区域；
- 固定控制条允许安全地换行或切换为两行布局，但动作文字不得截断为不可理解的省略号；
- 主操作、危险操作和普通次要操作不会因自动换行而交换相对语义；
- 页签标签保持可辨认；空间不足时使用可访问的溢出导航，不允许把页签静默裁掉；
- 失败卡中的数值与阈值仍保持成对可读；
- 图像保持正确宽高比，不被拉伸；
- 鼠标滚轮位于图像上时缩放图像，位于内容上时只滚动当前页的唯一滚动区；
- 任何时刻都不存在两个相邻的纵向滚动条；
- 在 100%、150% 和 200% DPI 下不发生文字重叠、按钮叠加或内容越界。

## 5. 暗色主题验收

暗色主题是夜间功能要求，不是可选美化。

- 除真实图像数据本身外，不允许出现大面积纯白或接近纯白背景；
- 普通正文与背景对比度至少达到 4.5:1；大号文字和非文本控件边界至少达到 3:1；
- 选中、悬停、键盘焦点、启用、禁用和按下状态必须彼此可辨；
- 禁用控件不得只通过轻微降低透明度表达；
- 状态颜色必须同时配有文字或图标：通过、等待、警告、暂停、失败不能只靠绿/灰/黄/红；
- 红色只用于真实失败、危险动作或必须立即理解的阻断，不能用于“没有失败”；
- 青绿色主色不能同时作为按钮背景和低对比文字前景；
- 列表、表头、分隔线、滚动条和空白区都必须继承同一暗色主题；
- 截图复核时使用灰度查看一次，确保状态层级在去除颜色后仍然成立。

## 6. 单滚动上下文验收

每个选中的主页面最多只能有一个纵向滚动上下文：

- 固定控制条位于滚动区之外；
- 如果页签整体滚动，内部列表必须随内容展开或使用分页/折叠，不能再独立滚动；
- 如果质量门/证据使用占满余下空间的虚拟列表，则该页签外层不得再有纵向滚动；
- 图像缩放不应改变整页布局尺寸；
- 指针在图像上时，滚轮专用于图像缩放；按住明确修饰键或移出图像后才滚动页面；
- 内部区域到达边界后不得形成“滚轮无响应”的陷阱；
- 截图中不得同时出现外层和内层两根纵向滚动条。

## 7. 交互预览验收

QHY、G3 和 ATR 主预览都必须直接支持以下操作，独立窗口只能作为可选的“弹出大图”，不能是唯一交互入口：

- 以鼠标指针为中心的滚轮缩放；
- 左键拖动平移；
- `适配窗口`；
- `1:1`；
- 明确的放大、缩小和复位动作；
- 当前缩放百分比；
- 鼠标像素坐标和像素值/ADU（数据支持时）；
- 保持像素宽高比，不做非等比拉伸；
- 新帧到达时是否保持当前视图或自动适配的显式策略；
- 可关闭的叠加层，并显示叠加数据的来源和时间。

各数据源最低叠加要求：

| 预览 | 最低叠加和元数据 |
|---|---|
| QHY/GS350 | 检测星点、WCS/解析结果、中心目标、曝光、增益、滤镜、星数、背景和饱和比例 |
| G3 | 星点/FWHM、目标质心、LED 差分狭缝、导星/入缝残差、曝光、增益和帧时间 |
| ATR | 二维谱 ROI、饱和、谱线/提取孔径、一维谱、曝光、温度/制冷状态和 SNR |

没有图像时不画固定高度的大黑框。空状态至少显示：

- 数据源和负责它的 owner；
- 服务/会话是否可用；
- 是否存在活动作业；
- 没有图像的具体原因；
- 最后一帧时间（如存在历史帧）；
- 操作员下一步可以做什么。

空状态信息不得暗示插件已经连接或拥有真实设备。

## 8. 条件故障卡验收

故障区必须基于状态使用不同模板，而不是始终显示同一张红色卡片。

| 状态 | 表现 | 不应出现 |
|---|---|---|
| 无失败 | 一行中性或正向摘要，可完全折叠 | 红色背景、错误代码占位、空证据按钮 |
| 趋势警告 | 紧凑黄色状态条，包含指标、趋势和阈值 | 把警告描述为运行已停止 |
| `PausedNeedsAttention` | 展开的橙红诊断卡，说明已暂停、失败门、实测/阈值、图像和安全恢复动作 | 隐藏暂停原因、自动继续倒计时 |
| `Faulted` | 展开的红色故障卡，说明不可自动恢复和安全收尾状态 | 提供未经复核的一键继续 |

故障卡必须优先使用结构化字段，不能把所有信息拼接成一段长文字。至少包括：

- 阶段和错误代码；
- 一句话原因；
- 预期/阈值与实测值；
- 数据时间和新鲜度；
- 相关预览；
- 已保存的原始证据和分析证据；
- 推荐的人工检查；
- 恢复的前置条件和重新验证范围。

如果某项证据不存在，应显示原因文本，不得渲染一个看似可点击但被禁用的状态句。

## 9. 可访问性和夜间操作验收

- 所有按钮、页签、输入框、图像工具和状态图标都有可见标签或可访问名称；
- 全部功能可使用键盘到达，Tab 顺序与视觉顺序一致；
- 键盘焦点轮廓在暗色背景上清晰可见；
- 关键动作的点击目标不小于 32×32 DIP，夜间常用控制优先达到 40 DIP 高；
- 危险动作与普通动作在位置、颜色、图标和文字上均有区别；
- 取消、人工接管等动作不能仅凭一次误按立即触发不可逆行为；其交互必须遵循既有安全状态机，而不是增加绕过安全门的确认开关；
- 中文正文不得被截成无法理解的省略号；较长原因允许换行或提供可访问的完整详情；
- 缩放到 200% 时仍可完成暂停、查看失败原因、打开失败帧和安全收尾；
- 状态变化应可被辅助技术读取，但不得反复抢夺键盘焦点；
- 动画和闪烁不是必要信息载体，严重告警不得持续高频闪烁；
- 时间必须标明 UTC 或本地时区，不能显示无时区的模糊时间。

## 10. 隔离模拟截图闭环

### 10.1 安全边界

所有开发迭代截图必须由**隔离的 UI 模拟 VM/渲染宿主**生成：

- 不启动生产 N.I.N.A.；
- 不启动、停止或重新配置 PHD2、DRIVER.UVEX4、已安装 Windows 服务或设备驱动；
- 不打开真实相机或 COM5；
- 不移动赤道仪、屋顶、UVEX 光栅、狭缝轮或 M2；
- 不启动真实曝光、调焦、导星或标定；
- 只使用确定性的合成图像、模拟状态、模拟质量门和虚构的安全路径；
- 模拟数据不得包含机器用户名、真实 DeviceId、网络地址、凭据或原始观测数据。

如果当前没有不依赖 N.I.N.A. 进程的 UI 渲染宿主，应先建立最小 UI Gallery/截图宿主。不能为了“看看效果”直接打开现场 N.I.N.A. 或连接实机。

### 10.2 每轮流程

每一次非平凡 UI 修改都必须执行以下闭环：

1. 构建插件和 UI 模拟渲染宿主；
2. 运行相关自动化测试；
3. 在隔离模拟 VM 中渲染四个强制场景；
4. 生成固定尺寸和 DPI 的截图；
5. 人工逐张检查本文清单，不得只比较像素差异；
6. 记录新发现的缺陷 ID、严重级别、截图和修改决定；
7. 修复后重新生成受影响场景以及一张相邻状态截图；
8. 直到 P0/P1 缺陷为零，四个场景全部通过，才可宣布 UI 闭环。

### 10.4 截图自检问题

每张截图至少要由修改者自己回答：

1. 三秒内能否看出模拟还是真实？
2. 三秒内能否看出系统是否在运行、暂停或故障？
3. 三秒内能否找到暂停和安全收尾？
4. 能否看出系统正在做什么、接下来会做什么？
5. 失败时能否看到实测值、阈值和对应图像？
6. 没有失败时是否完全没有红色故障语义？
7. 是否存在白底、低对比、截断文字或无法辨认的禁用按钮？
8. 是否存在两根同时可见的纵向滚动条？
9. 空预览是否解释了原因，而不是只留下黑框？
10. 不打开第二个窗口，能否直接检查图像细节？

任一问题答案为“否”，该轮截图不得标记为通过。

## 11. 自动检查与人工检查的边界

建议自动化检查至少覆盖：

- 固定控制条和关键命令存在；
- 所有按钮、复选框和页签具有可见标签/可访问名称；
- 不存在强制宽度和水平滚动；
- 故障卡按运行状态条件显示；
- 无证据时相关命令不可见而非伪装成状态按钮；
- 三路预览具有缩放、平移、适配和 1:1 命令；
- 各模拟状态能够确定性构造；
- 颜色资源满足静态对比度门槛；
- 窄宽度和高 DPI 渲染不抛布局异常。

以下事项仍必须人工看截图：

- 是否存在刺眼的大面积亮区；
- 视觉层级是否让真正的失败优先于等待项；
- 夜间常用动作是否足够醒目但不刺眼；
- 窄布局换行是否自然；
- 图像、叠加层和文字是否互相遮挡；
- 空闲、警告、暂停和永久故障是否一眼可区分；
- 信息是否像操作台，而不是调试日志或配置表单。

## 12. 完成定义

只有同时满足以下条件，自动观测界面才可被认为完成本轮闭环：

- UI-001 至 UI-010 以及 UI-013、UI-014 全部关闭；
- 四个强制场景的最新隔离模拟截图全部通过；
- P0/P1 视觉缺陷为零；
- 暗色、单滚动上下文、固定控制条、交互预览、条件故障卡和可访问性要求全部通过；
- 编译、自动化测试和冻结设计哈希检查通过；
- 截图过程中未启动 N.I.N.A. 或接触任何真实硬件；
- 修改者已经逐张人工查看实际渲染结果，而不是只查看 XAML 或测试结果；
- 未解决的 P2 问题有明确 ID、影响和后续计划；
- 真实设备验收仍按 `docs/commissioning.md` 单独进行，不能用模拟截图代替。

本规范的目标不是追求装饰性界面，而是确保操作员在高云、低星数、对焦或解析失败以及需要人工暂停时，能够立即看懂状态、看到证据，并安全地介入。

## 14. 目标导入验收

“观测计划”允许操作员显式快照导入 N.I.N.A. 构图助手当前目标，或通过
N.I.N.A. 当前 Profile 选择的第三方星图导入其当前选中目标。导入不是设备动作，
不得连接相机、PHD2、赤道仪或 COM5，也不得启动曝光、解析、序列或移动。

强制要求：

- 两条入口使用完整文字：`从构图助手当前构图导入`、`从第三方星图当前选择导入`；
- 构图助手默认采用本次构图矩形的初始中心；若采用当前构图中心，必须由操作员通过带解释的显式选项选择。两者都不得冒充不可变的目录天体坐标，入缝前仍须复核；
- 多面板构图不得静默取第一块，必须拒绝并说明当前版本尚未选择具体面板；
- 坐标在导入边界复制并规范化为 J2000，RA 以度保存；必须拒绝非有限值和越界坐标；
- 第三方星图没有明确选中对象、返回 404 或名称为空时不得沿用旧目标伪报成功；
- 成功导入时，旧目录 ID 只有在新来源提供可靠 ID 时才能保留，否则必须清空；
- 成功卡显示来源、目标、目录 ID、J2000 RA/Dec、位置角（若有）和导入 UTC；
- 导入只替换目标名称、目录 ID 和目标坐标。Night Setup、commissioning、设备身份、运动限额、地平线、安全策略、运行模式和计划时长保持不变；
- 运行或暂停中的计划是不可变快照，两个导入入口必须禁用；
- Dock 中导入只更新下一次从 Dock 启动的计划及以后新建容器的默认值，不得暗中改写已经创建的高级序列容器；
- 手工编辑任一目标字段后，界面不得继续把该目标描述为未经修改的外部导入结果；
- 失败信息必须区分“星图未启动/无法连接”“星图没有选中目标”“构图助手尚未生成目标”“多面板暂不支持”和“坐标无效”。

离线截图至少覆盖一次成功导入和一次运行中禁用态；服务单元测试至少覆盖
JNow→J2000、RA 小时/度单位防错、无目标、404、多面板、旧目录 ID 清空、失败不改原计划和显式构图中心选择。
