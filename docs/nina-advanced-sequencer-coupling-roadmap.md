## 1. 目的与现有证据

复刻操作员已经使用过的工作方式：同时运行两个不同配置的 N.I.N.A.，一个拍 ATR 光谱，
一个用 QHY 做多滤镜测光；把原来由人完成的启停、共享设备协调和文件关联改成明确、
可见、可审计的自动协议。

N.I.N.A. 继续负责成熟的高级序列、滤镜轮、对应光路的自动对焦/滤镜焦点补偿、相机
曝光和原生保存。OpenAstroSpec 负责目标获取、入缝、光谱质量、两端协作及科学证据，
不为 QHY 再实现一套完整的深空摄影编辑器，也不让两个实例各运行一套整夜设备调度器。

核心原则是：**两个采集实例，一个观测协调器；不同物理设备各有唯一拥有者；共享运动
和现场安全只有一条控制路线。** 两个实例必须使用不同的 Profile；不是把同一实例的
主相机在 ATR/QHY 之间来回切换。

### 1.1 不能混淆的三类完成状态

- [2026-08-25/26 QHY 联测记录](qhy-photometry-commissioning-2026-08-25.md)第 2 节记录了
  第二个 N.I.N.A. 人工连接 QHY，并通过 API 取状态、切滤镜、对焦和曝光。这是双实例
  采集的组件证据，不是自动联动、故障恢复或无人值守验收。
- 当前 `UvexTargetObservationContainer` 仍是 `IImmutableContainer`，固定包含 11 个阶段
  标记，与 Dockable 共用 factory、plan、coordinator 和生产 runner；尚未完成可自由
  组合的双实例高级序列接口。
- [2026-09-07 收口](commissioning-night-2026-09-07.md)中的 .137 真实 11/11 是
  **现有 QHY 服务路线**，不能据此宣称双 N.I.N.A. 自动路线已成功。

原测光记录中的滤镜身份勘误继续有效：旧名称 H 帧实际为 O III，不能因迁移采集端而
恢复已撤回的 Hα 结论。原 FITS、运行记录和历史设计均不追溯改写。

## 2. 双实例职责与设备所有权

下表是**拟迁移完成后的**分工，不是当前运行配置。

| 设备或职责 | 唯一拥有者/执行方 | 另一端的边界 |
| --- | --- | --- |
| ATR585M、光谱曝光与保存 | 光谱 N.I.N.A.（主控实例） | 测光端不枚举、连接或曝光 ATR |
| QHYminiCam8M、广域帧与测光曝光 | 测光 N.I.N.A.（执行端实例） | 主控通过协作接口请求；旧 QHY 服务不得同时打开相机 |
| QHY 内置滤镜轮 | 测光 N.I.N.A. 的已核验驱动路线 | 按物理槽位和带通绑定，不另开争用相机的 SDK 通道 |
| GS350/ToupTek 对焦器 | 测光 N.I.N.A. 的独立对焦器配置 | 不得替换成 C11/Gemini 或 UVEX M2 |
| C11/Gemini 对焦器 | 主控侧已标定的 C11/G3 对焦路线 | 不用 ATR 光谱图套普通星场自动对焦 |
| G3M2210M 与实时导星 | PHD2 | 仅主控共享 runner 编排选星、标定、移锁和导星生命周期 |
| UVEX4/COM5、狭缝、光栅和 M2 | `UvexAdv.Service` | 两个 N.I.N.A. 均不直接打开 COM5；测光端无机构命令 |
| 赤道仪转向、居中、Sync、翻转、停放 | 主控 N.I.N.A. telescope mediator | 测光端不连接实体赤道仪作运动控制；PHD2 保留受协调的导星纠偏 |
| 目标顺序、运行状态、安全/屋顶/镜盖策略 | 主控高级序列 + 同一个 OpenAstroSpec coordinator | 测光端只报告状态、停止本端采集，不独立关顶或停放 |

三套焦点域继续遵守 [ADR-0003](adr/0003-slit-illumination-and-focus-domains.md)。QHY 失焦
不能触发 M2 或 Gemini 运动。GS350 自动对焦只占用自己的 QHY/滤镜轮/对焦器；如某个
设置或触发器还会停止共享 PHD2、重新居中或移动公共设备，必须禁用该副作用。对焦帧
与测光帧分开保存和分类，对焦期间的采样空档进入联测时间表。

测光端质量不佳不自动升级成全台收尾；现场明确不安全则按已有模式处理，不能因等待
测光端应答而无限延迟必要的安全动作。

## 3. 实例角色、绑定和配置隔离

不能只用“第二个窗口”、进程序号或固定 API 端口识别执行端。每次握手至少核对：

- 角色 `SpectroscopyMaster` / `PhotometryWorker`、协议版本及支持的能力；
- PID、进程启动时间、该次启动随机 session ID，防止重启后 PID/端口复用；
- 精确 N.I.N.A. Profile ID、实际相机/滤镜轮/对焦器身份；
- N.I.N.A.、插件、相机驱动/SDK 的实际版本或哈希，以及执行模板哈希；
- 主控运行 ID、worker 作业 ID 和运行/配置 revision。

这些是拟定契约，不是现有 API 已全部暴露的承诺；缺项应在适配层实现并测试。相机
身份不按枚举序号选择；无可信序列号的对焦器使用已 commissioning 的设备拓扑。

两套 Profile 和模板单独保存、分别备份，不能因主控切换配置就覆盖测光配置。角色应
在设备连接和桥端点注册前明确；未分配角色时不自动连接、不启动 coordinator。插件若
被两个 N.I.N.A. 同时加载，worker 不得再启动光谱完整流程、争用主控桥端点或恢复旧
运动账本。现有固定命名管道需要实例隔离：采用角色/会话绑定的当前用户专用端点，
不能通过“发现一个能连的端口就用它”选择实例。

测光配置不复制主控的赤道仪、PHD2、屋顶和镜盖控制。原生功能如需坐标、气团或导星
状态，应使用带时间来源的只读遥测；不能为满足状态字段而连接并控制共享设备。
涉及两端授权、只读描述和命令审计时，不在公开配置中保存认证材料或本机设备秘密。

## 4. 程序接口与前台可见性

主控继续通过 [ADR-0009](adr/0009-single-production-observation-route.md) 的单一生产
runner 发起工作。大模型调用主控的前台同源接口；worker 不另写目标获取、运动恢复
或光谱质量状态机。

优先复用经核验版本的 N.I.N.A. 原生序列 API；不足的能力用小型 worker 桥补足。不用
computer use，不靠键鼠、截图文字或窗口焦点判断成功。不能假定 Advanced API 的
“暂停”能够拦截所有批量曝光或完成跨进程安全协议，必须验证精确版本的真实语义。

### 4.1 拟提供的协作操作

| 操作 | 契约与实际完成证明 |
| --- | --- |
| `Handshake / Snapshot / WaitRevision` | 只读身份、能力和状态；读取不增加 revision |
| `PreparePhotometryJob` | 校验目标、相机参数、滤镜/焦点、模板与授权；不曝光、不运动 |
| `CaptureAcquisitionWitness` | 经本端同源曝光/保存路径取得新 QHY 广域见证，附帧标识、时间和哈希 |
| `StartPhotometryJob` | 启动已锁定的 worker 高级序列；命令接受不等于已有首帧 |
| `PauseAtBoundary / AwaitQuiescent` | 禁止新曝光，确认当前曝光/读出/保存边界及相关滤镜轮/对焦器动作终态 |
| `ResumePhotometryJob` | 仅对同一作业和新鲜共同许可继续；不能隐式新建运行 |
| `StopAndFinalize` | 有界停止并发布实际终态及文件清单；幂等，不删除历史数据 |

以上是规划接口名称，不是可直接调用的现有命令。实现时映射到 worker 可见的序列项、
按钮和同一套本地命令服务，校验其可执行状态；不能另开隐藏曝光路线。

主控显示两端连接/授权状态、目标、QHY 当前滤镜/曝光/对焦状态、两路独立进度、最后
应答和跨端等待原因。worker 真实显示正在执行的高级序列及图像。手工与代码使用相同
状态更新；用户在任一端暂停或接管后，模型不得擅自自动 Resume。

### 4.2 命令幂等、超时与本地运行许可

- 每个命令绑定 command ID、双方 session ID、运行/作业 ID、配置哈希和预期 revision。
  同一命令重传返回原结果；不同参数重复使用 ID 必须拒绝。
- `Accepted`、`Running`、`Quiescent`、`Finalized` 分开表示。HTTP 成功或发送成功
  不能当成曝光成功、暂停已确认或收尾完成。
- 原生 API 结果不确定时先读取实际序列、相机和文件事件；未查清不能再次发送 Start、
  Capture 或运动命令。重试受原作业次数/时间预算约束。
- worker 使用同进程的有界运行许可和心跳检查；主控失联后，即使模板尚有循环/帧数，
  本端也不得继续发起新曝光。当前曝光按锁定策略完成或中止，保留原帧并标记。
- 许可检查覆盖普通曝光、循环、自动对焦和滤镜探针的实际命令发出点，不能只在模板
  开始时检查。若现有 API/插件钩子无法可靠做到，就不能宣称具备无人值守能力；部署
  前必须补足实现或明确只能使用受监督模式。
- 心跳、静止等待、最大重试和恢复预算按现场采样周期、最长曝光与保存耗时配置，不
  写死一个过短的统一秒数。短暂通信抖动不立即触发全台反复停启。
- 心跳许可不是屋顶安全证明，也不授权 worker 停放、关顶或接管 PHD2。主控自身崩溃
  时的全台安全仍由已 commissioning 的独立保障和明确现场模式负责。

## 5. 高级序列的两端外观

主控负责目标顺序和共同生命周期；worker 模板只定义本目标的 QHY 采集计划。

~~~text
光谱 N.I.N.A.：主控目标容器
├─ 时间 / 高度 / 目标顺序 / 本目标结束条件
├─ OpenAstroSpec：锁定目标、Night Setup 与双实例身份
├─ OpenAstroSpec：经主控 N.I.N.A. 目录转向并确认静止
├─ OpenAstroSpec：请求 QHY 新广域见证
├─ OpenAstroSpec：G3 获取目标、入缝并建立 PHD2 导星
├─ OpenAstroSpec：启动测光实例的受控高级序列 ─────┐
├─ OpenAstroSpec：ATR 自适应试拍与光谱科学块      │ 并行
├─ OpenAstroSpec：停止两路新曝光、关联结果 ◀──────┘
└─ 主控目标级 / 夜间级收尾

测光 N.I.N.A.：本目标受控测光模板
├─ 核对共同目标与本端相机/滤镜/焦点配置
├─ 每滤镜短探针 / 已验证档位
├─ 滤镜序列 + 本光路焦点补偿 / 必要的自动对焦
├─ 多帧曝光循环 + 本地许可/主控暂停/时长条件
└─ 本端停止与不可变文件清单
~~~

主控提供少量可组合项：准备双实例、获取/入缝、启动测光、ATR 科学块、测光健康条件、
双端暂停/翻转屏障、停止并关联。Dockable 一键入口生成并执行同一高层计划。获取/
入缝内部的 LED、PL3、PHD2 和回程事务不能拆成可任意删除的低级指令。

### 5.1 从用户已有测光模板迁移

先导入模板副本，列出允许、需改造和禁止项；保留原模板及哈希，不直接覆盖。

- 可复用：本端滤镜、曝光帧数/时长、目标元数据、经核验的 GS350 焦点补偿和自动对焦。
- 需包装：循环、批量曝光、失败重试、取消和收尾，服从本地许可与共同停止条件。
- 不允许从 worker 发出：转向/居中/Sync、抖动、PHD2 启停/重标定、中天翻转、停放、
  屋顶/镜盖、UVEX 机构操作，以及可能执行这些动作的脚本或第三方触发器。
- 启动前递归检查嵌套容器、条件、触发器和脚本；未知动作不能只按显示名称加入白名单。
  运行中编辑冻结模板、切 Profile、手工连接共享设备或改变目标，应进入接管/暂停，
  不能让另一实例悄悄继续原计划。

普通深空“拍几张后抖动”的模板不能直接用于狭缝联测。未来若需要联合抖动，必须由
主控暂停两路、执行有界运动并重新入缝后恢复；它不属于第一阶段实现。

## 6. 从广域见证到同步测光的完整 QHY 路线

迁移不只替换测光启动：原服务还承担目录转向后的广域取场、失败曝光阶梯、G3/QHY
同指向解算配对。**这些阶段也统一改由 worker 拍摄，不能前半段用服务、后半段无声
切给第二个 N.I.N.A.。**

1. 主控锁定目标和拍摄目的，经 worker 获取新 `ACQUISITION` 帧；保存仍走 worker
   的 N.I.N.A. 原生管线，不将上一目标或历史日期目录中的文件冒充新图。
2. 主控保存曝光前后赤道仪读回、时间和文件哈希，再调用共享解算/物理校验组件。
   worker “解算成功”不直接授权赤道仪运动。
3. [ADR-0012](adr/0012-qhy-wcs-mount-coordinate-authority.md) 的无机械零位大坐标失配
   恢复仍仅由主控发起一次证据授权的 Sync；新 QHY 采集端不改变门限、读回或后续
   fresh G3 到位证明。正常 QHY/G3 光轴差不能当成主控坐标修正。
4. G3/入缝/PHD2 保持共享生产路线。QHY 可以准备本光路焦点和探针，但取场帧、对焦
   帧与科学样本分开；静止见证与会改变其绑定的动作不得重叠。
5. 主控允许科学阶段后，worker 运行锁定的测光模板，与 ATR 按各自节奏并行。首帧
   “已采到”、任务“健康”和测光“质量通过”分别记录，避免重现等待首张合格测光帧
   而无法启动的死锁。

## 7. 暂停、翻转、失败与收尾

### 7.1 普通暂停与恢复

主控停止安排新 ATR 曝光，并向 worker 发出相同暂停边界。两端报告曝光、读出、保存
及相关动作的实际终态；不能把“收到暂停请求”显示成“双端已静止”。普通暂停不等于
关顶或清除运动账本，导星/镜盖处理遵循已有模式。

用户在 worker 手工暂停/停止，也通知主控进入可见暂停或接管；只有用户或明确恢复
策略再次授权并核对目标、实例、配置、新鲜导星/狭缝证据后才恢复。可恢复瞬态与人工
暂停分开，不能以通用重试覆盖人工意图。

### 7.2 中天翻转屏障

1. 主控按剩余曝光、保存、最坏恢复时间和本地地平线预留翻转窗口。
2. 禁止两端新曝光，确认或按策略中止当前曝光；排空 worker 会改变光学状态的动作。
   正常翻转先取得两端静止证据，不能带着未确认命令直接移动赤道仪。
3. 主控在旧侧按既有预算解决可确认的锁点动作责任，结束旧 PHD2 guide epoch。
   账本仍有歧义时不得清零，更不能把旧像素回程向量带到新侧执行。
4. 仅由主控 N.I.N.A. 原生赤道仪路线翻转；普通星场重新居中不能误用 ATR 光谱图。
   未公开的翻转钩子需先做版本化适配和模拟验收，不假定现在已经接入。
5. 作废旧 pier side、朝向、guide epoch 相关证据；重取所需 QHY 静止见证和 G3 WCS，
   重新核验狭缝、PHD2 原生校准适用性、选星和实际入缝。
6. 主控安全/身份/新鲜度门通过，按本轮严格或已授权监督质量策略恢复科学阶段；不因
   双实例改造撤销 [ADR-0013](adr/0013-supervised-slit-quality-warning-probe.md) 的警告
   策略。QHY 是否必需由预先锁定的联测策略决定。
7. 翻转前后样本归属不同采集区间；跨越运动/恢复区间的帧保留并标记。

### 7.3 故障处理矩阵

| 事件 | worker 行为 | 主控行为与成功边界 |
| --- | --- | --- |
| QHY 饱和、比较星不足、对焦/信号质量差 | 保留帧及分项标志，按本滤镜已授权的有界策略重试或调整 | 显示测光质量警告，不自动宣称光谱失败，不把坏测光计为合格 |
| worker 断连/崩溃/驱动失去相机 | 不自动切回服务，不确定命令保留 | QHY 必需则暂停科学块；可选则记录缺失，仍须通过 ATR/PHD2/安全门 |
| 主控断连/崩溃 | 本地许可到期后无新曝光；当前帧按策略收束；禁止共享设备运动 | 重启先核验双方状态与旧账本，不凭新进程/运行 ID 消除旧责任 |
| 应答丢失、重复 Start/Capture | 查询原命令结果，不盲目再次曝光 | 命令/帧 ID 去重，实际证据未明前不能记为完成 |
| 用户暂停/停止/编辑活动配置 | 可见暂停/接管并报告 | 不自动 Resume，不热换目标或配置哈希 |
| PHD2 真丢星、未确认锁点或设备明确不安全 | 接收停止许可，保留异常区间数据 | 执行原安全/恢复流程；短时质量警告与真实危险分开 |
| 紧急收尾但 worker 不响应 | 尽力本地停止，无关顶/停放权限 | 握手超时不能无限阻挡已授权安全收尾；保留未知状态，不伪造双端完成 |

只读刷新和有界重试可以恢复瞬态；身份变化、歧义运动和人工接管不能靠“再试一次”
解决。优化恢复路径不等于增加无限重试或重新发放运动预算。

### 7.4 目标结束与夜间收尾

先结束两路新科学曝光、保存结果，再由主控执行目标级或夜间级策略。目标完成不自动
断开所有相机；制冷、关盖、停放和屋顶遵循既有配置，不能因 QHY 模板中的通用收尾
项而提前影响 ATR。弱监督仍不自动开关屋顶。

最终报告分别列出 ATR 采集结果、QHY 作业终态、QHY 科学质量、共享设备收尾和未确认
状态；一个 worker 的 `Completed` 不代表整个目标或全台收尾成功。

## 8. 测光科学计划与数据关联

### 8.1 复用拍摄能力，保留测光专用要求

模板可设置滤镜顺序、每滤镜曝光/帧数、循环时长、焦点补偿、自动对焦和校准帧。先
复现操作员已有模板，再按需加入每滤镜短探针及离散曝光选择；不要把某夜 3 s 或 15 s
当成跨目标真值。自动调整产生新版本/证据，不静默混合不同读出模式。

物理槽位/带通、HDR 线性与拼接拐点、比较星/检验星、颜色项、偏置/暗场/平场和结果
不确定度继续遵守 [QHY 测光记录](qhy-photometry-commissioning-2026-08-25.md)。第二个
N.I.N.A. 拍出图不等于上述标定已经完成。采集状态与科学接受/拒绝分开；原 QHY 后处理/
质量算法可继续消费 worker 的不可变文件，但分析进程不再打开相机 SDK。

### 8.2 时间契约

- 两端共用父 `ObservationRunId`，各自有子作业/曝光 ID；保存目标 J2000 坐标、实际
  Profile、相机、物理滤镜槽位/带通、曝光/gain/offset/模式/温度/binning 及焦点位置。
- 记录实际曝光开始/结束/中点、时间来源及精度/不确定度。命令到达或文件修改时间不是
  曝光开始；SDK 无法提供的量标记为估计，不制造精确硬件时间戳。
- 同机进程仍核验 UTC 跳变与测量延迟，超时使用单调时钟；未来跨主机部署需另有时钟
  同步与偏差证据，不默认由本方案覆盖。
- 按曝光区间重叠和中点差建立**一对多** ATR—QHY 对应表，记录覆盖比例、滤镜、时间差、
  空档以及导星/云/翻转/对焦标志。不要求曝光等长，也不承诺软件提供硬件级同时曝光。

### 8.3 保存、归属与可复算性

ATR 和 QHY 均由各自 N.I.N.A. 原生保存到各自配置路径。分析进程不能再次保存同一帧
并产生两份互相矛盾的“原始文件”。曝光前注入可用身份字段，保存后只读核验实际 FITS、
原生类型和科学角色。若缺少可靠注入钩子，采用明确 capture ID、保存事件、绝对路径
和 SHA-256 sidecar 绑定，并验证无歧义；不曝光后改写 FITS。

manifest 只收录本作业实际发布的文件，不扫描整个日期目录凑数量。原文件不改写、
不重命名、不移动；`ACQUISITION`、`FOCUS`、`PROBE`、`PHOTOMETRY`、`SCIENCE`
分开统计。最终产品区分仪器差分量、标准星等、窄带指数与绝对线流量，软件切换不能
补齐缺失的科学证据。

## 9. 配置冻结、服务退出与 SDK 边界

### 9.1 运行配置

主控动作配置同时锁定 worker Profile ID、设备绑定、模板内容哈希、采样策略、本端
权限、超时/许可策略和 QHY 必需/可选选择。下一轮编辑产生新哈希，不能热改活动运行，
也不能要求用户永久保留旧配置。两端 `.astroproj` 工作副本与运行快照明确区分，真实
模板、设备身份和端点保存在忽略的本机配置中。

大模型仍从前台同源接口执行有限白名单命令，不能用任意脚本/worker API 绕过检查。
实例密钥、认证材料和私有网络信息不写入仓库或公开示例。

### 9.2 明确交接，不自动换拥有者

迁移必须在无活动观测的维护边界：

1. 备份两套 Profile、测光模板、QHY 服务实际配置及相关版本/哈希。
2. 结束旧 QHY 作业并确认曝光/读出结束、相机关闭和句柄释放，检查旧运行及动作责任。
3. 经单独授权停用可能重新抢占相机的服务启动/自动连接/监护策略，留下回滚记录。
4. 指定 worker 核验身份后连接 QHY、对应滤镜轮和 GS350 对焦器，其他实例不打开它们。
5. 静态证明、有界连接/曝光验收完成后，才允许新目标使用双实例模式。

服务无需删除，simulator、历史数据读取和离线分析仍可保留。第一版不维护两套可自由
热切换的生产控制路径；未来若保留服务为可选采集端，也只能在新运行前明确选择并
证明前 owner 已释放。同一运行故障时绝不自动从 worker 切回服务。

回滚反向执行同样的断开/释放/核验，不把旧作业或旧运动账本改成成功。

### 9.3 驱动和 SDK

不能假定 worker 与服务使用相同 SDK。N.I.N.A. 原生驱动可能加载其发布包内的 SDK，
ASCOM 又有不同调用链；实施前选择确切路线，记录实际 DLL 路径/版本/哈希、Windows
驱动及可读的固件版本，核验兼容性。

[ADR-0011](adr/0011-qhy-allinone-shared-sdk-installation.md) 的“服务直接加载 AllInOne
SDK”不能无条件套到 N.I.N.A.。ADR-0014 将此部署变化列为待审查部分；仍禁止为赶进度
私自向 N.I.N.A. 目录拷 DLL、混拼 SDK 或刷固件。完整官方包维护原则和证据要求保留，
更换采集程序也不证明 USB 掉线根因已解决。

## 10. 分阶段实施与交付

### 阶段 A：设计落地与只读双实例识别

- 审定 ADR-0014，按仓库流程正式更新冻结基线、适用的仓库所有权规则及哈希；此前不
  改变生产拥有者。
- 核对 Profile、驱动和设备分工，验证主控/worker 不争用插件端点。
- 明确序列、保存、取消和自动对焦钩子的实际能力；形成模板迁移清单并保留原文件。
- 新逻辑增加离线测试，文件发现与接口快照不授权设备连接或软件重启。

### 阶段 B：双模拟器闭环与故障注入

- 用两个 N.I.N.A. 模拟配置验证握手、准备、首帧、并行、暂停、取消、停止及文件关联。
- 注入应答丢失/重传、PID/端口复用、任一端崩溃、UTC 跳变、旧帧/重复帧、模板热改、
  共享设备禁用项及不响应的曝光边界，证明本地许可确实拦住下一帧。
- 验证 `.astroproj` 保存/加载/克隆、语言、序列进度和两端手工接管。

### 阶段 C：受控交接与无赤道仪运动的实机验证

- 获得单独硬件授权后按第 9 节交接；先只读连接，再做有界曝光/滤镜/焦点动作。
- 分别验证相机、内置轮及 GS350 对焦器，确认无 ATR、PHD2、赤道仪或 COM5 副作用。
- 对照旧 QHY/N.I.N.A. 数据，核验首帧时限、文件来源、槽位映射与取消终态。

### 阶段 D：真实单目标双前台联测

- 主控从 Dockable 或高级序列单次启动，经 worker 取得 QHY 广域见证，再完成共享
  G3/入缝/PHD2；启动可见的 worker 模板，与 ATR 同时产出真实文件。
- 分别验收严格模式与授权监督质量模式，保留误差/警告，不冒称精确入缝。
- 验证 QHY 必需/可选策略、暂停/人工接管、取消、有界收尾和真实时间关联。

### 阶段 E：翻转、多目标与夜间安全

- 先模拟翻转屏障、旧侧证据失效、无未结回程和新侧重新入缝，再经授权做实机翻转。
- 主控接管原生目标顺序、时间/高度和结束条件，失败目标不得污染下个目标的数据/配置。
- 按现场模式验收天气、镜盖、停放和屋顶终态，不用有人监督的一次成功代替无人值守。

每阶段交付版本、配置哈希、执行入口、完整终态和剩余限制。未达阶段写“待实现/待
实测”，不以截图、单个 API 成功或历史后台脚本替代生产验收。

## 11. 验收清单

只有同时满足以下条件，才可称为“双 N.I.N.A. 自动联测路线通过”：

1. 双实例实际使用不同、精确核验的配置和相机；QHY 服务已释放且不会自动抢占。
2. 两端前台显示实际同源执行，后台没有绕过任一端的命令或采集管线。
3. QHY 广域见证、配对和测光都经过 worker，无运行中隐式 owner 切换。
4. worker 的嵌套模板、第三方触发器和人工介入不能偷偷发出共享设备动作。
5. 断连/崩溃/心跳到期后，重复命令不重复执行，worker 不会无限自行曝光。
6. 人工暂停/取消优先、恢复重新核验；正常翻转等实际边界，紧急收尾不被失联端无限
   拖延；未确认终态如实报告。
7. Dockable、高级序列、模拟/replay 和真实路线共享主控阶段、质量和运动恢复逻辑。
8. 实际文件、角色、滤镜、运行 ID、哈希和时间关联可复算；采到图、科学质量通过与
   全台安全收尾分别证明。
9. 同一父运行下至少产出合格 ATR 科学帧和合格 QHY 测光样本。可选 QHY 全部质量失败
   时可以记“光谱降级完成”，但不能据此通过双路科学联测验收。
10. 单目标通过后，再分别验收跨侧翻转、多目标和无人值守；不能由一项成功替代其他。
    历史 .137 服务路线与 8 月人工双实例记录只在各自范围有效。

## 12. 后续实现与现场验收仍需核实

- 实际 API 是否能识别作业、暂停到曝光边界、停止自动对焦循环；哪些能力需 worker
  小型插件补足，不预先承诺未知能力。
- 同一插件在双实例中的角色、端点隔离和重复主控防护。
- 内置滤镜轮在选定 native/ASCOM 路线的句柄关系，以及 GS350 对焦器的唯一绑定。
- 共同运行 ID、曝光时间和 worker 字段的可靠 FITS 注入/读回或 sidecar 方案。
- 服务配置到现有测光 Profile/模板的逐字段迁移和回滚。
- 本机时钟/曝光时间精度、两端停止预算及实际所需测光采样覆盖。
