# 同步测光：先分清两个窗口，再完成配对

适用界面：`0.4.0.140` 起的“OpenAstroSpec 测光协同”。本页讲操作与命名，
不代表已完成设备交接或天空联测。完整安装与设备限制见[实现说明](dual-nina-implementation.md)。

## 三台相机各做什么

| 界面名称 | 用途 | 唯一控制者 | 当前台站的型号示例 |
| --- | --- | --- | --- |
| 光谱相机 | 记录二维光谱，供一维提取 | 光谱 N.I.N.A. | ATR585M |
| 测光相机 | 先拍广域定位帧，再进行连续测光 | 测光 N.I.N.A.；旧服务只作显式兼容路线 | QHYminiCam8M |
| 光谱仪导星相机 | 观察狭缝、判断目标位置、导星 | PHD2 | G3M2210M |

界面页签、步骤和日常提示按职责命名，不要求用户认识某个品牌缩写。
设备选择列表和“技术详情”仍显示实际型号、稳定 ID、原始错误码和文件路径。
历史配置、FITS 字段、接口、证据代码不因显示名称改变而重命名。

**通用命名不等于通用驱动已经通过验收。** 当前测光原生适配器仍明确支持
QHYminiCam8M；其他型号需要独立集成和验证。型号专属 SDK 修复、无机械快门等
硬件说明保留型号，不把台站特性表述成所有光谱相机的普遍属性。

## 第一次配置

先在空闲时备份配置。保留现有光谱 N.I.N.A. 窗口，另开一个使用**独立配置**的
N.I.N.A. 窗口作为测光端，两端安装相同版本插件。建议新建测光专用配置，避免
把光谱配置中的赤道仪、导星、屋顶等公共设备一并带入测光端。

打开两个窗口中的“OpenAstroSpec 测光协同”：

1. **光谱窗口选择“光谱主控”。** 第 1 步点击“复制主控编号”。
2. **另一个窗口选择“测光端”。** 在 N.I.N.A. 设备页只选择测光相机、测光滤镜轮、
   测光电调焦；其他设备必须取消选择，不能仅断开。回到协同页第 1 步，点击
   “记录所选设备（不连接）”。
3. 在测光端第 2 步粘贴刚复制的主控编号，再点击“复制测光端地址”。
4. 返回光谱主控第 2 步，粘贴地址，点击“保存测光端地址”。地址通常以 `nina://`
   开头；这是本机两进程的配对地址，不是相机型号，也不是网络服务器。
5. 核对测光端输出目录、未压缩 FITS 格式、设备与本夜配置，然后点击第 3 步的
   “开始接收主控任务”。重启测光端后需要重新允许本次会话。
6. 回到光谱窗口的“自动观测”，设置固定顶部的“同步测光”总开关，再从正式入口启动。

记录设备、复制信息、保存地址、开始接收本身**不会连接相机或拍摄**。
显示“地址已保存”也不等于另一窗口已经连通。运行时仍检查双方配置、会话和设备身份。
当前主控若显示“旧版独立采集服务”，说明尚未切换到双实例；不能让旧服务和测光端
同时占用相机。需要在空闲时由操作员确认旧服务释放，而不是仅改一个地址。

测光电调焦的原生补偿还要求匹配的本夜配置和已审核运动限额；界面配对不会生成这些
标定或升级旧的人工调焦许可。详细验收步骤仍按实现说明执行。

## 观测时看哪里

- **光谱主控 → 自动观测**：看整套观测的目标、定位、入缝、光谱曝光与收尾。
- **测光端 → 测光协同 → 运行状态**：看测光任务类型、实际状态、已记录帧数，
  以及暂停、停止和重新允许新任务。
- **技术详情**：排查问题时再展开，里面保留准确设备 ID、原始状态、原因和文件路径。

“正在暂停”表示还在等待当前帧、保存或设备动作，不是“已暂停”。“正在停止”也不是
“已停止”。人工暂停/停止不能由主控偷偷覆盖；需要重新开始时，先停止旧任务并等待
终态，再点击“允许接收新任务”，最后由光谱主控按正式流程发起新任务。该按钮不恢复旧任务。

## 光谱优先的含义

光谱定位需要测光相机时，连续测光先在帧边界让路；确认曝光、保存和设备动作结束后，
同一个相机拥有者才拍新的定位帧。定位与导星恢复后，主控安排续测并保留中间的覆盖缺口。
光谱实例不会为此另开测光相机。

关闭“同步测光”只是不做连续测光；定位所需的测光相机短曝光仍可使用。
这是同时段并行观测，不承诺相机硬件同步触发或亚秒级计时精度。

## 是否必须用高级序列

不必须。直接在测光协同页开始接收即可。当前高级序列入口只支持一个测光协同接收项和
受限顺序容器，不支持直接导入任意深空模板，也没有开放独立抖动、翻转和自动对焦扫描。
