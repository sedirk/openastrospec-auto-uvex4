# 上轮跨侧回程的只读起点核验（0.4.0.189）

## 事故与原因

0.4.0.188 启动时在 Night Setup 之前报告 `G3_MOTION_CRASH_RETURN_BLOCKED`。
原始原因是 `G3_SEARCH_PIER_SIDE_CHANGED`（保存的 `pierWest`，当前 `pierEast`），
不是文件哈希不一致，也不是 SEP 检测失败。界面原来把所有这类 G3 错误归成了
“WCS 证据不足”，掩盖了真正的恢复分支。

上轮保存的是最终绝对起点回程：指令坐标与保存起点相同。
起点 RA=31.39937583333335°、Dec=42.45742583333334°（JNOW）；
此前一次所有者读回约 RA=31.39791458333°、Dec=42.45742138889°，相差约 3.88″。
这在已有的稳定近起点容差 10″ 内，但旧函数先要求侧别相同，无法进行到位核验。
单次历史读回不能证明现在仍在原处，因此安装时不修改这份运行记录。

## 修复边界

- 仅新运行的 `ValidateNightSetup` 可以处理另一旧运行的最终绝对起点 `ReturnIntent`。
- 原有清单、哈希、配置身份、唯一未完成记录及预算聚合检查全部保留。
- 先通过所有者连接和安全检查，再从 N.I.N.A. 所有者读取连续坐标窗口，
  至少三次，覆盖已标定的稳定时间；侧别必须已知且窗口内不变、历元不变、
  赤道仪连接且无转向/导星脉冲，PHD2 不处于导星或校准。
- 每次坐标距旧绝对起点均须在**原有**稳定回程容差内，任意两次漂移不超过原有 2″。
  2″ 在此是回程静止核验，不是星像质量或入缝质量门。
  不自动开启跟踪；跟踪关闭时也必须满足实测稳定条件。
- 只有核验通过才保存读回证据和原封不动的旧记录副本，然后把原运行记录标成
  `SettledBudgetLedger`。旧运行 ID、侧别、起点、实际残差、消耗次数、累计运动和起始时间保留。
- 不把旧记录挂接到新运行，不沿用旧星图或旧目标成功状态。新运行仍从正式 Night Setup 开始。
- 核验失败保留未完成记录，明确显示起点残差和漂移；不跨侧发旧位移，不删除记录。
  出站、中间回程、侧别未知、同一运行的中途翻转均不适用此只读结束路径。

## 验证与交付

回归覆盖上述实测坐标、已过期的旧时钟、持久化重读与旧预算保留，以及错误历元、
侧别变化、窗口不足、陈旧/重复时间戳、无效坐标、未到原点和不稳定读回的拒绝。
生产连接顺序检查保证新分支位于身份/安全检查之后、旧预算接管之前；只读分支不含运动命令。
Dockable、序列和后台按钮仍共享同一个生产 runner，没有后台专属清账路径。

本次只安装、重启，不启动新的观测、回零或转向。真实起点核验在下一次正式启动时执行；
未完成该实机核验之前不能声称旧回程已解决或完整天空闭环成功。
