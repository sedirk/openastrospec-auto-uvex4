## 序列正常退出与独立安全待机（0.4.0.281 / ADR-0033）

选择“保持开顶”后，目标执行完、失败终止或取消会让原生观测序列退出，不再卡在
最后一个容器里等待截止。开顶保护由同一主控 N.I.N.A. 内的独立安全待机继续负责，
仍保留 AIWeather、断连检查、晨光和启动时锁定的截止；不自动开始新目标。

自动观测面板单独显示安全待机状态及“安全待机关顶收口”按钮。取消观测不会取消
天气保护；关闭 N.I.N.A. 则会停止软件保护，因此安装重启期间仍需现场看护。
取消本身不会触发新的机械动作。未确认停止、未结运动责任仍如实保留，不冒充成功。
无法确认停止时只保留监控和故障提示，不能保证机械收口执行，须人工处理。

手动启动同配置的新序列，可在安全、未到截止且已确认停止/结清的边界接替待机，
不会为交接而关顶再开顶。已经开始安全收口则不能抢占。仅修改表单不会改变待机的
截止或安全策略；新一轮启动才锁定新值。历史夜间记录及待机记录分别保留；新一轮
不再显示上一轮的取消/失败状态。旧模板和关顶开关无需改格式。

以下旧版本的“序列内等待”和“取消交还人工”行为由本节取代，其他采集能力不变。

## 精调预算与取场换侧（0.4.0.279）

已启用警告试拍的目标，第一步精调后若下一整步仅因累计运动/回程预留超额，
会在原预算内检查更短的一步；完整窗口预测须有用，移动后仍取三帧实测再决定
试拍。没有增加 100 px 等台站限额，也没有把预测当成实测。

WCS 转向后的已知侧别变化单独标记本目标失败，绝不跨侧执行旧向量。
只有终止清理、设备停止和旧账本归档全部通过，且本目标选择“失败跳过”，才继续
下一目标。未知侧别、断连或停止未确认仍不跳。正常光谱中天翻转继续使用 ATR
逐帧边界；取场阶段报告换侧不等于这一翻转流程已完成。
详见[取证、职责与回归](reports/2026-10-11-bounded-placement-and-pier-boundary.md)。

## 每目标曝光模式与紧凑状态栏（0.4.0.278）

展开各自的目标卡片，在“光谱采集 → 曝光模式”选择：

- **固定曝光**：填写曝光秒数，仍先试拍并执行原有光谱信号、饱和及安全检查。
- **自动曝光**：先试拍，沿用“观测计划”保存的 ATR 曝光阶梯与探针起始时间，
  由同一个 ATR 试拍流程选择档位；不会修改全局 Profile 或其他目标。

旧文件不需要转换：原来的正曝光秒数仍是固定模式，0 仍是自动模式，摘要显示
`N × AUTO`。在当前编辑会话切回固定模式会恢复刚才的秒数；新建目标默认为自动，
首次选择固定模式为 120 秒。运行中的目标不允许热改这两项。

N.I.N.A. 底部状态栏统一显示一条简短 OpenAstroSpec 进度，不再分别长期占用
启动、阶段和真实运行三段。冗长说明保留在日志，测量/失败证据不变；进度、原生
设备自己的状态与模拟标识保留。连接 AIWeather 或选择 REAL 的提示不等于安全许可。

## 警告后试拍与完整安全链（0.4.0.275 / ADR-0031）

“允许警告后试拍”是保存到 Profile、启动时锁定的**科学质量策略**，不再要求切换为
有人弱监督。保持完整 AIWeather／屋顶／晨光／截止／所有权安全链，也可以使用同一
生产 runner 的实测警告试拍；单次运行和序列目标使用相同决策。未勾选时仍严格验收。
警告不代表精确入缝，FITS 和证据保留实测残差、SLITWARN、SLITPOL 和 SAFEMODE，
最终仍按实际光谱信号验收。新策略不改变任一目标的曝光张数、强制校准或收口选项。

滚动检查只补一帧，但验收的是完整连续窗口；识别失败会丢弃旧窗口重新取得整组，
不拼接失败帧前后的好帧。光学质量耗尽使用显式目标级结果，停止与归档确认后执行
该目标卡的“质量失败后跳过”。未知故障、停止未确认、天气不安全、人工取消或
“结束整夜”策略仍停止后续目标，不能因改为目标级结果冒充已停止或观测成功。

## 开始区域的两张启动卡片（0.4.0.266）

按顺序放置：等待开始时刻 → **启动 AIWeather 安全检测** → **选择真实观测模式** →
等待到安全 → 目标区域。两张卡默认关闭，必须显式启用；仅支持主控实例、根序列开始区域，
且每张光谱目标卡已经是 REAL。不会自动把模拟目标改为真实，也不授予后台控制权限。
AIWeather 卡只连接已选中的 `AIWeatherSafetyMonitor`，不会替换天气源；已连接不重复连接。
连接成功不代表 Safe，仍由随后原生“等待到安全”和运行期安全链判定。运行中的序列不会热改。

同版移除入缝阶段光学导星偏差的 2→2.5→3 阶梯；有效新帧中偏差大于 3px 只警告，
不因这个值重复等待、重新校准或退出。真正丢星、原生命令未完成和目标未入缝仍是独立问题。
详见 [ADR-0028](adr/0028-advisory-measured-guide-residual.md)。

## 目标结束自动归档导星旧状态（0.4.0.265）

目标完成、失败或取消后，在确认本轮采集已结束、PHD2 已停止、赤道仪没有运动或
导星脉冲、调焦与测光任务空闲且设备身份一致时，自动归档该目标的 G3/PHD2 控制记录，
清除目标局部的旧帧、导星会话与 epoch 缓存。原始 FITS、日志、计数和控制记录原文保留。
不重启相机，不清除 PHD2 校准，不执行 Home/Park，也不为清理状态开关顶。

这里的“回程”只是回到本轮定位前的旧锁点，不是机械回零。目标已经结束时可以明确
放弃旧回程并保留审计；不会冒充回到原位、成功入缝或取得科学帧。下一目标重新解算定位。
暂停后恢复、同目标重试和中天翻转前后仍属于同一目标，不能借清理刷新运动或时间预算。

已审核的导星丢星、回程稳定失败及 epoch 改变，可按目标卡保存的“质量失败停止确认后
跳过”处理，但必须先成功完成上述停止与归档检查。无法确认停止、设备身份不符、坏记录、
未知异常及其他机构/翻转责任仍保留，不启动下一目标。升级前已结束目标的旧 PHD2 记录，
可在新一轮取得新鲜 G3 星场后按同一检查迁移，不盲目重放旧回程向量。

这是 [ADR-0027](adr/0027-terminal-target-guide-state-retirement.md) 对下面历史版本
“未结回程一律阻断下一目标”的有限替代，不改变 AIWeather、晨光、截止或收口开关。
WR137 的短帧交接另增加一次有界边界复核：仅边界超出量不大于本对新帧实测散布时补拍
一对；最终仍须两张均落在原交接范围内，不能用额外复核扩大接受半径。

## 单次运行和序列收口分开（0.4.0.263）

- **单次运行**：自动观测 → 高级设置 → 站点与模拟，独立设置“单次完成后关顶”和
  “单次普通失败后关顶”。只写下一次独立运行的配置快照，不控制整夜序列；关闭时
  屋顶由人工接管，不能当成无人值守待机。运行中的完整安全链 Unsafe 不受普通失败开关影响。
- **序列运行**：右侧指令集 → OpenAstroSpec Auto → **关顶与整夜收口（可选）**，
  拖到“光谱整夜序列”容器的最后，最多一个。指令上的“普通结束或失败后关顶收口”
  开启时统一收口；关闭时，在确认设备停止后保持受保护的开顶待机。所有目标都失败
  也不会因此跳过该选择。不能放进每个目标卡片，也不能放在整夜容器外。
- 新模板已带末尾指令；旧文件没有该指令时，仍使用原“测试结束保持开顶”开关。
  有新指令时以新指令为准，不叠加两个互相冲突的选择。选择在启动时锁定，不能热改。
- 目标层只停采集、停导星、保留/核对运动账本。实际关盖、停放、关顶仍由同一个整夜
  所有者执行，并逐项读回；没有新增屋顶驱动或第二个机械所有者。
- 截止、晨光、AIWeather 不安全、安全监视断连/身份不符仍结束待机并安全收口。
  普通取消仍不发机械命令；未结运动不会被“顶已关”或“不关顶”清除。

这是普通收口策略选择，不是关闭天气保护。前后半夜两个独立序列仍各有自己的截止，
保持开顶不承诺跨截止免关顶或自动接力。

## 可跨夜复用的纯时间截止（0.4.0.261）

**开始**继续使用放在整夜容器前面的 N.I.N.A. 原生“等待到时间”；**截止**在整夜容器
的“夜间设置”填写 `00:30`、`05:00` 等本机时间，不必每天改日期，也可填写秒。
本次两份十目标计划分别为 `19:00 → 00:30` 与 `00:30 → 05:00`，原文件名不变。
两份都按用户要求启用“目标结束后保持开顶待机”：提前完成或质量跳过不立即关顶，
截止（分别 00:30 / 05:00）、晨光或 Unsafe 仍统一收口。它们仍是两份独立序列，
不会自动接力，也不保证 00:30 两段之间免关顶。

截止按本机时区、中午 12 点至次日中午划分观测夜：晚上启动时 `05:00` 指次日凌晨；
凌晨启动仍指当天凌晨。05:00 已过而在 06:00 重试，不会自动改成明天 05:00。
只有重新启动新观测夜才计算新截止。开始等待仍遵循 N.I.N.A. 自身的跨夜规则；
这里固定中午边界是为了避免晨光之后重试把截止推迟一晚。
运行中目标切换、等云、重选星、重新校准、翻转和保持开顶等待都复用同一 UTC 截止；
本夜日志保存原输入、时区、观测日期、解析时间与实际 UTC 截止。

旧带时区日期仍按原绝对时刻执行，不擅自迁移；无日期的时分输入才可每日复用。
留空仍表示不设时间截止（晨光和目标完成有效），但“保持开顶”不能留空。
夏令时缺失/重复时刻拒绝启动，可显式输入带偏移的绝对时刻。
旧 JSON 字段名 `EndAtIso8601` 保留，但现在可填 `05:00`。纯时间文件需 .261 或更新插件；
旧版会拒绝，而不是忽略截止。不得删除截止来绕过版本不兼容。

晨光、AIWeather、安全收口及每目标曝光/导星恢复选项均不改变。时间可复用不代表目标
全年可见，跨季节仍须检查高度/中天窗口。设计见 [ADR-0025](adr/0025-reusable-night-clock-deadlines.md)。

## 如何使用

### 在每张目标卡片内编辑（0.4.0.259）

展开高级序列中需要修改的 **UVEX4 目标观测** 卡片，直接编辑该目标；不再在整夜顶部
用下拉框选择目标。每张卡片独立显示名称、J2000 赤经（时/分/秒）、赤纬（度/分/秒）、
目标高度图、合格帧数、固定曝光秒数、最多尝试、可见窗口预算、强制校准开关和失败策略。
目标身份区可折叠，光谱采集和强制校准仍在本目标内；不用展开内部十一阶段。
复制、删除、上下移动仍使用 N.I.N.A. 原生容器操作，编辑后用原生保存按钮保存序列。
不修改共享 Profile；运行中先停止整个序列，不能热改活动目标。

交互参考 [N.I.N.A. 官方高级序列说明](https://nighttime-imaging.eu/docs/master/site/sequencer/advanced/advanced/)
及本机对应版本的 `DeepSkyObjectContainer`、原生坐标模板和层级容器视图。复用原生
`InputCoordinates`、坐标校验、折叠控件和高度图；按目标分层编辑，而非在整夜容器再造一个目标表单。
这不改变光谱目标内部的固定十一阶段，也不表示可混入普通主相机曝光或普通翻转来代替光谱流程。

**`2×120s` 是两张合格的 120 秒 ATR 光谱，不是每个目标后额外等待 240 秒。**
合格试拍可计入两张，失败帧不计入；定位、制冷、导星、读出、重试另耗时。
将帧数改成 3、曝光改成 300，摘要随之显示 `3 × 300 s`；生成器的目标标题也同步更新。
从 0.4.0.278 起直接选择“固定曝光 / 自动曝光”；旧文件的曝光 0 仍兼容自动探针选档。
不要只改容器标题；自定义标题只是标签。

替换目标可以直接填写名称及坐标，也可以把右侧“目标”中的已保存目标拖到本目标身份区，
或点击“从星图读取”导入配置的星图软件当前所选目标。名称输入不自动查星；“发送到构图助手”
只打开规划视图，不执行指向、居中或曝光。赤经直接输入时分秒，赤纬保留负零度的小数角度。
拖入和星图导入只替换本目标身份，不覆盖其曝光、导星或失败选项，更不会修改其它目标。
名称或坐标变化会清除旧目标目录资料，避免继承旧目标的星等/分类身份。
改完还须检查新目标的可见窗口，不能认为旧目标的预算仍然合适。

每个目标的 **本目标开始时强制 PHD2 校准一次** 默认关闭。打开后，在该目标首次无未结
精调责任的导星边界，请求 PHD2 重新校准；完成后重新取场、确认狭缝，再进入精调。
这是会产生运动的选项，不是在编辑或加载模板时立即执行。失败/恢复/翻转续拍不重复
强制校准；PHD2 仍是唯一校准管理者，不恢复旧的重复数值硬门。详见 [ADR-0023](adr/0023-explicit-per-target-phd2-calibration.md)。

整夜容器只保留全夜摘要与默认折叠的 **夜间设置**，包含截止、晨光、初始导星稳定等待、
Home/Park 和保持开顶设置；不再显示任何单目标参数或强制校准开关。
此次编辑界面不改变天气、安全收口、目标间屋顶状态或既有失败跳过策略。

已有可直接导入的[三目标光谱序列模板与填写说明](spectroscopy-multi-target-template.md)

## 目标间与整夜结束

每个目标结束先停止并核对 ATR/PHD2/并行测光状态，不在目标之间反复关盖、关顶。
整个夜间容器持续持有同一个观测排他锁，目标间隙也不允许面板另开一轮或主镜对焦。

整夜完成、截止，或明确点击**结束本夜并收口**后，先等待当前目标任务退出及停止确认。
默认生产收口为：关平场板/镜盖 → 赤道仪已标定停放位 → 确认停放且停止 → 关顶并回读。
ADR-0021 已确认无干涉模式保留镜盖收口，但屋顶先于独立 Park 关闭并确认；Park 失败仍报错。
任何断连、身份不符、运动未停或终态未确认都不能显示收口成功。
**停放不等于机械 Home。** 默认模式须现场确认已保存的 Park 姿态允许关顶；无干涉模式则须确认
所有姿态均允许关顶，不能把 Home 或失败的 Park 当作这项确认。

### 可选 Home → Park 收口（0.4.0.246 起；0.4.0.247 修正原生开关标签）

经台站所有者明确要求，原生整夜容器增加“收口先 Home 再 Park”及 30–600 秒 Home
超时（默认 180 秒）。选项默认关闭，保存于序列而非通用 Profile；启动时锁定，复制和
原生 JSON 保存/加载均保留。只有已验证全姿态无干涉、完整安全链的台站可在真实模式启用。
启用后整夜结束/Unsafe 的顺序为：停止采集与导星 → 关盖 → 停止赤道仪 → 关顶并核验 →
一次 Home → 核验 Home 且停止跟踪 → 一次 Park → 核验 AtPark。已 Park 不再 Unpark/Home。
Home 与 Park 使用各自的超时；Home 失败会请求停止、不再发 Park、不重试、不重开顶。
普通取消仍不执行机械收口。不要在序列末尾再叠加同类原生指令，避免重复运动。

Home 的 API/驱动返回值不是到位证明：必须同一 N.I.N.A. 所有者、精确设备身份，且
连续两次读回 `AtHome && !Slewing && !IsPulseGuiding && !TrackingEnabled`。
它不清除旧运动账本、不设新 Park、不改限位，也不是下次启动时自动回零的隐藏恢复。
2026-10-09 单次现场 Home 出现“原生日志完成，但 AtHome 持续 false”的不一致；新增
检查会保留此失败。自动 Home/Park 的真实成功验收仍待设备动作与读回恢复，不保证
仅添加该选项即可解决控制器问题。

普通“取消”/中断只停止采集，不新增机械收口动作；收口进行中取消也传给同一收口操作。
安装本身不执行这些动作，也不自动续拍；真实启动和机械收口须有适用的当次观测授权。

## 失败策略与边界

0.4.0.271 补齐 `PHD2_LOCK_RETURN_POSITION_UNCONFIRMED` 的质量失败跳过分类：

曝光已停止。此分支不发布观测成功，也不改变上一目标的停止确认或旧运动账本。
截止/晨光、取消、安全变化、无效计划、配置变化仍停止；开始设备流程后的高度失败

`%LOCALAPPDATA%\UVEX-ADV\nights\night-*.json`。这些是本机运行证据，不进入 Git。

## 0.4.0.243：目标失败跳过与整夜收尾边界

原生整夜序列仍由 N.I.N.A. `SequentialStrategy` 驱动。单目标质量失败不等于目标完成：
保留其失败 manifest，等待协调器持久化结束、采集停止及运动责任结清后，才记录
`SkippedQualityFailure` 并进入下一目标。未知故障、取消、天气 Unsafe、设备身份改变、
持久化错误或未结运动不按普通目标质量失败跳过。

终态质量门会先释放原生阶段项，再完成通知/持久化。桥接器明确记录终态质量门，
不再把这一时间差误判为原生条件要求结束整夜。目标监听只接收本次 run ID 的快照，
上一目标的 Faulted 不得终止下一目标初始化。Journal 保留失败策略、终态代码、
人工结束/Unsafe/取消标志，便于区分“质量跳过”与“整夜停止”。

整夜计划的 `DeferObservatoryCloseout` 同时约束失败门、重新验证与统一故障清理；
目标只停止其采集所有者，夜间容器才负责最终机械收口及 Unsafe 响应。独立单目标的
完整安全链行为不变。全姿态无干涉模式下，N.I.N.A. `SetTrackingEnabled(false)` 返回的
