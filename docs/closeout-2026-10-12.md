## 2. 设计与安全语义

- [ADR-0032](adr/0032-meridian-boundaries-through-acquisition.md)：小时角过零不等于
  实际换侧。同侧小幅修正继续；计划翻转或稳定读回换侧才进入已有受控中天会话。
  原所有者退出、停止及持久化意图通过后，归档旧控制句柄，新侧重新取场、入缝、
  导星及试拍，累计科学计数。已换侧不再发第二次翻转，不跨侧使用旧回程向量。
- [ADR-0033](adr/0033-independent-observatory-safety-standby.md)：保持开顶不再让
  原生序列永远 RUNNING。普通结束/故障/取消可以结束观测，将原锁定安全请求和独占
  编排租约交给同进程的安全待机；天气、晨光、原截止继续有效，失败记录不冒充成功。
- [ADR-0034](adr/0034-idle-boundary-mount-clock-recovery.md) 和
  [ADR-0035](adr/0035-clock-repair-same-target-continuation.md)：只在确认停止的边界，
  整夜最多预记一次校时恢复；采用同一 N.I.N.A. 所有者和原 TimeSync 路线。后者替代
  前者“成功也必须跳目标”的设计：先按原剩余时间、动作、尝试和积分账目重新定位
  同一目标，只补未完成帧，恢复失败或预算耗尽才按保存策略跳过。
- 以上设计变更及 AGENTS 的非 UI 优先验收规则已由此前用户明确要求，相关受保护
  哈希随对应维护更新。本次 Git 收口只核验，不改冻结记录、不重新生成其哈希。
- 真实天气危险、电子/机械限位、设备独占、操作员取消和未确认物理停止仍独立保留。
  只有已分类的目标质量失败且停止/责任检查通过，才按保存策略继续下一原生目标；
  不把所有异常统归“忽略”，也不重置失败目标的运动或时间预算。

### 屋顶策略的准确含义

| 情形 | 已选择保持开顶时的行为 |
| --- | --- |
| 目标完成、普通目标失败、普通取消 | 观测任务退出，移交独立安全待机，不因取消本身发送机械动作 |
| 达到启动时锁定的截止或晨光高度 | 调用既有有界、逐项读回的安全收口 |
| AIWeather Unsafe、监视器断连或绑定变化 | 调用同一安全收口；一般数值变化但仍 Safe 不等于需要关顶 |
| 停止/设备状态未确认、收口失败 | 保留错误和可用监控，不把命令发送或软件退出说成屋顶已关 |
| 退出/重启 N.I.N.A. | 软件看护结束；旧待机和旧截止不会自动恢复，需人工/独立保护或显式新运行 |

这是当前序列策略的说明，不是独立 Windows 屋顶守护服务或普遍无人值守认证。
