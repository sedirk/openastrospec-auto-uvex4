## 目的

这套接口把历史 `tmp/live-unattended-loop/Invoke-LiveUnattendedLoop.ps1` 的“一次启动、持续观察、保存清单、遇到阻断后再处理”运行外壳，迁移到正式 N.I.N.A. 前端。历史脚本仍作为实机 commissioning 证据保留，但它直接调用 N.I.N.A. HTTP、PHD2、QHY、G3 与 PlateSolve3，不能再次成为生产入口。

新的后台控制器不维护第二棵观测状态机，也不直接访问任何设备或设备服务。所有改变状态的请求都在 N.I.N.A. UI 线程上调用当前 Dockable 按钮所绑定的同一个 `ICommand`；正式 `ObservationCoordinator`、生产 runner、设备单一所有权、质量门、运动/回程预算和不可变证据仍是唯一权威。这符合 [ADR-0009](adr/0009-single-production-observation-route.md)。

## 操作员可见的接口

在 `OpenAstroSpec 自动观测 → 高级设置 → 大模型前端闭环桥` 中：

1. 勾选“启用本机当前用户的 LLM 后台命名管道”。该开关会持久化，默认关闭；后台也可通过同页“代码启用后台桥”按钮所绑定的 `ICommand` 执行 `enable-bridge`。
2. 模拟流程可直接从后台触发。真实流程必须在每次 N.I.N.A. 启动后重新授权；可由操作员勾选，也可让后台执行与可见“代码授权本次真实流程”按钮相同的 `ICommand`。后台代码授权必须在该次请求中携带精确操作员证明，证明只用于内存比较，不写入 descriptor、audit 或运行清单。
3. 页首显示桥状态和最近一次后台调用；高级设置同时显示调用总数、恢复调用数和端点。

本机端点为：

```text
\\.\pipe\OpenAstroSpec.UVEX4.ObservationAutomation.v1
```

传输是当前 Windows 用户专用的 JSON Lines 命名管道。描述文件写到 `%LOCALAPPDATA%\UVEX-ADV\automation\bridge.json`，追加审计写到 `%LOCALAPPDATA%\UVEX-ADV\automation\audit.ndjson`。

## 协议

协议版本为 `1`，每行一个 JSON 请求和一个 JSON 响应。支持三个操作：

- `snapshot`：读取前端与正式 coordinator 的当前快照；即使桥未授权，也可只读查询关闭状态。
- `wait`：等待 revision 变化，最长 60 秒，用于避免轮询。
- `invoke`：触发一个白名单按钮；可携带 `expectedRevision`，前端已变化时以 `STALE_REVISION` 拒绝，要求调用方重新读取。

白名单包含：`enable-bridge`、`arm-real-control`、`disarm-real-control`、`arm-slit-quality-warning`、`disarm-slit-quality-warning`、`select-simulation`、`select-real`、`apply-target-draft`、`import-planetarium-target`、`import-framing-target`、`start-selected`、`restart-real-run`、`pause`、`resume`、`takeover`、`cancel`。其中 `enable-bridge` 只改变持久化接口开关，`arm-real-control` 只改变当前进程内授权并要求精确操作员证明，`select-real` 和 `select-simulation` 只改变模式选择；这些动作本身都不连接或移动设备。`start-selected` 与界面页首“启动”按钮完全同源，并按界面已经选择的模式启动；真实 `start` 与 `resume` 仍必须具备本次进程授权。`restart-real-run` 与界面“新开一轮”按钮完全同源，要求本次真实授权和同一份操作员证明；它按照正式产品逻辑安全关闭旧运行边界、审计退役可识别的旧 G3 恢复状态，然后建立新运行。

`arm-slit-quality-warning` 另需 `OPERATOR-ACCEPTS-SLIT-PRECISION-WARNING-SUPERVISED-ATR-PROBE`，不是常规设备运动授权的附带效果。对应的取消命令保存严格精度策略；两者均只能在计划可编辑时修改并保存当前 Profile 的科学质量选择，不能改变活动运行已冻结的动作配置。`supervisedSlitQualityWarningAuthorized` 保留兼容字段名，.168 起表示当前 Profile 选择，不表示真实设备已授权。

`apply-target-draft` 调用观测计划中“确认 J2000 目标草稿”的同一个 `ICommand`。可选 `targetDraft` 对象（PowerShell 客户端 `-TargetDraft` 哈希表）只能包含 `targetName`、`catalogId`、`rightAscensionDegrees`、`declinationDegrees`；坐标必须显式给出、有限且处于 J2000 度数范围。未提供参数时确认当前可见草稿。两个导入命令分别调用原有星图／构图导入按钮。三者均只在目标计划可编辑时执行，不修改运行中的目标，不改变设备、地平线、安全门、时长或光学设置，也不会启动观测。选定目标后正式启动仍会检查整个计划时段的地平线；不应通过降低门限来解决不适合当前时段的目标。

快照在 UI 线程从同一份不可变 dashboard 同步刷新显示与诊断后返回；读取本身不增加 revision，避免主机刚进入阻断状态时返回上一帧的空错误代码，也避免 `wait` 自己唤醒自己。

接口有意不提供 UVEX 设备手控、M2/狭缝/光栅运动、任意清除恢复账本、修改设置或删除证据。唯一可退役旧 G3 恢复状态的入口是与可见“新开一轮”按钮同源的 `restart-real-run`，它保留审计且拒绝歧义状态。后台不能把 disabled 的 UI 命令当作可执行，也不能跳过恢复复核、安全门或预算。

响应快照包含运行状态、当前/下一阶段、两级状态摘要、阻断代码与说明、恢复说明、全部阶段质量门、最近 30 条时间线、最近 20 份证据、运行清单、可用/不可用命令及原因、建议恢复动作和需要操作员完成的动作。面向操作员的文字跟随 N.I.N.A. 当前界面语言；稳定代码、原始技术消息和文件路径保持不变，便于大模型诊断而不篡改机器值。

## 命令行客户端

读取快照：

```powershell
.\scripts\invoke-observation-automation-bridge.ps1 -Snapshot
```

等待指定 revision 之后的变化：

```powershell
.\scripts\invoke-observation-automation-bridge.ps1 -Wait -AfterRevision 42 -TimeoutMilliseconds 30000
```

触发快照中已启用的同源按钮：

```powershell
.\scripts\invoke-observation-automation-bridge.ps1 -Invoke -Command resume -ExpectedRevision 42
```

## 从旧“一键完成”脚本迁移的闭环控制器

`scripts/invoke-model-frontend-closed-loop.ps1` 保留旧脚本有价值的外层行为：生成控制器 run id、从可见按钮启动、按状态 revision 等待、捕获完整 blocker 快照、原子保存事件清单，并可把 blocker 文件交给外部大模型修复命令。它不再包含任何 N.I.N.A. HTTP、PHD2、QHY、G3 或 PlateSolve3 调用。

控制器把“命令已接受”和“新观测已经开始”严格分开：启动前记住旧 `ObservationRunId`，只有前端报告了不同且非空的新 ID 后才绑定本轮生产运行。旧运行即使显示 `Completed` 也不能冒充本轮成功。最终成功还必须同时满足：前端状态为 `Completed`、快照 ID 与绑定 ID 相同、运行清单及其快照 ID 相同，且运行清单终态为 `Completed`。

验收还检查完整 11/11 阶段及 11 个 `Passed` 阶段门、无未完成阶段/暂停原因、请求模式对应的 real/simulator adapter、计划与锁定元数据 SHA-256 格式、同一 revision 的持久 `RUN_COMPLETED` 日志。真实运行必须具有非零 ATR 科学尝试/接受计数；所有登记证据文件须存在且实际 SHA-256 匹配。阶段警告保留在运行证据中，不以截图、旧 Completed、仅 RPC 接受或单张预览判断成功。

纯模拟流程：

```powershell
.\scripts\invoke-model-frontend-closed-loop.ps1 -Mode Simulation
```

真实流程必须携带显式操作员证明；控制器会依次调用可见的“代码启用后台桥”和“代码授权本次真实流程”同源命令，使两个复选框在前台同步显示：

```powershell
.\scripts\invoke-model-frontend-closed-loop.ps1 `
  -Mode Real `
  -OperatorAttestation OPERATOR-ATTESTS-ROOF-OPEN-CLEAR-SKY-DEVICE-MOTION-AUTHORIZED
```

可选 `-ModelRepairCommand` 是“后台模型已经决定并获准如何修复”后的执行钩子。程序向它传入两个参数：blocker JSON 的绝对路径和控制器 run id。它可以进行源码修复、构建或受控安装；它不是安全绕过器。只有 `PausedNeedsAttention` 和 `Faulted` 会进入这个结构化修复钩子；没有钩子或次数用尽时明确停止。普通 `Paused`、`ManualTakeover` 和 `Cancelled` 被视为操作员所有的边界，控制器绝不通用调用 `resume`，也不擅自重启。修复返回后会重新读取前端状态、恢复桥开关与本次代码授权，并建立一个新的运行边界：已有真实运行时调用原“新开一轮”按钮对应的 `restart-real-run`；干净真实启动或模拟启动则先选择模式，再调用页首原“启动”按钮对应的 `start-selected`。每次都必须重新绑定新的 `ObservationRunId`。

每轮控制清单以同目录临时文件加原子替换写到 `%LOCALAPPDATA%\UVEX-ADV\automation\runs\<run-id>\manifest.json`。其中明确记录控制器 ID、已绑定的生产 `ObservationRunId`、`entryPoint=NinaDockableICommandBridge`、`directDeviceApiCalls=false` 和 `productionRunnerRemainsSoleWorkflowOwner=true`，因此后台闭环的成功与前端手动点击共享同一条产品路线。命名管道客户端还同时限制连接时间和响应读取时间；即使 UI 线程不再响应，也不会让控制器无限挂起。

## 安全与测试边界

源码检查、命名管道协议测试、UI harness、编译和模拟运行不授权真实设备行为。真实曝光、赤道仪运动、屋顶/镜盖动作、PHD2 会话变化以及 UVEX4 机构运动仍须遵守 [commissioning 手册](commissioning.md)、现场安全条件和设备单一所有权表。

### 历史 PHD2 零向量跨镜筒侧复核

`ReturnRequired` 账本即使记录 `OriginLock == CurrentLock == RequestedLock`，也不能仅据此改成已结清。若是外来历史运行，且当前拓扑替换**唯一**的镜筒侧字段后能完全重现旧拓扑 SHA-256，才允许进入“只复核、不回程运动”的恢复入口；未知镜筒侧、相机/配置/ROI/binning/旋转/安装变化、非零向量或模糊意图阶段均不适用。

此入口仍检查原有配置、标定、身份、安全、预算、当前目标/狭缝、全新导星 epoch 和最终新帧证明。它不会凭坐标相等结清，不会跨镜筒侧解释非零像素向量。回程核心在每次读锁点后强制检查当前锁点与新建原点严格相同，且规划必须已经完成；否则保留债务并停止，绝不发出回程移锁命令。只有新证据通过后才能执行原有的原子结清/预算交接，随后重建正式 G3/狭缝授权再继续科学流程。

### PHD2 Selected 与曝光生命周期

真实测试发现 `get_app_state=Selected` 时 `capture_single_frame` 仍可能因 capture active 被拒绝。[PHD2 Guider::GetExposedState 实现](https://github.com/OpenPHDGuiding/phd2/blob/master/src/guider.cpp) 在 `CaptureActive=true` 的选星分支中可以返回 `Selected`；不能把它当作相机空闲证明。

停止与单帧采集均只接受 `Stopped` 作为空闲回读，停止 RPC 返回后仍须等待回读确认。普通 `Looping/Selected` 预览由正式 G3 采集入口执行受确认的接管停止；Guiding/Calibrating/LostLock/Paused/Unknown 不在该接管集合中。只有结构化的“下发前拒绝、尚未操作设备”异常允许一次接管重试。原生重选星连拍可以从 `Selected` 开始等待，但保存仍必须由新的 `LoopingExposures` 事件及同连接 Looping 状态共同授权；没有新事件不能保存旧图，也不能私自启动或停止拍摄。

### 原生重选星的几何排除

首次选星仍由 PHD2 对全幅原生排序。若返回星撞到目标光晕、狭缝或探测器边界，后续最多三次重选只向 PHD2 提供安全的矩形 ROI：排除目标光晕、有限狭缝区域、已拒绝点与已搜索区域。矩形按面积和坐标确定性排列，协调器不检测或排序替代导星，也不降低原有几何阈值。每次返回候选的 ROI、坐标、验证结果均写入 `phd2-native-guide-candidate` 证据；空候选只有在取得下一张真实新帧后才能继续。

大 WCS 修正后的局部搜索仍保留原始运动账本原点、消耗与时钟。新运动族的范围若连已结清位置都不能覆盖，必须在写账本前拒绝，不能把局部 900″ 半径直接写成距旧原点的总半径，也不能因一次尚未发出的搜索动作制造回原义务。

### 有人监督的新帧导星证据必须贯穿科学阶段

入缝和 `StartGuiding` 已接受的风扰新帧验证，不能在 `StartQhyPhotometry` 又被只认正式 settle 的旧判断否决。后续连续性检查必须复核同一连接/导星 epoch、同一已接受的 settle 操作及当前 Guiding/非暂停状态，并保持明确监督授权和标定质量门。

这不是永久放行标记：使用此路线时，每次 ATR 探测帧及科学帧曝光前通过 PHD2 的导星取帧接口取得至少三张新的不可变 G3 帧；每张目标身份和入缝残差均须通过当前质量等级缩放后的原有容差。检查不停止导星、不移动锁点、不重新开相机。结果写入 `phd2-supervised-pre-atr-window`，并保持 `unattendedAuthority=false`；新帧不通过则不打开 ATR 快门。

若只是新帧的光学残差短时超限，同一导星 epoch 内允许最多四组新帧窗口；每组仍需全部满足原容差，并保留失败窗口证据。连接/导星 epoch 变化或目标身份失效不得使用此重采样入口；四组用尽也不会放宽门限或自动重置运动预算。

`guide` 的本地终态等待还须覆盖接管首帧、读出和最后一次曝光边界：在原 settle 时限之外加入两次事件余量及两帧已验证曝光时长，但不改变发给 PHD2 的 settle 门限。只有真实收到、绑定到本操作的 `SettleDone` 才能产生结果；本地等待超时不能合成一个远端失败终态。这样不会在 PHD2 仍完成原操作时提前采残差，又被稍后到达的真实事件打断。

### 可选 QHY 配对任务的零帧终态

有界 QHY/G3 配对任务可能在首帧落盘前被正常取消。QHY 在创建任务时就返回未来的 `FrameIndexPath`，但零帧任务并不创建 `frames.jsonl`。此时仅登记包含零帧计数及终态的任务清单，不把尚未存在的索引发布给观测证据写入器。只要任务确实报告了帧，索引仍为必需证据，缺失时不能以文件存在性检查静默忽略。

### G3 回程的可恢复边界

回程中间点的名义位置偏差不能直接当作最终到达。仅当偏差不超过两倍原到达容差、回读漂移通过原稳定门、实际运动完整包含在预付单步预算内，且距离原点确实减少时，才允许从实测位置重新规划剩余回程；下一步仍检查全部动作、半径、累计距离和原始时间预算。证据 `g3-intermediate-return-replanned` 明确记录名义端点没有被接受、预算没有重置。

N.I.N.A. 重启后，恢复入口先执行与正式 Night Setup 同源的设备所有权、连接、标定身份和现场安全核验，再读取赤道仪坐标。原时钟到期仍不能发出下一步运动；但允许读取并稳定核验“上一笔回程已经到达原点允许范围”的事实，这与回程规划器原有的零动作完成分支一致。旧记录只有经过此证明才可结清。即便债务结清，旧运行的过期采集预算也不恢复；需要通过可见“新开一轮”同源命令建立新观测，而不是改历史账本。

控制器解析快照时间戳时保留 `DateTime` / `DateTimeOffset` 的小数秒，不经本地化字符串往返。否则同一秒内开始并报错的新观测会被误判为早于启动请求，掩盖真正的前端阻断。

### 分段 WCS 修正后的 PL3 搜索提示

目标尚在数度以外、一次修正只能移动到中间天区时，旧 QHY 帧因运动失去绑定，不能退回用最终目标坐标搜索当前中间天区。正式 G3 WCS 修正已计算的“上一张 WCS + 实际到位回读”预测中心应传入后续曝光阶梯，仅用来缩小 PL3 的搜索范围；它不是新 WCS，也不单独授权运动。每一档仍拍摄新 G3 帧并执行正式解算及原有物理/目标/狭缝质量门，且不因此多拍一次 QHY。来源和预测中心写入 `g3-solve-hint-measured-wcs-arrival` 审计。

### 导星帧的局部背景暗狭缝检测

普通暗缝检测先按原算法运行。仅当它返回 `SLIT_LOCUS_LOW_CONFIDENCE`，且本轮 LED 差分几何、轮位身份、相机和 binning 已验证时，才对**同一张新导星帧**追加双侧局部背景检测：沿狭缝的各采样点分别与自己的左右背景配对，避免把沿缝照明梯度混入噪声估计。

备用搜索不超过一条实测缝宽和 1°，仍使用当前配置的对比度阈值；至少 20 个有效配对、至少 2/3 的采样覆盖和正暗槽支持、左右两侧分别为正的中位暗槽差都必须通过。饱和采样不参与。其统计量采用局部配对差的 MAD，不与原全局背景统计量混称为同一次检测。证据 `phd2-fresh-slit-local-background` 同时保存原检测、备用检测、原帧哈希、PHD2 帧序号与时间。

此路径不叠加或改写原始 FITS，不改变曝光，不移动导星锁点；目标位置仍由当前新帧及原身份链确定。只有备用检测通过才生成该帧的残差证据；否则保留原失败并执行现有有界重采样。新算法的实机表现仍以正式前台运行的目标/狭缝、导星和科学终态证据为准。

新导星帧的普通识别入口也可能返回明确的 `TARGET_IDENTIFIED_SATURATED_TOPOLOGY`。当其保留正式目录 WCS 身份链时，残差记录必须沿用饱和实心核的测量类型，使用 `SATURATED_TARGET_TOPOLOGY_FLUX_NOT_APPLICABLE`，而不是把非线性的饱和连通域总 ADU 当作普通恒星通量。原积分值单独保留为诊断；普通恒星、身份不明或没有正式 WCS 链的结果仍受原通量硬门约束。

### 实测导星偏差与移锁收敛

旁星精调使用与保存帧绑定的 PHD2 `GuideStep.dx/dy` 和同一锁点，重建原生实测导星位置（多星模式保留 PHD2 自身的偏差估计）。保存前后必须保持同一导星帧号、锁点及连接/导星周期；若不满足，则只能使用真正通过识别的新帧本地质心，不能把请求锁点当成星位并伪造零残差。证据中分别记录原生偏差、原锁点和位置来源。

有人监督的移锁稳定等待不再固定为 3 秒：使用原单步时间预算的 60%，且不超过配置超时；稳定持续时间最多 3 秒，空间容差不变。例如 30 秒单步预算提供最多 18 秒稳定等待，余量用于新帧与回读。真实超时仍保留失败状态，监督新帧路径不能隐去实际导星偏差。下一步精调因预算不足被拒绝时，优先执行同一账本中已预留的回程，绝不重新发放次数或距离预算。

旁星的导星偏差与目标入缝残差必须分开：`MaximumGuideLockResidualPixels` 是导星相对请求锁点的跟踪建议值，不代表目标距狭缝的实际距离。在明确有人监督、同一锁点及导星周期内，若新帧包含实测导星位置和实际目标质心（不是旧 WCS 投影或请求锁点替代物），导星偏差超限记录为警告，继续以 `实测导星 +（实测狭缝中点 − 实测目标）` 规划精调。新帧窗口、标定质量评价与位移规划采用同一语义，不得在下一层重新按同一个跟踪偏差阻断；原始偏差、阈值与警告全部保留。该结果只授予有人监督运行权限，不授予无人值守科学权限，也不放宽目标入缝容差。

不能证明上述同帧几何时，仍只允许同一锁点、同一连接/导星周期内最多四组有界新帧，不选择其中最好的一帧冒充整组。首轮验证最多占用一个原单步时限；移锁后的等待与 settle 共用从该次确切锁点回读开始计时的原单步时限，不为重采样重置时钟。`phd2-placement-guide-window` 记录全部残差、建议阈值、几何依据、警告、次数、截止时间以及未追加导星/移锁命令。目标身份、帧新鲜度、检测器边界、位移/时间/回程预算和实际科学帧质量仍独立判断。

### 已取消目标与新目标之间的 PHD2 意图退役

操作员取消旧目标并明确启动另一个不重叠的新目标后，旧 PHD2 像素回程不得搬到新星场执行。只有旧 manifest 明确为 `Cancelled`、目录 ID 不同且目录位置相隔超过 1°（保守的不重叠判据，不授权任何运动）、新目标已通过正式 G3 身份/狭缝门和新鲜 mount binding、设备/标定包身份相符、赤道仪静止且 PHD2 实时报 `Stopped` 时，才将唯一旧 lineage 标记为 `RetiredCancelledObservation`。

该状态不是 `SettledBudgetLedger`，不声称回程成功、入缝成功或科学完成。退役前把整个旧状态写入新运行的不可变 `phd2-cancelled-target-retired` 审计，原 canonical 账本保留全部位置、累计量、次数和起始时钟，仅记录退役阶段及审计引用。同目标恢复、只改名称、旧运行仍活动、旧运行未明确取消、身份不明或新场不可靠时都不能进入此分支。后续新目标使用自己的正式指向/取场/精调预算，旧目标预算没有被重新发放。

同一目标跨夜/回零后的独立新运行另需可验证的物理起点：在本轮第一次目录转向和跟踪启用**之前**，程序必须两次确认同一赤道仪 `AtHome && !Slewing && !TrackingEnabled && !IsPulseGuiding`，同时 PHD2 实时报 `Stopped`，并保存本轮 `phd2-new-run-verified-home-boundary`。该检查只读，不发回零命令；需要回零时先取得操作员明确授权。此证据必须晚于旧取消运行的更新时间，属于当前 run 和同一赤道仪。随后仍需当前正式 G3 身份/狭缝与 mount binding 通过，才允许把唯一旧取消 lineage 归档为未完成。没有该新回零证据的同目标重试不能走此分支，跨侧旧像素向量依然不得执行，旧次数、累计量和端点依然完整保留。

### 大步 WCS 居中与预测/实测位置边界（0.4.0.124）

2026-09-06 天津四真实运行发现：赤道仪读回与 G3 WCS 的赤纬存在偏差时，把相同切平面向量分别套用到两个原点，会再次引入不同的 `cos(dec)` 换算，造成额外赤经轴误差。居中现将实测 WCS 中心与目的中心转换到读回的同一历元，转移赤经/赤纬轴增量；抵达读回误差也使用同一转换。实际球面运动、回程预留、地平线、侧向与累计预算仍走原校验，不以预测成功代替设备运动成功。

邻场 WCS 加已记账运动只提供取场预测。当当前目标场没有成功解算时，PHD2 新帧必须先以实心饱和核或原取场窗口内的唯一恒星质心接替预测点；不得拿未被实测接替的预测点授权锁点微调或声称入缝。普通恒星仍保留真实通量和原通量门限，饱和目标仍明确标记通量不适用；导星残差警告不取消目标/狭缝的独立实测要求。

这些修正的最终结果以安装后真实前台运行记录为准，编译和定向检查不构成闭环成功。

### 近邻接近与原生选星区域越界（0.4.0.125）

长距离 G3 居中不会直接把远处 WCS 的抵达预测当作最终取场证据。目标距离超过两倍图像长边时，先沿原方向进入目标位于画外 120 像素处的近邻点；在那里重新解算，再完成最后小步。近邻步骤不产生最终目标预测授权，仍消耗同一运动账本的次数、距离和时间，也仍需预留回程。审计同时记录狭缝目的点、近邻目的点及所用分支。

PHD2 `find_star` 可在 ROI 内挑中种子后，把精化质心移到 ROI 外。客户端为这种已明确完成的响应提供带原坐标/ROI 的类型化候选拒绝；前台流程将其写入原生选星证据，保持原 4 次上限并尝试下一未搜索区域，不对该候选启动导星。网络/协议/未知命令失败不因此被自动重试。

0.4.0.126 将近邻目的点接到专用的有限画外逆算入口，允许范围仅为上述 120 像素外沿；普通狭缝目的点逆算仍必须在画内。此修正针对 0.4.0.125 首次实机接入时被原画内参数检查拒绝的问题（发生在运动发出前），并增加了真实逆算接口的对应回归检查。尚不能把这些检查计为真实闭环完成。

### 近邻小步后的实测目标快速交接（0.4.0.127）

0.4.0.126 实机已验证近邻点能重新解算并完成最后小步，但到达后的完整 5/10/15 秒解算阶梯仍耗时数分钟；进入 PHD2 时实际目标已漂出原取场窗口。新路径只针对带正式近邻 WCS 和已记账到位读回的最终小步：首张参数、哈希、设备身份及像素检查合格的非全局过曝新帧，必须由原唯一恒星/实心饱和核算法实际识别目标，且实测点同时处于预测点和狭缝的原取场窗口内，才跳过本目标场重复 PL3 与更长曝光。

`g3-post-wcs-measured-target-handoff` 保存预测、实测、狭缝、源 WCS/运动绑定和新帧哈希。它只触发后续 PHD2 原生选星和新帧测量，不宣称目标场已解算，也不直接授权移锁或科学曝光。原 PHD2 新鲜目标/狭缝、通量语义、身份、运动/回程预算仍全部执行。未知、模糊、画外、超窗、全局过曝或只有预测没有实测时，继续原解算路线；中间近邻点仍必须正式解算。

0.4.0.128 将近邻步骤的“当前天区搜索提示”与“目标场免解算交接权限”显式分开。每个已到位 WCS 步骤都向 PL3 提供当前场中心；中间近邻点标记 `AllowUnsolvedTargetHandoff=false`，必须新帧正式解算成功。禁用交接不再丢失搜索中心、退回用尚在远处的目标坐标搜索。只有最后小步可以进入上述实测目标快速交接。

### 固定狭缝搜索锚与整组入缝确认（0.4.0.129）

0.4.0.128 的真实前台已触发实测快速交接并完成一次精调，推进到 ATR 曝光选择；随后连续新帧入缝检查未过门，没有开启 ATR 快门。证据显示暗缝检测把上张结果作为下一次搜索起点，产生逐帧漂移；同时入缝规划以最后一帧残差判定完成，可能提前接受偶然低残差。

后续导星帧统一锚定同一运行、设备、binning、标定和 Night Setup 的 LED 狭缝几何；每张帧仍必须真正检出暗缝，搜索不超过原配置且不超过一条缝宽和 1°，不能以缓存几何冒充新帧检测。入缝完成至少要求三张新帧整组通过原容差；最后一帧接近而整组未稳时，最多补四组新帧，再从最后一张真实测量重新规划。补帧使用原账本总时限，后续移锁仍逐步预留回程、累计量与次数，不合成均值图或篡改帧身份。ATR 曝光前的独立检查保持不变。

### 老化且几何异常的 PHD2 标定（运行策略）

已知标定年龄超过当前质量策略的合格年龄、同时轴不正交误差超过当前版本化策略的合格上限时，首次入缝前允许一次 PHD2 原生重标定。必须不存在未结清的锁点运动；本轮已尝试过或已处于标定后重取场的入口不得反复重标定。该决策写入 `phd2-aged-calibration-refresh-intent`。

重标定仍调用原生 `guide(recalibrate=true)` 路线，必须收到绑定到本操作的标定终态，并通过真实新标定的硬门。标定终态有独立、有限的 4 分钟等待；它不能错误复用只有十余秒的 settle 超时。之后原有逻辑停止导星、废弃标定前 G3 几何并重新进行正式 G3/PL3 取场。当前进程只对同一连接和匹配的实际标定数据采用实测标定开始时间，不改写用户持久配置中的历史时间，也不重置运动账本。

### 原生纠偏等待与解算采样恢复（0.4.0.130）

安装重启后，前端暂时没有当前 run ID 不代表磁盘没有旧运动记录。操作员明确要求独立新轮、且旧动作责任已核查时，控制器可使用 `-NewRunBoundary` 显式选择原有可见“新开一轮”命令；默认行为不变，控制器不直接改写或删除账本，不把旧失败改成成功。

### 标定降级恢复与等待回程预留（0.4.0.131）

.130 实机第二档原分辨率成功解算；精调后实际进入同锁点等待，没有把 `FRESH_G3_RESIDUAL_REQUIRED` 直接转成回程。连续新帧仍未达到原缩放后的 1.5 px 容差，按原预算返回并暂停，ATR 科学帧计数仍为零。这证明恢复分支执行，不代表科学闭环通过。

老化标定的自动恢复现在使用同一版本化质量策略的 `QualifiedMaximumOrthogonalityErrorDegrees`，不再混用另一处二元标定需求的 15° 上限；例如策略在 10° 开始降级的 11.1° 老标定，可以在无未结清运动时尝试本轮唯一一次原生重标定。标定不是成功捷径，之后仍必须重新获取 G3/PL3、评估当前标定和完成新鲜目标/狭缝测量。

同锁点完成等待还必须保留原账本的最坏回程时间：按当前位置到原锁点的距离、原回读容差与原单步保证进度计算回程次数，提前从原总截止时间中扣除。剩余时间不足以容纳一个原单步时限的等待时，立即进入已预留回程，不让只读补帧把动作收尾时限耗尽。
