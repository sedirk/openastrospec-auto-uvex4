# Known issues

This is the public, operator-oriented issue register. It distinguishes usability defects
from intentional safety gates. Machine-local identifiers, private paths, and raw
observations do not belong here.

## Automation and commissioning

| ID | Status | Issue and impact | Current handling |
|---|---|---|---|
| OBS-001 | Intentional blocker | A real run cannot start without a valid Night Setup, commissioning preset, hardware fingerprint, PHD2 evidence, and live safety/identity gates. | The UI now lists every missing item. Do not convert these gates into confirmation dialogs or bypass switches. |
| OBS-002 | Fallback implemented; transfer schema pending | The GS350/QHY-to-C11/G3 field transfer is not a rigid constant and may change after thermal flexure, pier changes, or reassembly. | The current real runner requires explicit `Skip`, records `TransferSkipped`, then uses a fresh direct G3 solve and a configured bounded local star-field search with safe return. `AutoIfValidElseSkip` remains blocked until an independent versioned transfer record exists. Never reuse the distinct G3-pixel-to-mount transform as an optical-axis offset. |
| OBS-003 | Graded active-calibration path implemented; historical repository open | PHD2 calibration, focus, slit geometry, and transforms can expire or fail after mechanical/environmental changes. A single 10° orthogonality cutoff also rejected otherwise usable 11.7° evidence without considering settle, residual, identity or age. Production currently receives one active PHD2 calibration, not a historical candidate set. | Use the versioned [PHD2 calibration quality grades](phd2-calibration-quality-grades.md) to grade the single active calibration with exact profile/equipment/topology/pier, age, direction/rates/symmetry, operation-bound settle and fresh residual. Degraded and direct-target guiding are explicit supervised-only modes; never use `Assume Orthogonal` to hide a bad calibration. |
| OBS-004 | Site integration incomplete; supervised mode implemented | Full unattended qualification depends on trustworthy roof/dome, weather, safety-monitor, optical-cover, horizon, and clock inputs. | **Operator weak supervision** permits missing adapters as explicit warnings and never claims unattended operation. The operator's statement that the roof is open is not a reusable software safety attestation. |
| OBS-005 | Known observing limitation | Thin/high cloud can reduce detected stars without obvious saturation and invalidate focus/solve fits. | QHY/G3 gates now reject noise peaks and preserve raw frames. The failure card points to star count, FWHM, SNR, background, saturation, and the relevant preview. |
| OBS-006 | Superseded in the production route by ADR-0008 | A normal QHY solve after catalogue slew can be thousands of arcseconds from the target. The former QHY route split that error into 600 arcsec segments and could exhaust its return-reserved budget before reaching the target. | New runs retain QHY WCS as a no-motion witness, then use fresh G3 WCS, a durable N.I.N.A. large-move envelope and fresh post-move G3 verification. The old schema-1 QHY envelope remains readable for historical evidence/recovery but no longer blocks startup. Fine slit-placement limits remain unchanged. |
| OBS-007 | Legacy-route recovery limitation, avoided by production | The retained QHY-motion implementation keeps pending return state in the running N.I.N.A. process, so a process loss after a legacy QHY move cannot prove a return. | ADR-0008 does not select QHY motion for new runs. G3 acquisition and slit-placement movement use durable cross-process ledgers. If an old QHY-motion run is interrupted, reconcile manually and start a new run; never infer its origin. |
| OBS-008 | PHD2-native mechanism passed on sky; one-click runner replay pending | In a field dominated by an ultra-bright target, PHD2 auto-selection can lock onto a compact-looking halo island instead of an independent star. PHD2 multi-star circles and a successful settle do not establish astronomical identity. An earlier coordinator-ranked replacement worked on Deneb but duplicated PHD2's mature selection function. | Production asks PHD2 to perform its native full-frame selection and validates that exact returned point against fresh G3 morphology, SNR, bright-target halo, edge and dark-slit guards; rejection never substitutes a coordinator-ranked star. On 2026-08-24 PHD2 natively selected `(835.41,496.08)`, completed a fresh calibration, and later natively recovered an off-slit guide at `(1108.47,170.01)` without coordinator ranking. This proves the owner function, but the complete installed runner still needs a no-intervention replay before an unattended claim. See the [2026-08-24 real-night closeout](commissioning-night-2026-08-24.md). |
| OBS-009 | Open science blocker; false boolean gate corrected | N.I.N.A.'s ATR585M Advanced API can simultaneously report actual temperature `0 °C`, target `-10 °C`, a different set-point field, and non-zero cooler power. Its `AtTargetTemp` value is also derived from strict `Temperature == TemperatureSetPoint`, so ordinary 0.1°C quantization can flip it false. A successful image download or that boolean alone therefore does not prove science-temperature readiness. | Classify frames with incoherent telemetry as technical evidence only. Cooling readiness requires coherent actual temperature, actual set point, `CoolerOn` and cooler-power/trend history for the exact N.I.N.A.-owned camera, with numeric tolerance and consecutive samples; `AtTargetTemp` is audit-only. The ATR585M manual describes PID direct-to-target control and does not mandate a ramp. Default closeout confirms idle, turns TEC off, disconnects through N.I.N.A. and confirms cooler off; a warm/cool ramp is permitted only as an explicit commissioned device policy. |
| OBS-010 | Real manual path passed; production handoff incomplete | Mirfak proved the desired bright-target behavior: the target may disappear normally after reaching the physical slit, after which PHD2 can natively acquire an off-slit star and WCS can independently prove the catalog target remains on the dark aperture. The current `AutoPreferDirectTargetThenOffSlit` source falls back during initial direct-selection failure, but does not yet perform a durable in-flight guide-epoch handoff after direct-target loss during an exact-lock stage. | Do not claim unattended direct-to-off-slit handoff from the current source. Until a durable old/new guide-epoch translation and fresh WCS-on-slit residual are implemented and tested, the production runner must pause safely on mid-stage direct-target loss. The successful same-night field-tool path and immutable Mirfak evidence define the required implementation and regression oracle. |
| OBS-011 | Fixed in source; installed live replay pending | N.I.N.A. 3.2's PlateSolve3 adapter copies PS3's raw position angle and leaves `Flipped` at its default. Passing that angle directly to `Coordinates.XYProjection` mirrored Deneb's predicted detector position and caused a wrong commissioning move. | The G3 projector now recognizes the exact PlateSolve3 solver identity, applies `normalize(360° - PositionAngle)`, and treats the commissioning preset—not PS3's default boolean—as parity authority. A regression uses the immutable 2026-08-24 Deneb sidecar. The wrong move was fully returned on sky, but the corrected source still requires installation and one fresh runner replay. |
| OBS-012 | Fixed in source; installed live replay pending | Treating the nearest point on a finite slit centreline as completion admitted a target at the left endpoint, which can increase spectrograph asymmetry and aberration relative to the slit middle. | [ADR-0006](adr/0006-runtime-slit-midpoint-as-science-destination.md) makes the fresh runtime dark-aperture midpoint the default destination for both PHD2 exact-lock and independent-transform fallback. A supervised Deneb correction achieved `1.03 px` pre-capture and `1.56 px` post-capture midpoint residual; the unified production path needs a no-intervention replay. |
| OBS-013 | Fixed in source; installed live replay pending | The ATR exposure gate used full-ROI saturated fraction and percentile. Three visibly clipped Deneb 10 s frames falsely passed because their narrow trace occupied little of the 3840×2160 detector even while 23.6–42.3% of wavelength columns clipped. | `SpectralTraceQualityAnalyzer` now finds the trace inside the configured spatial aperture and gates trace-local saturation, clipped-column fraction and longest clipped run. Exposure selection starts with a shorter bright-target-capable ladder and must recapture every newly selected tier; a clipped probe can never authorize a science exposure by extrapolation alone. The immutable 2026-08-24 FITS replay and synthetic narrow-trace regressions cover the defect. |
| OBS-014 | Partly resolved on sky; multi-node mosaic remains open | The dawn HD 19445 test exposed a target field with no formal WCS and a 5 arcmin east neighbour with one 22-source/7-match PlateSolve3 result. The subsequent M76 run proved that rejecting this class merely for low source/match counts was over-conservative: formal PL3 solve + configurable two-optical-axis reach + scale/parity checks, followed by fresh WCS move response, placed the catalogue target and completed a 600 s emission-line spectrum. | Production no longer has a project-authored PL3 minimum-star/match gate. It trusts a physically plausible formal solution and keeps source/match counts as telemetry; motion limits remain separate and every large move is freshly re-solved. One bounded neighbouring-field node is implemented and sky-tested. A connected multi-node overlap graph for fields where no neighbour formally solves remains open; see [faint-target and sparse-field acquisition](design/faint-target-and-sparse-field-acquisition.md). |
| OBS-015 | Partially implemented | A freshly validated exposure tier is safe against clipping, but freezing it for an entire science block can be conservative or become unsafe as seeing, transparency and slit coupling change. The Algol 10 s frames ranged from about 23% to 46% bias-corrected full scale. | Add multi-probe upper-envelope selection and bounded rolling re-probe/adaptation. The exposure ladder is configurable and now includes 15 s; science frames remain immutable and any clipping forces backoff. For faint targets, use accumulated-stack SNR rather than a per-frame bright-target threshold. |
| OBS-016 | Software fixes complete; hardware replay pending | After one successful non-zero-gain QHY frame, a subsequent frame reported gain unavailable and Windows then lost the camera with a USB descriptor failure. The operator confirmed that the physical USB cable had fallen out. See the [2026-08-26/27 closeout](commissioning-night-2026-08-26.md). |

## Packaging and public release

| ID | Status | Issue and impact | Current handling |
|---|---|---|---|
| REL-001 | Current snapshot clean; reachable history not certified | The current tracked and non-ignored untracked source snapshot passes the strict public-release scan, but older reachable commits and refs have not been sanitized or certified for publication. | Run the strict public-release audit before every source bundle. Publish a reviewed clean snapshot or deliberately sanitize history before exposing the existing Git graph; do not claim that a clean working tree makes old commits safe. Immutable observation products remain ignored and must never be rewritten merely for source publication. |
| REL-002 | Open release blocker | Redistribution rights for vendor SDK/driver binaries are separate from OpenAstroSpec's GPL license. | Source releases must not include vendor binaries by default. Review and document each binary's redistribution terms before attaching a binary bundle. |
| REL-003 | Open release blocker | The full third-party dependency inventory and generated notices are not yet frozen for a tagged release. | `THIRD_PARTY_NOTICES.md` defines the boundary; generate and review the exact NuGet/Python/application license inventory before the first public binary release. |
| REL-004 | Known CI limitation | Hosted CI does not have N.I.N.A. 3.2 assemblies, so it cannot compile/load-test the N.I.N.A. plugin. | Hardware-independent projects and Spectral Studio run in hosted CI. The plugin requires a Windows release check on a machine with the supported N.I.N.A. version. |
| REL-005 | Open | Public installers are not code-signed and the two GitHub release bundles have not been automated. | Keep source builds reproducible first. Add signing and release packaging only after license/privacy audits pass. |

## Reporting a new issue

Include the product name, version/commit, run ID, exact quality-gate code, and sanitized
manifest/evidence references. Never attach credentials, private network URLs, raw
observations without permission, or a machine-local production configuration.
