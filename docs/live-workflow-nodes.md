# 实时流程节点：只读运行投影（Phase 1）

## 这张图做什么

“运行概览”中的实时节点图把现有生产编排器的状态、目标定位分支和证据关系放到同一视图中。它回答“本轮走到了哪里、实际用了哪个方法、因为什么停下”，不建立第二套流程，也不代替观测计划。

本阶段是 **只读投影**，不是可编辑流程图：不能拖动节点改变顺序，不能连接、删除或跳过节点，点击节点也不会执行曝光、导星、转向或回零。画布的拖动只用于平移视野。启动、暂停、恢复、取消仍使用原有按钮和同一生产命令。

界面位置与参数入口：

- **运行概览 → 实时流程节点**：看当前阶段、实际分支和原始记录；可缩放、适配全图、平移，并选择是否跟随当前执行节点。
- **观测计划 → 目标**：选择目标和目标定位策略，查看星图资料以及带先决条件的尝试顺序。这里是计划，不是执行结果。
- **高级设置**：左侧平级分类目录、右侧当前分类参数；保存操作固定在分类区域之外，不再通过多层“高级用户展开”寻找参数。

高级设置的十个分类依次为：运行与归档、后台接口、站点与模拟、解算与居中、邻场与导星、双相机配对、并行测光、鬼影辅助、亮星翼部、设备绑定。窄窗口中分类列表与参数区域分别滚动；切换分类只改变显示位置，不修改开关、设备绑定或运行配置。参数仍绑定同一份设置，原有保存命令和运行期间的修改限制不变。

## 怎样看线和节点

图中的十一段主线来自现有 `ObservationRunCoordinator.Stages`。主线的连接表示编排顺序，不表示两端已经执行或成功，也不表示每段内部不存在其他动作。例如 PHD2 入缝精调内部可以先建立导星，不能根据后面的“导星与稳定复核”节点推断此前一定没有导星。

| 关系 | 数据含义 | 不能据此推断 |
| --- | --- | --- |
| 主链实线 | 现有编排器的固定阶段顺序 | 已经走过这条线、阶段通过或可以手动跳到下一节点 |
| 阶段关联虚线 | 本轮记录把某个定位方法关联到该阶段 | 方法只能属于此阶段，或每轮都必定执行 |
| 实际切换连线 | 本轮分支记录中先后出现了不同方法 | 任意失败都允许进入下一方法，或方法之间可自由重连 |

同一个定位方法可在多个阶段被调用；图上是一个方法节点，详情保留当前窗口内属于它的多条记录。节点状态采用该方法的最新记录，并不是每次调用都单独画一份。重复往返可能合并成同一条可见连线，应在“时间与日志”中看真实顺序。

六个目标定位方法的适用条件见[目标定位策略](target-acquisition-strategy.md)。它们是带先决条件的候选方法，不是无条件错误回退列表。特别是 SEP 短帧已经给出目标身份或位置冲突时，不能改用目录几何覆盖冲突；鬼影和亮星翼部仍需要各自既有的标定、独立身份和显式配置。

点击节点可看四类只读详情：

1. **原因**：状态说明、原始代码、使用条件、质量门记录和阶段完成来源。
2. **指标**：实际记录的质量数值；没有记录时明确说明，不补默认零值。
3. **时间与日志**：当前保留窗口中的相关事件及原始消息。
4. **证据**：与当前运行和节点关联的记录路径、类型与说明。展示路径不等于已重新打开文件、验证文件存在或重新验收科学结果。

## 状态的准确含义

| 显示 | 意义 |
| --- | --- |
| 未记录执行 | 当前证据窗口没有该节点的执行记录；不是已跳过、不可用或失败 |
| 已选择，结果未记录 | 已经选择该定位方法，但没有该方法的终态证明 |
| 转入后备方法 | 记录到一次兼容条件下的后备尝试；不是尝试成功 |
| 正在执行 | 编排器仍在执行当前阶段 |
| 已通过 | 主阶段有完成事件或编排器完成计数；分支则必须有本轮明确的分支通过记录 |
| 已通过 · 有警告 | 阶段完成，但保留质量警告；不能把警告隐藏为完全正常 |
| 未通过 | 当前质量门或分支明确未通过；详情给出原始原因 |
| 明确跳过 | 必须有明确的跳过记录；不能由“没有记录”推断 |
| 正在暂停 / 正在取消 | 请求已发出，但尚未得到暂停或取消终态 |
| 已暂停 / 已取消 | 编排器已进入对应状态；不等于已关顶、盖板关闭、回零或断电 |
| 执行记录未闭合 | 曾记录尝试，但当前记录没有它的完成结果；不补造成功，也不直接认定设备故障 |
| 故障停止 | 编排器报告故障终态；需查看实际故障与设备读回 |

中途一次通过的质量门不能使尚在运行的阶段变成绿色。完成事件离开有限事件窗口后，编排器的阶段完成计数仍可证明主阶段完成，详情会说明来源；分支没有这样的完成计数，不能因为后续阶段已经完成而补成“分支通过”。

**分支通过不等于精确入缝；阶段通过不等于整轮成功。** 科学成功仍需同一运行的 `Completed`、最终收尾与归档，以及实际接受科学帧和证据。模拟运行的完成也不能用来宣称真实曝光或天空验收成功；应核对本轮锁定的运行来源与模式，不能拿后来切换的界面模式选择替旧运行命名。

## 同一运行、同一数据源

数据链是现有生产运行产生 `ObservationDashboardSnapshot`，再由 `ObservationWorkflowProjection` 生成只读节点与关系。可见界面和 LLM 桥的 `Workflow` 字段使用该投影，不另行启动 runner，也不自行推算设备应当移动多少。

运行 ID 是证据边界：

- 图的目标优先来自与 `ObservationRunId` 匹配的本轮锁定计划；当前可编辑目标草稿不能替换仍显示的旧运行目标。
- 分支记录必须明确绑定同一个运行 ID；其他目标、旧运行及未绑定分支不能充当本轮分支成功记录。
- 阶段证据由同运行的显式阶段标记或本轮协调器事件关联。没有关联依据时宁可不显示，不根据文件名猜测归属。
- 新运行清除旧运行的选中节点与证据上下文；目标草稿改变但尚未启动时，不能假装旧运行已经变成新目标。
- 完整归档路径也必须匹配本轮运行 ID；新运行初始化时不能把新路径贴到尚在显示的旧运行节点上。

方法和策略使用独立的最多 4096 条记录窗口，不会被科学帧使用的普通 200 条证据窗口挤掉。超过上限后保留较新记录，并提示查看完整运行归档。主阶段证据和协调器事件仍有各自的有限窗口，因此图中详情不是整夜日志全集。

Dockable 启动与原生高级序列遵循同一生产路径。LLM 后台的 `show-workflow` 只导航到可见图；启动、恢复和取消仍调用绑定到可见按钮的同一 `ICommand`。节点投影不会放宽真实会话授权、目标身份、运动预算或唯一设备拥有者规则。接口约定见[大模型前端闭环接口](model-frontend-closed-loop.md)及 [ADR-0009](adr/0009-single-production-observation-route.md)。
