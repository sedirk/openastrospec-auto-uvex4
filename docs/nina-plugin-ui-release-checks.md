# N.I.N.A. 插件 UI 发布检查

本规则适用于每一次 N.I.N.A. 插件 XAML、Dockable ViewModel 或打包产物变更。
DLL 能被插件加载器读取不等于界面模板能安全实例化；发布前必须完成以下全部检查：

## 0. 先证明前端使用同一条生产观测路径

本节也适用于“只改后端 runner、没有改 XAML”的自动观测变更。完整决定见
[ADR-0009](adr/0009-single-production-observation-route.md)。发布检查必须先证明：

1. Dockable 的启动命令和 Advanced Sequencer 的目标容器都从同一设置状态捕获不可变
   `RealRunConfiguration`，使用 `ObservationPlanFactory` 生成 canonical plan，通过
   `RealObservationStageRunnerFactory` 创建 `RealObservationStageRunner`，最后由
   `ObservationCoordinatorHost` 执行；不得存在 UI 命令专属的阶段跳过、超时、恢复或清理。
2. 本次引用的任何成功 field harness 都附带 route-parity 矩阵。矩阵中的可复用行为已经
   移入共享生产组件，而不是复制到 XAML code-behind、Dockable、SequenceItem 或另一个脚本。
3. replay/simulator 测试从两个前端入口开始，断言相同配置哈希、相同 canonical stages、
   相同关键分支和相同终态；只直接 new 某个 helper/runner 的测试不能替代入口测试。
4. 实机行为改变时，安装后的最终天空验收必须从一个正式前端入口单次启动并运行到
   `FinalizeObservation`。后端工具成功但前端尚未重放时，版本说明必须明确写“待前端实机
   验收”，不得写“一键自动流程通过”。
5. manifest/发布证据保存入口类型、构建版本、配置哈希和 `NoManualOrModelCorrectionAfterSingleStart`
   等干预边界。不同入口只允许展示和 N.I.N.A. 生命周期差异，不允许科学或运动语义差异。

以下 UI 检查在上述生产路径一致性门通过后执行：

1. 运行 `scripts/build.ps1`。`XamlBindingSafetyTests` 必须通过；任何位于
   `IsReadOnly=True` `TextBox` 中的 Binding 都必须显式使用 `Mode=OneWay`
   或 `Mode=OneTime`，不得依赖 `TextBox.Text` 默认的 TwoWay 模式。自动观测
   主界面的“运行概览”和“观测计划”不得用外层 `ScrollViewer` 包裹整个工作区；新增常用状态或
   目标字段时应新增/重组页签或使用紧凑分栏，不得把常用页面重新堆成长滚动表单。
   观测计划的每个子页必须有独立的按需垂直滚动兜底：固定运行条和子页标签不随内容滚动，
   小高度、窄窗口和显示缩放后底部字段与保存按钮仍须可达。不能把“不做长表单”解释成
   “禁止溢出滚动”，也不能仅凭 `IsVisible` 判断未被裁切；测试必须验证实际视口边界、
   滚轮产生位移、滚到底部后控件进入视口，并检查滚动前/后截图。
   “运行概览”不得以 `Height="*"` 把 PHD2、鬼影或其他说明卡拉满剩余高度；只读实时节点图属于
   运行可视化，可占据剩余内容区域，此规则不限制图的自适应高度。首页说明卡只显示
   等级/模式、是否可用和下一操作，policy SHA、commissioning route、缩放、完整适用性
   与权限契约放在“高级设置”对应的平级分类中，选中分类即可直接查看，不再要求逐层展开。首页状态必须使用操作员可读的中文，
   不得直接显示 `DegradedSupervised`、`AutoIfValidElseSkip`、decision gate code 等内部枚举或证据代码。
2. 渲染 UI harness 的全部场景并人工检查截图，不得只检查编译结果。
   会共同重建 `UvexAdv.Nina.Plugin` 的插件测试与 UI harness 测试必须串行运行；
   不得让两个 `dotnet build/test` 进程同时写同一个 WPF `obj/*_wpftmp` 目录，避免
   生成的 `InitializeComponent`/命名控件文件发生竞态。
3. 安装将要交付的精确 artifact 后启动 N.I.N.A.，至少依次打开一次
   OpenAstroSpec 自动观测和 OpenAstroSpec 校准库两个面板，并在自动观测中切换到
   `实时图像 → 光谱相机 · 光谱`，确认内嵌的光谱相机单帧检查区能实例化。
   改动测光协同页时，还须分别用光谱主控、测光端配置检查对应步骤、语言和按钮状态；
   地址已保存不能显示成已连接，正在暂停/停止不能显示成已经结束。
4. 检查本次新建的 N.I.N.A. 日志。出现 `XamlParseException`、dispatcher
   未处理异常、Binding 异常或非预期进程退出时，本次发布失败；即使日志已经写出
   `Successfully loaded plugin` 也不得判为通过。
5. 保存安装 DLL/artifact SHA-256、N.I.N.A. 版本、进程 ID、日志路径与三面板
   实际打开结果。不得用离线截图替代真实 AvalonDock 模板实例化检查。
6. 用模拟或 replay 使流程各进入一次 `PausedNeedsAttention` 和 `Faulted`，确认 N.I.N.A.
   应用内提示与 Windows 系统通知都出现，并且标题、阶段、错误代码和原因可读。同一阻断的
   重复快照不得重复通知；恢复/重新验证后若同一阻断再次发生，应重新通知。人工暂停、人工
   接管、正常完成和取消不得弹出故障通知。Windows 专注助手或系统通知权限可以隐藏系统层
   提示，因此验收时应确认 Windows 允许 N.I.N.A. 通知；通知通道失败绝不能改变观测状态。

`UvexAdv.Nina.Plugin.Tests/XamlBindingSafetyTests.cs` 是上述第一条的自动门；
第三、四条是安装后的真实 smoke test，必须在每次交付前执行。

自动观测主界面的布局基线为七个一级标签：`运行概览 / 设备手控 / 观测计划 /
自动准备 / 实时图像 / 诊断与证据 / 高级设置`。固定运行控制条始终在标签外。
“诊断与证据”内部按当前问题、质量门、时间线、证据文件分层，不复制多个故障入口。
`设备手控 → 光谱仪 · 狭缝 / M2`只通过 `UvexAdv.Service` 完成 UVEX4 显式连接/断开、状态回读、四槽位切缝、狭缝灯、
M2 有界相对步进和释放 COM5；设备选择保存在当前 Profile，打开服务或面板不得自动连接，
普通断开后不得后台重连，未连接时设备动作不得隐式连接。它不得要求 Night Setup、PHD2、
QHY、WCS 或整套自动观测 commissioning，也不得绕过服务租约、限位和动作后回读。`自动准备`应提供启动前静态核对、
任务导航和本夜配置；长期台站方案、设备候选及标定包统一在高级设置维护。
可从 N.I.N.A. 保存的选择和 bindings 读取的设备值应自动填写到设备绑定分类，
人工决定项使用选择器，并在对应卡片就地标记未完成状态；
不得把完整内部校验字符串倾倒到固定页脚。常规状态、手控、计划、准备和预览不得依赖
整页滚动；计划子页在高度不足时必须允许内容区滚动，不能裁掉控件。动态失败详情可以在内容确实超高时滚动，质量/证据集合可以在列表内部滚动，
高级设置使用固定保存栏、左侧平级分类导航和右侧参数区；分类导航与每类内容分别按需滚动，
不可用嵌套 Expander、默认折叠的“高级用户”入口或横向拥挤的多行标签隐藏参数。
窄窗口仍应能滚动到全部分类和所选分类底部，切换分类不启用任何例外分支、授权或设备动作。
站点、地平线、模拟速度和 commissioning 原始字段
属于高级设置，不得重新占据计划页。

高级设置分类顺序为：`运行与归档 / 后台接口 / 站点与模拟 / 解算与居中 / 邻场与导星 /
双相机配对 / 并行测光 / 鬼影辅助 / 亮星翼部 / 设备绑定`。表单字段使用可换行布局，
不是固定列宽挤出视口；保存按钮和结果不随分类内容滚走。源码断言与 UI harness 应覆盖全部分类、
独立滚动和亮星授权复选框不受分类选择影响。本条是新的发布要求，不声明本次布局已完成构建、
安装或实机验收。

### 自动准备与高级设置的职责检查

页面职责见[观测前准备界面](observation-preparation-ui.md)。自动准备使用固定摘要及两个平级子页：
`核对与入口 / 本夜配置`；只允许各子页内容独立按需滚动，不使用外层长表单或嵌套折叠。

- 核对页只显示资料状态和导航。目标/策略/曝光预算仍在观测计划，主镜对焦及狭缝手控仍在设备手控。
- 台站方案、完整标定包和设备候选只在高级设置 → 设备绑定提供编辑入口；
  监督方式只在高级设置 → 站点与模拟编辑。直达按钮必须选中正确分类，不只是打开高级设置首页。
- 正式启动的本夜配置、下一轮期望狭缝与草稿意图区分显示。波段、标定参考与滤镜记录仅写草稿，
  不应暗示已经修改锁定配置或完成实测。监督方式会影响下一轮运行策略，不能混入草稿参数区。
- 准备摘要计入缺失目标与无效狭缝；静态检查无问题不代表已连接、现场安全、设备到位或获得真实控制授权。
- 运行/取消未结束时禁止准备参数和设备候选编辑；导航仍可用。分类选择不能改变监督模式或设备状态。
- 渲染 preparation-* 的默认、缺失、静态齐全、忙碌、中英文和窄窗前后截图。
  验证滚轮实际产生位移、滚到底后控件进入视口，固定摘要、子页标签与运行控制条不移动。
  同时重查高级分类 2 与 9 的新增区域及底部字段，保留全部旧参数的访问能力。

`设备手控 → 主镜对焦`是独立子页，使用主N.I.N.A.电调焦与PHD2导星图像，
不属于UVEX M2控制。状态、启动条件及取消按钮固定在内容滚动区之外，设置/曲线/记录分页；
`自动准备`只保留导航，不再内嵌长对焦表。无效数字和未配置范围必须在启动前解释，
观测取消未完成不能开始对焦，取消完成后旧进度不能重新显示为正在曝光。
本页以及原生对焦扩展使用实际N.I.N.A. `AutoFocusChart`。UI harness必须加载该真实控件、
仅模拟图表数据与配色；禁止用手绘曲线替代这项验证。检查`main-focus*`全部场景的按钮
状态、固定区实际边界、底部设置可达性，以及原生模板不重复显示开始按钮。
安装后的复核还须显式选择可选SEP自动对焦实现并打开原生自动对焦窗口；未获安装/设备授权
时不得越权完成此项，交付说明必须写明“源码和离线检查完成，安装后原生窗口/实机待验收”。

### 目标定位策略的专项检查

行为及生产路径对照见[目标定位策略](target-acquisition-strategy.md)，实机阶段见
[实机调试清单](commissioning.md)。目标页应分别展示选择、星图资料、条件优先级和本轮实际执行；
运行概览显示只读实时节点图和紧凑导航，不复制完整参数表。候选顺序必须写明鬼影标定、亮星翼部例外及独立身份/
焦点等先决条件，不能暗示每次失败都会无条件执行下一项。

- 检查 `target-strategy-auto`、`target-strategy-unknown`、`target-strategy-catalogue`、
  `target-strategy-fallback`、`target-strategy-busy` 和 `target-strategy-narrow-bottom` 全部场景。
- “根据星图自动”位于选择列表末尾；资料未知或与目标不符时明确警告，不继承上一目标资料，
  不自动声称目标不可见。星图导入和策略按钮在活动运行期间均禁用。
- 计划中的条件顺序不等于执行记录。实际方法、切换原因及尝试历史来自同一生产运行；
  新运行不得沿用旧成功。颜色必须配有文字，定位分支通过不等于精确入缝或整轮科学验收成功。
- 小高度/窄窗口验证自动按钮、完整优先级说明与末尾实际运行摘要进入真实视口；
  固定控制条与页签不随内容滚动。实际方法历史从固定的节点详情查看，不新增历史折叠区。

### 只读实时节点图的专项检查

数据语义见[实时流程节点](live-workflow-nodes.md)。主页的十一段主链必须来自同一生产编排器，
六种定位方法必须区分候选结构与本轮实际关联；禁止从“没记录”推断“已跳过”或从中间质量门通过推断阶段已完成。
检查 `workflow-*` 场景的未启动、执行、转入后备方法、阻断、取消中、已取消、完成、窄窗和矮窗。

- 顶部状态条、当前阶段和图来自同一快照；运行模式及目标取自本轮锁定记录，模拟/回放明确为非实拍。
- 节点选择、缩放和平移不能触发设备动作；同轮刷新保持手动选择及视口，新轮不能沿用旧目标证据。
- 原因、指标、时间与日志、证据是固定详情标签，不依赖多层展开；小窗口可滚动到最右下的真实节点。
- 主阶段完成、方法通过、精确入缝和整轮成功不能互相替代；警告仍为警告，正在取消不能显示成已经安全收口。
- 普通帧证据滚动超过 200 条后仍保留独立的方法记录；超过方法窗口上限须提示记录截断。
- 新轮初始化间隙，归档路径必须匹配当前显示运行 ID，不能将新轮 manifest 显示为旧轮完整归档。
- 高级设置十个分类逐一选中验证，窄窗必须可访问最后分类及最后字段，保存栏固定；分类切换不修改例外授权。

本阶段不含参数节点化、自由连线、模板编辑或第二套执行引擎。

`范围与连接 / 光谱提取 / M2 对焦 / 光栅锁定`。该页只配置光谱相机/UVEX4 光谱工具和对应的
两个 Advanced Sequencer 闭环项，不得暗示它控制自动观测、C11/G3 对焦或科学曝光。
ATR 提取矩形必须明确标作完整图像上的软件提取而非相机硬件 ROI；M2 与光栅使用
独立 commissioning 授权；绑定后的 ATR DeviceId 只读并优先于名称回退；未配置的
浮点字段显示为空白/“未配置”，不得向用户显示内部 `NaN` 哨兵值。

ATR 相机身份绑定和单帧提取检查并入自动观测的
`实时图像 → 光谱相机 · 光谱`。插件不得再导出只有状态、绑定和一条临时曲线的
`OpenAstroSpec 光谱`占位 Dockable。自动观测 Dockable 内的 `设备手控`是完整的 UVEX4
观测前准备任务，复用 `UvexAdv.Service` 的单一 COM5 所有权；它不形成第二套串口或采集
流程。普通断开保持 `Disconnected`；释放端口给原厂软件必须显式进入服务维护模式，
两种状态都不得后台自动重连。恢复时必须由操作员点击连接并重新读取可信位置。

光谱页以全宽自动预览为主，手动单帧检查默认折叠；自动流程占用相机时，手动检查区
应收起并禁止发起采集。相机连接文案取同一所有者的当前缓存状态，不得永久保留启动时
的“未连接”。黑白点和伽马位于可展开的显示调节行，不得逐控件换行挤压图像。
“谱带”适配只在存在有效实测谱线位置时建议显示范围，可关闭回到全幅；不得裁写 FITS、
改动提取数据或将旧位置当作新证据。即时 1D 诊断曲线独立于图像拉伸和缩放。
检查 `atr-live`、`atr-levels`、`atr-narrow`、`atr-manual` 场景时须覆盖调节展开、手动工具
展开后的重新居中、完整图像恢复、中文/英文标题以及自动占用状态。

该检查不能由“我没有改 XAML”口头豁免：ViewModel 属性可写性、DataTemplate、资源字典
和打包内容的变化同样可能只在真实 Dockable 首次实例化时失败。每次插件交付都必须执行。
