# OpenAstroSpec Auto — UVEX4 自动观测夜 SOP

**适用范围：** C11 + CCDT67、UVEX 4i、ATR585M、G3M2210M、GS350/QHYminiCam8M 的采集侧自动化  
**执行入口：** N.I.N.A. 的 `OpenAstroSpec 自动观测` 面板或高级序列中的 `OpenAstroSpec · UVEX4 目标观测`  
**自动化原则：** 健康阶段自动推进，不设置逐步人工确认；失败或不确定的质量门自动进入 `PausedNeedsAttention`  
**当前限制：** 尚无可信的 N.I.N.A. Dome/Roof 和 Safety Monitor 实时输入，因此当前只能做有人监督的 commissioning 与有界闭环测试，不能称为正式无人值守运行

本 SOP 是日常操作说明。架构和安全语义以[冻结的自动化设计基线](design/observatory-automation-baseline.md)、[ADR-0001：单设备单一所有者](adr/0001-single-owner-device-orchestration.md)、[ADR-0002：自动推进与人工暂停](adr/0002-automatic-progression-with-operator-pause.md)、[ADR-0003：实测狭缝照明与三个独立焦点域](adr/0003-slit-illumination-and-focus-domains.md)和[ADR-0004：可选、版本化的广域到狭缝场转换](adr/0004-optional-versioned-wide-to-slit-field-transfer.md)为准；实机动作还必须满足[实机调试清单](commissioning.md)。如本文与这些记录冲突，以冻结记录和后续 ADR 为准。

## 1. 操作模型

点击“开始真实自动观测”表示操作员已经授权软件执行本次计划中全部已锁定、受限且可审计的动作。质量门通过后，流程立即进入下一阶段，不再弹出“是否继续”之类的确认框。

自动推进不表示忽略风险：

- 每次新的移动、曝光或长时间子任务开始前都经过检查点。
- 设备身份、Night Setup、屋顶/天气/安全能力、地平线、解算可信度、目标入缝、PHD2 稳定度、相机状态和数据质量分别设门。
- 自动恢复受单步位移、累计位移、重试次数和总耗时限制；达到上限即暂停，不继续猜测。
- 质量门失败或无法判断时进入 `PausedNeedsAttention`，保留图像、指标和原因，并停止发起新的移动与曝光。
- 操作员始终可以使用“暂停”“恢复”“取消”和“人工接管”。UVEX 急停独立于普通控制租约。

软件不会自动打开或关闭屋顶，也不会根据光谱相机画面、导星画面或监控视频猜测屋顶与天气安全。

## 2. 设备所有权

同一台实体设备在一个观测周期内只能由一个长驻进程打开。三台不同相机可以同时工作。

| 实体设备 | 唯一所有者 | 正常职责 | 禁止事项 |
|---|---|---|---|
| UVEX4 / COM5 | `UvexAdv.Service` | 狭缝、光栅、M2、状态、租约、运动边界和急停 | N.I.N.A. 插件、旧 Manager 或脚本不得同时打开 COM5；服务不得扫描其他串口 |
| ATR585M | N.I.N.A. | 探测曝光、科学光谱曝光和原始 FITS | 插件不得直接加载 ToupTek SDK；QHY/PHD2 不得打开它 |
| G3M2210M | PHD2 | 狭缝全视场、导星星选择和导星修正 | 插件不得第二次打开 G3；PHD2 不得改去占用 QHY |
| QHYminiCam8M | `UvexAdv.Qhy.Service` | GS350 广域取景、粗解析和同时测光 | N.I.N.A. 与 PHD2 不得把它作为临时相机打开 |
| 赤道仪 | N.I.N.A. telescope mediator | 指向、受限修正、停驻状态和序列协调 | 外部脚本不得与自动流程并行发运动命令 |
| C11 主镜焦点 | N.I.N.A. 的 Gemini/Star Focuser Pro ASCOM（COM8） | 以 G3 星点清晰度对 C11 主焦面做有界调焦 | 不得用 GS350 的 ToupTek AAF 或 UVEX M2 代替 |
| GS350 粗解析镜焦点 | 版本化的宽场焦点所有者；当前物理执行器为 ToupTek AAF | 以 QHY 星点清晰度校验 GS350 焦点 | 不得临时切换 N.I.N.A. Profile 抢占 ATR/C11 状态；身份不明时保持手工锁定 |
| UVEX 内部光谱焦点 | `UvexAdv.Service` / COM5 的 M2 | 以 ATR 谱线 FWHM 优化谱仪内部焦点 | 不得用它修复 G3 或 QHY 星像 |

“人工接管”只停止自动协调并把有关作业转为可人工处理的状态，不改变上述单一所有者。接管后仍应通过 N.I.N.A.、PHD2、UVEX Manager 或 QHY 服务各自的正规入口操作，不能另开一个驱动实例。

## 3. 观测夜开始前

### 3.1 人工完成的物理准备

1. 根据目标亮度、所需波段和分辨率选择当夜光学配置。
2. 确认 UVEX 狭缝轮机械声明：1 = 300 µm、2 = 15 µm、3 = 25 µm、4 = 35 µm；机械序号还必须由 schema 4 preset 中四个独立 LED 宽度指纹和本轮 fresh OFF/ON/OFF 结果作光学复核。任一不唯一或错位结果都先停，不自动重排标签。详见[狭缝轮光学身份复核](slit-wheel-optical-identity.md)。
3. 设定光栅位置、UVEX 内部 M2 焦点和主镜焦点。C11 + CCDT67 的真实焦距与倍率必须使用实测值，不能从产品名推断。
4. 分别验证三个焦点域，不能把一个历史步数套给另一条光路：
   - 用 G3 星点的 HFD/FWHM、椭率和全场梯度验证 C11 主镜 Gemini 焦点；本机由 `ASCOM.StarFocuserPro.Focuser` / COM8 呈现。
   - 用 QHY 星点和解算质量验证 GS350 的 ToupTek AAF 焦点；当前自动所有权尚未完整验收时只记录手工锁定值，不在观测中临时切换 N.I.N.A. Profile。
   - 用 ATR 校准谱线的 FWHM 验证 UVEX M2；M2 位于狭缝之后，不能改善 G3 狭缝场星像。
5. 使用白天天光或夜间亮星完成上述初始对焦。正常情况下同一 Night Setup 内不再悄悄改变狭缝、光栅、三个焦点轴或相机安装姿态。
6. 人工打开屋顶并现场确认无机械干涉。当前系统不会开顶，也不会在取消后自动关顶。
7. 确认电缆、相机冷却、赤道仪、USB 和网络状态正常，旧 `DRIVER.UVEX4` 未持有 COM5。

任何狭缝、光栅、M2、相机 ROI/binning/readout 或色散方向的主动改变，都意味着旧校准上下文失效。应结束当前运行，创建新的 Night Setup ID，并重新获取相容的标定数据。

### 3.2 锁定 Night Setup

第一颗目标开始前，创建不可变的 Night Setup 记录，至少包括：

- 唯一的 `NightSetupId` 和 UTC 锁定时间；
- 狭缝编号与宽度、光栅步数及名义中心波长、M2 步数；
- C11/Gemini、GS350/ToupTek AAF 和 UVEX M2 三个互不替代的焦点角色，分别记录 owner、ProgID/物理绑定、位置、质量指标、置信度和最后验证时间；
- ATR585M 稳定 DeviceId、gain、offset、温度、binning、ROI 和 readout mode；
- G3 稳定身份和 PHD2 Profile 名称；
- QHY 稳定身份、gain、offset、温度、binning、ROI 和 readout mode；
- 独立的 `QhyCoarseCenteringLimits` schema 版本、单步/累计修正、动作次数、耗时和安全回原点策略；这套广域粗门不得与 G3/狭缝精修门共用；
- `WideToSlitTransferMode`：默认 `AutoIfValidElseSkip`，也可显式选 `Skip` 或 `RequireValid`；所选 QHY→G3 转换记录 ID/哈希、安装纪元、适用 pier side/姿态/温度/时间范围、预测不确定度门和最大预置移动；
- G3 直接解算失败时的曝光/检测档位及本地搜索图样、单步、半径、累计位移、次数、耗时和安全返回策略；
- 色散方向和预期波长上下限；
- 波长标定策略及参考天体；
- 40° 围墙基线、启动/继续裕量和可用时的方位角地平线轮廓；
- 屋顶、天气和 Safety Monitor 的真实能力状态；
- 长波截止滤镜状态和二级光谱污染风险标记。

ATR585M 的当前 commissioned 常规设置为 gain 100、offset 256、1×1、High Conversion Gain、−10 °C。使用其他设置时必须建立另一套版本化设备预设及相容的 bias/dark/flat，不能只在界面中临时改数值。

Night Setup 与 commissioning preset 的生成、SHA-256 校验和 PHD2 注册表证据导出按[commissioning evidence 工具说明](commissioning-evidence-tool.md)执行。生成 `.bindings.json` 后，在 `OpenAstroSpec 自动观测` 面板点击“导入标定 .bindings.json”。导入只填入有证据约束的绑定，不会自行勾选真实模式或把未测参数伪装成已调试值。

### 3.3 建立观测队列

推荐的同一设置观测块为：

1. `WavelengthReferenceBefore`：亮校准星或紧致发射线天体；
2. `LedFlat`：同一狭缝、光栅、M2、相机设置的 LED 平场；
3. `ScienceTarget`：科学目标；
4. `WavelengthReferenceAfter`：同设置的后置波长参考。

可根据可见性排列多个科学目标，但每个队列项目必须引用同一个锁定的 Night Setup ID。若中途改变狭缝、光栅或对焦，则关闭当前标定块并以新 Setup ID 建立另一组“参考—平场—科学—参考”。

校准数据的含义必须区分：

- 紧致行星状星云或外部谱灯通常比宽吸收线恒星更适合精确波长锚定；亮星只能在质量门明确报告精度限制时作为较低精度参考。
- LED 平场可用于像素响应、尘埃和狭缝照明结构，但不能单独得到大气与仪器响应曲线。
- 相对响应需要合适的分光光度标准星，并尽量匹配设置和大气质量；普通亮校准星不自动等于分光光度标准星。
- 没有长波截止滤镜时，约 6800 Å 只是尚未实测的二级蓝光污染风险起点。数据应保留并带风险标记，不能静默裁掉，也不能把该红端当成严格测量结果。

## 4. 启动前检查

在 `OpenAstroSpec 自动观测` 面板完成以下检查。这里是一次性的观测计划准备，不是每阶段确认门。

1. N.I.N.A. 当前 Profile 正确，ATR585M 和赤道仪的稳定身份与锁定记录一致。
2. `UvexAdv.Service`、`UvexAdv.Qhy.Service` 和 PHD2 使用预定配置；没有第二个程序占用任一实体设备。
3. UVEX 实际狭缝、光栅和 M2 位置与 Night Setup 一致；不可信或未知的位置不允许自动运动。
4. ATR585M 已达到目标温度容差，gain/offset/binning/ROI/readout 与 Night Setup 一致。
5. PHD2 Profile、G3 身份和注册表证据哈希一致；commissioning preset 未过期。
6. 目标名称、目录 ID、RA/Dec、计划持续时间和观测地点正确。目标可手工填写，也可点击“从构图助手当前构图导入”或“从第三方星图当前选择导入”生成一次性 J2000 快照。构图助手默认取本次构图矩形初始中心，可显式改用当前构图中心；多面板会拒绝而不是静默取第一块。第三方星图必须先明确选中命名目标。导入不会改变 Night Setup、commissioning、持续时间或安全设置，也不会回写已经创建的高级序列容器；入缝前仍须复核坐标。
7. 地平线基线、启动裕量和继续裕量来自锁定预设。若仍使用默认 40° 基线、5° 启动裕量和 2° 继续裕量，则开始时应高于约 45°，运行期间不得降到约 42°以下。
8. 软件必须预测目标在粗解析、入缝、导星、全部科学曝光、标定、恢复和可能的子午线翻转期间都可见；“当前高度刚高于 40°”本身不构成通过。
9. 在“广域→狭缝场转换”区域核对模式、有效/失效理由、记录版本、硬件 fingerprint、适用范围、预测修正和不确定度。默认模式下没有有效记录会明确显示“本次跳过，转 G3 直接解算”，不会把历史数值或代码默认值当作当前光轴差；需要绝对禁止中间移动时显式选择 `Skip`。
10. 检查“真实模式、不可变证据与设备身份”区域没有缺项，再点击“开始真实自动观测”。测试配置应先点击“开始全流程模拟”。

## 5. 正常自动流程

启动后，以下阶段在质量门通过时连续自动执行。操作员不需要逐项点击继续。

| 阶段 | 自动动作与通过条件 | 实时可视化/保留证据 |
|---|---|---|
| 1. 验证并锁定 Night Setup | 校验计划、文件哈希、commissioning fingerprint、设备身份、UVEX 位置、环境能力和整段地平线 | 门矩阵显示每项结论；运行清单锁定计划与哈希 |
| 2. 转到目录坐标 | 安全门通过后由 N.I.N.A. 必要时自动解除停驻，再转到目录 RA/Dec；不操作屋顶 | 赤道仪状态、动作时间线和有界计划 |
| 3. QHY 广域取景 | QHY 服务用 GS350 拍摄原始全视场并解算 | QHY 预览、原始 FITS、WCS、解算器版本与残差 |
| 4. 广域粗居中 | 比较目标坐标与 WCS，使用独立版本化的 QHY 粗门发有限次、有限幅度修正；大残差可拆成不超过单步上限的多次闭环，每步发令前重查安全/地平线并预留分步回原点的累计量与次数，每次移动后重新曝光和解算。不得放宽或复用 G3/狭缝精修门 | 粗门 schema/不可变配置哈希、每次 QHY 解算 JSON、输入 FITS SHA-256、移动意图/实发量、累计量、回程预留及返回证据 |
| 5. 可选广域→狭缝场预置移动 | `AutoIfValidElseSkip` 只在版本化 QHY→G3 记录的身份、安装纪元、pier side、姿态/温度/时间、不确定度和运动门全部通过时发一次受限预置移动；`Skip` 或默认模式下的无效记录直接进入下一阶段，不暂停、不猜值 | 模式、记录 ID/哈希、适用性判定、预测/实际移动、不确定度或明确跳过原因 |
| 6. G3 直接精解析、本地搜索、实测狭缝几何与物理身份 | 无论第 5 阶段是否移动，PHD2 都以唯一 G3 所有者取得新全帧并先直接解算；无星/解算失败时按锁定的有界小步图样逐点重拍、重解，成功后停止搜索，触顶则安全返回或暂停。随后 UVEX 服务在同一控制租约内执行短、长两组 `SLOF → SLON → SLOF`，在固定探测器坐标用 HDR 测量黑色暗孔径的两条物理边；反光脊可过曝且其 FWHM 只作诊断，旧 overlay 只作 seed。fresh 暗孔径宽度必须唯一匹配四槽位库中与机械回报/Night Setup 相同的物理狭缝，任何退出路径都关灯并验证 | 每次 G3 原始 FITS/WCS、搜索原点/步次/累计量/解算结果；短/长 OFF/ON/OFF、光电值、反光边/物理中心/宽度、过曝覆盖率、四候选残差、光学身份 gate 及哈希 |
| 7. 目标入缝 | 用目录坐标、WCS、时间连续性和形态确认目标，再用独立、有效的 G3 像素→赤道仪转换做受限闭环；完整修正大于单步上限时每次只发一个分段，随后完整重拍 G3 九帧并重新计算。每段发令前把 run/config/commissioning 哈希、实报起点、命令和失败回程预算原子持久化 | 目标/狭缝残差、转换版本、每段 move intent、实报命令残差、fresh G3、返回或通过结果、累计量/次数、不可变叠加图及 JSON |
| 8. 启动导星 | 排除狭缝及保护区，选择未饱和、非混合、非边缘、形态稳定的星；按 [PHD2 校准质量分级](phd2-calibration-quality-grades.md) 评估 PHD2 当前暴露的单个 active calibration，并取得本轮真实 settle 与 fresh 入缝残差。正交误差只是多维项，超过 Qualified 10°但未超过 Degraded 上限时只能显式进入有人监督降级，不能静默成为无人值守科学权威；历史候选库尚未接入生产路径 | 独立导星星叠加、策略 ID、grade/全部理由、Profile/设备/topology/pier、方向/速率/对称性、同 epoch settle、fresh residual 与动作缩放 |
| 9. 启动 QHY 测光 | 同一 QHY 服务和相机从 acquisition 转为固定设置的 time-series photometry，不断开设备 | 曝光、WCS、FWHM、椭率、背景、饱和、透明度及质量旗标 |
| 10. ATR 曝光选择 | N.I.N.A. 在光谱 ROI 上按离散曝光档拍探测帧，根据扣偏置高分位、饱和比例、每分辨元 SNR、天光/目标对比和裁剪风险选择档位 | ATR 2D ROI、即时 1D 曲线、探测帧和选档原因 |
| 11. 科学曝光 | G3 导星、ATR 光谱和 QHY 测光并行；每个新 ATR 曝光前重查导星、环境、地平线、UVEX 和目标入缝代理 | 三路预览、已尝试/保留/通过帧数和质量事件 |
| 12. 收尾 | 停止并核验 QHY 作业终态，核对 PHD2/ATR 终态，完成运行清单 | 最终状态、计数、警告、降级与证据索引 |

QHY 在粗解析期间取得的帧标记为 `ACQUISITION`，不会混入科学测光。进入科学块后，它仍由同一个 QHY 服务持有，用相同 observation run ID 和 UTC 时间与 ATR 光谱对应。

第 5 阶段只是提高“一次进入 G3 视场”概率的优化，不是正常流程的前提。两镜当前光轴差不得出现在代码常量、机器无关默认配置或未经来源说明的 UI seed 中。拆装、重新同轴、相机旋转、安装纪元改变、热/姿态范围不符、过期、翻转后 pier side 不符或新 G3 解算残差超限时，该记录立即失效；默认行为是显式跳过并执行“QHY 粗解析/居中 → G3 直接精解析 → 必要时有界小步搜索 → 识别目标后闭环入缝”。

界面中的 QHY→G3 记录编辑必须生成新版本并显示来源、系数单位、样本数、残差/协方差、预测不确定度、有效期、安装纪元、适用 pier side/天区/温度范围和运动上限。成功的 QHY/G3 解算对可产生带原始哈希的新候选样本或候选版本，但不得原地改写当前运行引用的记录。这里的两镜预置模型与第 7 阶段的“G3 像素→赤道仪”微调矩阵是两份独立证据，不能共用字段或互相顶替。

在面板中可以同时查看：

- GS350/QHY 广域取景与测光画面；
- PHD2/G3 狭缝视场，包含目标、狭缝、预测点、质心和导星星叠加；
- ATR 的 2D 光谱 ROI 与即时 1D 提取；
- 当前阶段、下一阶段、进度、质量门矩阵和运行时间线。

点击任一预览下的放大按钮可打开交互窗口；使用滚轮或缩放滑块放大/缩小，拖动平移，双击恢复全图。预览用于实时判断，原始 FITS 和带哈希的证据文件才是后续科学复盘依据。

## 6. 人工控制

### 暂停

“暂停”是协作式暂停：软件立刻记录请求，不再开始新的有界移动或曝光；已经开始的动作按其声明的完成、取消和保留策略结束。界面可能短暂显示“请求暂停（等待有界动作结束）”，随后进入“已暂停”。

暂停不是急停，也不代表赤道仪已经停驻、屋顶已经关闭或当前曝光被强制丢弃。PHD2 自动命令通道和 QHY 作业会进入相应暂停状态，所有现有数据继续保留。

### 恢复

“恢复”不会从旧结论盲目继续。系统先重新验证可能过期的设备身份、Night Setup、环境、地平线、导星、入缝和服务状态；全部通过才发起下一动作。原失败原因未消除时会再次进入 `PausedNeedsAttention`。

若 N.I.N.A. 在目标入缝分段的发令、等待或 fresh G3 验收之间暂停、异常或退出，运行目录下带 canonical payload SHA-256 的 schema 3 durable pending envelope 优先于内存状态。每轮受限精调使用不可变 `BudgetLineageId`；恢复和新 run 开始前必须扫描全部旧 run 目录，并用各 run 的不可变 `manifest.json` 复核 run ID、设备/配置/commissioning 哈希、目标、站点、地平线、Night Setup 和终结状态。任一不可读记录、多个未结动作、多个非终结预算 lineage、账本分叉或恢复上下文不一致，均禁止自动运动，只允许显式人工接管。只有唯一、非终结且上下文完全一致的旧 run pending/settled ledger 才可被新进程收养，并必须先把同一 lineage、累计位移、动作次数和最早精调起始时间原子交接到当前 run；已终结 run 的 settled lineage 只作为关闭的历史记录，不污染新的独立观测。恢复必须先读取赤道仪实报位置：仍在本段声明包络内且安全门通过时，按同一单步/累计/次数限制返回该段实报起点并验收到位；人工接管把设备移出包络时禁止自动跨回。每个 outbound 和 return intent 都在发令前保守预扣动作次数与声明位移，最后一刻再次核对实报位置、历元和 pier side，Wait 后也必须以相同历元验收到位。已验证分段的累计量/次数仍以 settled budget ledger 保留，进程重启不得从零重新计数；不得删除 pending 文件来伪造恢复完成。fresh G3 证明像素→赤道仪转换显著恶化时，先把转换隔离状态持久化，再执行不依赖该转换的原点返回；原 preset 在新 commissioning 哈希替换前不得再次用于自动入缝。

不得通过修改阈值、关闭身份检查或替换哈希来“恢复”当前运行。标定证据改变或失效时，应取消旧运行，建立新证据和新的 observation run ID。

### 取消

“取消”阻止新的移动和曝光，通知 QHY/PHD2/ATR 执行受控清理，并把运行清单写入 `Cancelled` 终态。取消后检查终态与清理事件；屋顶不在自动清理范围内，仍由现场操作员处理。

如果 N.I.N.A. 或服务失联，应按设备所有权逐项核对实际状态，不要立刻用第二个程序打开同一相机或 COM5。

### 人工接管

“人工接管”先进入暂停检查点，然后停止协调器继续自动调度。PHD2 自动化暂停，QHY 作业进入 `TakenOver` 或已结束状态；现有导星是否继续以面板和 PHD2 实际状态为准，不得猜测。

接管后：

1. 记录接管原因；
2. 只通过各设备的唯一所有者操作；
3. 不改变原始文件；
4. 修正设备状态后，只有在全部陈旧质量门可重新通过时才尝试“恢复”；
5. 如果改变了光学配置、设备绑定或 commissioning 证据，则取消并新建运行。

紧急机械风险不等待协作式暂停：使用 UVEX Manager 的急停及赤道仪/屋顶各自的安全手段，然后保留故障现场与日志。

## 7. 失败处理

| 现象 | 自动行为 | 操作员处理 | 恢复条件 |
|---|---|---|---|
| QHY 解算失败 | 依次尝试有限的曝光/检测参数和受限方形或螺旋搜索；超限后暂停，并按策略回到起点 | 检查云、焦点、星数、目标坐标和 PlateSolve 配置 | 新解算通过，修正量仍在单步/累计/时间限制内 |
| QHY→G3 预置转换缺失或失效 | `AutoIfValidElseSkip` 记录明确跳过原因并直接拍 G3；`Skip` 无条件跳过；只有显式 `RequireValid` 才在移动前暂停。绝不退回硬编码轴差 | 检查模式、安装纪元、设备/ROI/方向 fingerprint、pier side、有效期、姿态/温度范围、残差和不确定度；也可保持跳过 | 有效新版本通过，或以 `AutoIfValidElseSkip`/`Skip` 完成直接 G3 路径 |
| G3 直接解算失败或场内无目标 | 按锁定的曝光/检测档位和受限方形/螺旋小步搜索逐点重拍、重解；达到半径/累计位移/次数/耗时/地平线任一上限即安全返回或暂停 | 检查云、G3/Gemini 对焦、饱和、ROI、星数、搜索证据和目标坐标 | 新 WCS 确认目标且剩余闭环修正在上限内；不是靠亮度猜目标 |
| 狭缝 LED 几何不可信 | 保留 OFF/ON/OFF 帧，不使用旧 overlay 冒充测量并暂停；若只见定位孔或散射斑，只把它作为轮位证据 | 检查 LED 光电值、固定曝光、探测器固定坐标合成、星残差掩膜、狭缝位和 G3 画面；必要时用暗狭缝和恒星跨缝吞吐扫描 | 连续狭缝结构、前后暗验证、RMS/置信度和相机/ROI/狭缝绑定全部通过 |
| LED 宽度与机械轮位不符或无法唯一识别 | 不自动改写序号，不入缝、不导星、不开始科学曝光；保留九帧和四候选结果 | 检查轮盘安装、标签、固件 ordinal、相机/binning/图像尺寸和四槽位 commissioning 证据；重新逐槽标定而不是按微米比例猜测 | fresh 宽度在统计门内唯一匹配机械回报与 Night Setup 同一槽位，且 calibration/证据 SHA 全部有效 |
| 狭缝 LED 无法确认关闭 | 阻止后续 G3/ATR 科学曝光并进入需处理暂停；急停路径也发 `SLOF` | 检查 UVEX 服务、COM5、租约、光电值及差分后暗帧 | 服务报告最后命令为 Off、光电值回落且后暗帧无残留照明结构 |
| G3 星点虚焦或彗形 | 不用 M2 或 GS350 AAF 代偿；阻止精确入缝/选星并暂停 | 只用 C11 Gemini/Star Focuser Pro 做有界 3/5 点焦扫；若中央改善而边缘仍异常，再查 G3 relay 间距、倾斜、SCT 准直和 CCDT67 后焦 | 中央稳健 HFD/FWHM、椭率和全场梯度通过，且焦点身份/位置有证据 |
| QHY 星点虚焦 | 不切换到 C11 焦点或 M2；粗解析质量门失败后暂停 | 检查 GS350 的 ToupTek AAF 与其物理拓扑绑定 | QHY 星点与解算质量通过，宽场焦点记录新鲜 |
| ATR 谱线过宽 | 不移动 Gemini 或 ToupTek AAF；按已标定安全范围处理 M2 | 检查狭缝、校准谱线、回差、M2 行程与 ATR 设置 | 多条未饱和谱线 FWHM 和验证帧通过 |
| 目标身份或入缝不确定 | 不再移动，不开始科学曝光，保存叠加图并暂停 | 用放大预览核对是否为目录目标、狭缝位置与残差；必要时接管 | 重新采集的证据通过，而不是口头认定 |
| PHD2 校准质量不足 | 先按版本化多维策略评估 PHD2 当前暴露的单个活动校准；`Rejected` 才禁止使用并在身份/选星/安全前提满足时受控重标定。不要把纯算法的历史候选择优接口写成已经加载了历史库。`DegradedSupervised` 或 direct-target 必须由本轮显式选择，以缩小动作、更严 residual 和不可变降级旗标继续；不得用 `Assume Orthogonal` 掩盖问题 | 分开检查 PHD2 Profile、相机/赤道仪、topology、pier side、年龄、方向/速率/双向对称、正交误差、校准过程、同 epoch settle 和 fresh residual。本站极轴维护可能约半年一次，极轴漂移常见，但极轴误差与校准正交误差不能简单等同 | 当前活动校准达到 Qualified/Excellent；或在有人监督短块中明确保持 Degraded、每段 fresh residual 通过且所有科学帧带降级标志。显著运动/翻转后重新评估 |
| 导星丢失或大幅漂移 | 阻止新的 ATR 曝光；当前曝光按策略保留并加旗标 | 检查云、选星、机构漂移和赤道仪 | 重新导星稳定，并重新确认目标在缝上 |
| QHY 测光失败 | 故障隔离，不使 N.I.N.A.、PHD2 或 COM5 服务崩溃；按显式策略暂停或记录降级 | 检查 QHY 服务健康、租约、稳定身份和存储 | 不允许静默降级；策略允许且运行清单明确记录，或新作业通过 |
| UVEX 断线、位置未知或 Setup 不符 | 阻止 UVEX 动作和依赖该状态的新科学帧 | 检查 COM5 唯一占用、服务状态和位置可信度；需要移动时遵守实机调试清单 | 实时状态与 Night Setup 重新一致且位置可信 |
| 屋顶/天气/Safety 状态缺失或不安全 | 要求该能力的配置立即失败或不确定并暂停 | 处理真实环境或恢复相应适配器；不得用相机/监控画面替代接口证明 | 连接的适配器报告通过，或仅在新建的“有人监督 commissioning”预设中明确记录能力缺失 |
| 目标接近围墙或将在块内落下 | 不开始或暂停后续动作 | 缩短计划、换更高目标或等待；不能把 40° 改小来绕过墙体 | 全部剩余最坏时长重新预测通过 |
| 运行清单写入或哈希验证失败 | 立即暂停；持久化不健康的运行不允许继续动作 | 检查磁盘、权限和证据文件是否被改动 | 取消旧运行，修复存储后以新 run ID 开始；不要覆盖旧清单 |
| 程序崩溃、服务重启或租约过期 | 不留下持续自主运动循环；新动作需要重新建立租约和门状态 | 逐设备核对物理状态及日志 | 完整重验后新建运行；不要假定崩溃前状态仍有效 |

子午线翻转或任何显著赤道仪移动后，必须重新取得 G3 证据、分别复核 QHY→G3 预置模型和 G3 像素→赤道仪转换、重新入缝并重新导星。没有匹配新 pier side 的 QHY→G3 记录时默认跳过预置移动；不能沿用翻转前的任何转换。

## 8. 数据、证据与运行清单

每个运行使用唯一 `ObservationRunId`。本机运行清单位于：

```text
%LOCALAPPDATA%\UVEX-ADV\observations\<ObservationRunId>\manifest.json
```

同目录 `evidence` 子目录保存该运行生成的解算、目标/狭缝和导星选择证据。面板会显示当前运行清单的完整路径。

运行清单采用连续 revision 和原子替换写入，至少锁定或引用：

- 完整观测计划及其 SHA-256；
- Night Setup、commissioning preset、PHD2 profile evidence、QHY 配置和硬件 fingerprint 的哈希；
- 目标名称、目录 ID、坐标、地点和地平线策略；
- 设备稳定身份以及狭缝、光栅、M2 和相机设置；
- QHY→G3 预置模式、记录版本/哈希/适用性/不确定度、使用或跳过原因，以及独立的 G3 像素→赤道仪转换版本；
- G3 本地搜索原点、图样、限制、每步运动/图像/解算、返回结果和最终位置；
- 每个质量门、指标、理由和状态转换；
- QHY 解算 FITS、解算 JSON、G3 目标/狭缝叠加、导星星证据、ATR/QHY 帧引用；
- ATR 与 QHY 的 attempted/retained/accepted 计数；
- 暂停、恢复、取消、接管、重试、降级和故障清理；
- `Completed`、`Cancelled` 或 `Faulted` 终态。

原始观测文件是不可变输入。坏帧、SDK 修复、平场/暗场处理、波长标定和后期归一化只能生成带来源的新文件，不能覆盖、重命名、移动或删除原始数据。采集侧的“accepted”只表示通过当时质量门，不替代后期科学还原和人工审查。

观测结束后至少检查：

1. 运行清单存在且终态与界面一致；
2. ATR 与 QHY 尝试数、保留数和通过数合理；
3. 首次与最终目标/狭缝证据存在；
4. PHD2 导星区间覆盖科学曝光，丢星区间已标记；
5. QHY 测光时间段可与每张 ATR 光谱按 UTC 对应；
6. 前后波长参考、LED 平场及其 Night Setup ID 一致；
7. 所有暂停、降级和人工接管都在时间线中可见。

## 9. 当前有人监督限制

当前部署没有可信、已连接的 N.I.N.A. Dome/Roof 与 Safety Monitor 状态。因此：

- 不允许把当前系统称为“正式无人值守”；
- 不允许让软件自动开顶，取消和故障后也不能假定软件会关顶；
- 监控视频、银河可见、相机星点清晰和公共天气预报都只是参考，不能替代本地屋顶状态与安全传感器；
- 现场或远程操作员必须在整个有界 commissioning 运行中保持可介入，持续关注屋顶、天气、线缆和赤道仪，并能使用暂停、取消、接管和物理急停；
- 若 commissioning preset 把 `RequireSafetyMonitor` 或 `RequireOpenDomeOrRoof` 设为 `true`，对应设备未连接时流程应进入 `PausedNeedsAttention`，不得绕过；
- 为短时有人监督测试把这些要求设为 `false`，只能在新的、限时、带哈希 commissioning preset 和 Night Setup 的 `SafetyCapability` 中明确记录“能力不可用、有人监督测试”。这不是临时 UI 开关，也不等价于安全门已经通过资格验收；
- 启动一次该测试即授权预设内的有界动作，流程内部仍不增加逐步确认。操作员通过“暂停”介入，而不是每一步点“继续”。

若天气数据来自预报服务而不是本地传感器，应在证据中标明来源。它可以用于计划参考，但不能单独支持正式无人值守的雨、湿度、风和云量联锁。

## 10. Commissioning 与正式无人值守的区别

| 项目 | 有人监督 commissioning | 正式无人值守 |
|---|---|---|
| 目的 | 测量和验证一个受限环节 | 重复执行已经资格验收的完整流程 |
| 自动推进 | 通过门后自动推进，无逐步确认 | 同样自动推进，无逐步确认 |
| 人员 | 操作员全程在线并可观察实体设备 | 正常运行不依赖人工盯守，但仍保留远程暂停/取消/接管 |
| 屋顶与 Safety Monitor | 能力缺失必须显式记录，只允许短时有界测试 | 必须有可信连接、状态语义和故障策略；不得靠 CCTV/预报替代 |
| 地平线 | 先用保守 40° 基线及大裕量，逐步测量 | 使用经验证的方位角地平线轮廓和全块预测 |
| 运动 | 单轴、单步、小范围，逐阶段从 shadow 到 closed loop | 使用已经验证的单步、累计、次数和耗时限制 |
| 目标 | 先选高空亮星和紧致发射线天体 | 只调度在已验收亮度、波段、pier side 和狭缝范围内的目标 |
| 转换/入缝 | 分开采集可选 QHY→G3 预置模型、必需的 G3 像素→赤道仪微调模型、狭缝位置和回差；同时验收完全跳过预置模型的 G3 有界搜索路径 | 默认仅在版本、安装纪元、pier side、姿态/温度/时间和不确定度均适用时使用预置移动，否则显式跳过；持续用新解算残差验证或派生新版本 |
| PHD2 | 验证 exact Profile、G3 身份、校准和 settle | 跨代表星场、姿态和翻转均已重复通过 |
| 故障恢复 | 每种恢复先单独、短时验证 | 解算失败、丢星、服务重启、超时、存储故障和翻转均有重复测试记录 |
| 证据 | 每次测试生成新的 preset/run，不把 seed 当测量值 | 每次运行仍保存完整证据和清单 |

实机资格验收顺序不能跳级：

1. 全流程 simulator；
2. 只读连接与稳定身份核对；
3. 真实图像的 shadow acquisition/analysis，不发运动命令；
4. 分别核对三个焦点轴身份，并以 QHY、G3、ATR 各自指标完成独立、受限焦点验证；
5. 在不移动赤道仪和焦点的条件下取得 G3 `OFF×3 → ON×3 → OFF×3` 狭缝照明证据，首次明确判定看到的是连续狭缝还是仅定位孔/散射斑；
6. 小范围、单步、有界人工动作；
7. 高空亮星上先验收 `Skip` 路径的“QHY 粗居中 → G3 直接解算/有界小步搜索 → 入缝”，再单独测量并比较 `AutoIfValidElseSkip` 的可选预置移动；
8. PHD2 settle、ATR 探测曝光和 QHY 测光并行；
9. 紧致发射线参考与科学目标的完整短块；
10. 多目标、多 pier side、不同狭缝和翻转后的重复验证；
11. 连接并验收屋顶、Safety Monitor 和本地天气联锁后，才评估正式无人值守。

缺失的焦距、板尺度、狭缝像素位置、QHY→G3 预置模型、G3 像素→赤道仪矩阵、回差、目标入缝容差或地平线轮廓不得从记忆、产品名或历史 seed 自动晋升为 commissioned 参数。缺失 QHY→G3 模型时默认跳过该优化，不妨碍按受限原流程获取新的 G3 解算；缺失 G3 像素→赤道仪证据则不能自动完成最终入缝。

## 11. 快速值守清单

### 开始前

- 屋顶由人确认已开，四周无干涉；当前运行明确属于有人监督或已具备正式安全联锁。
- 当夜狭缝、光栅、波段已选定；C11/Gemini、GS350/ToupTek AAF、UVEX M2 三个焦点分别验证并记录，不共用一个“焦点已完成”状态。
- 狭缝照明 LED 的关灯基线和光电阈值可读；实测几何绑定当前 G3 ROI/binning、狭缝位和安装方向，旧 overlay 仅作 seed。
- Night Setup、commissioning preset、PHD2 evidence 和 `.bindings.json` 是本次配置的新鲜、有效版本。
- “广域→狭缝场转换”模式显性可见；使用时记录版本、适用范围和不确定度通过，不使用时明确显示 `Skip`/`TransferSkipped`，没有来源不明的当前轴差。
- ATR = N.I.N.A.，G3 = PHD2，QHY = QHY 服务，COM5 = UVEX 服务；没有重复占用。
- 目标全块高度通过 40° 基线及启动/继续裕量，不只检查开始时高度。
- 标定星/紧致发射线目标、LED 平场和科学目标引用同一 Setup ID。
- 先运行 simulator；真实模式入口没有缺失或不匹配提示。

### 运行中

- 观察三路预览、门矩阵、当前/下一阶段、帧计数和时间线。
- 狭缝测量阶段观察 OFF/ON/OFF 差分、光电值和关灯验证；只见亮斑而非连续线时不强行恢复。
- 健康状态让软件自动推进，不进行逐步确认。
- 看到环境变化、错误目标、入缝异常、线缆风险或异常机构声音时按“暂停”；有立即危险时用急停。
- `PausedNeedsAttention` 时先查看证据与代码，再决定恢复、取消或接管。
- 不用第二个程序打开已经有唯一所有者的设备。

### 结束后

- 检查 `Completed/Cancelled/Faulted` 终态和清理事件。
- 核对 manifest、evidence、原始 FITS、PHD2 区间与 QHY/ATR 时间对应。
- 确认前后波长参考、LED 平场和科学帧设置相容。
- 按现场流程停驻赤道仪、关闭屋顶和处理冷却；不要假定软件已经完成这些屋顶侧动作。
- 将任何新测量制作成新的 commissioning 证据，不覆盖旧证据或原始观测。
