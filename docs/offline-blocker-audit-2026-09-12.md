# 0.4.0.177：离线阻断与恢复边界审计

## 范围与状态

本次接续 [0.4.0.176 连续性修复](phd2-spectral-continuity-2026-09-12.md)，
按用户要求只做离线分析、源码修正和回归。起点是 `main` 的 `17c9122`。
**离线审计交付时，0.4.0.177 仅为源码/构建版本；随后用户授权的安装记录见文末，
不代表已通过实机闭环。**
没有连接设备、启动曝光、下发运动、安装插件、重启 N.I.N.A./PHD2/服务，
也没有更改有效机器配置、旧运行账本或原始 FITS。

审计按三条链并行检查：PHD2 状态/输出、WCS 到精调交接、试拍/科学帧的恢复与终止。
结论不是“所有阻断都应删除”：可丢弃的派生证据允许有界重取，正常质量警告不应
假扮设备故障；身份不明、物理动作未结算、所有权不明和真正耗尽的运动预算仍不能
以重试或换阶段消除。冻结设计与设备唯一所有者不变。

## 确认并修复的问题

| 编号 | 原问题与确定反例 | 本次处理 |
| --- | --- | --- |
| B01 | 无输出候选的连续计数只在特定事件清零；“2 帧候选 → AppState 暂停/停止/失锁或 TCP 断线 → 新会话 1 帧”可被误认为同一连续 3 帧 | RPC、AppState 与 TCP 边界同样切断未锁存候选序列；真正 `Failed` 继续锁存，不因断线消失 |
| B02 | 原生输出恢复将 `Selected` 当空闲；本机保存的上游 PHD2 源码显示活动选星曝光也能返回该状态 | 全部四个重连检查点要求 `Stopped`；不能边循环采集边断开设备 |
| B03 | 设备解析器把缺少/无效的 `connected` 默认成 false，恢复流程却把这当明确释放所有权 | 重连前直接核验新鲜 JSON：相机和主导星赤道仪都必须显式为布尔 false，再核对所选设备和 Profile |
| B04 | 整段预算预检在目标锁点恰好回到原点时仍多预留一次返程，9/10 次已用、最后一次可完成的校正被误判 11/10 | 与单段/回程 planner 使用相同的零返程次数规则；累计位移的保守余量和原始上限不变 |
| B05 | 整段预算已拒绝，但未命中粗定位重建条件时仍能执行一个单独可支付的微调，之后再陷入无法完成后续的状态 | 每次新增锁点 intent 前，用当轮新测量和原账本重新预检整段；拒绝不能落入 dispatch。原地完成/明确授权的质量警告试拍先判断，无需运动时不被未使用的运动额度拦住 |
| B06 | 全传感器目标坐标与 ROI 本地狭缝几何直接混算，在非零 ROI 时制造假的跨缝/沿缝残差 | 先经现有 `ToFrameLocal` 转换，再计算沿缝和跨缝分量；覆盖两种坐标域 |
| B07 | `PHD2_SCIENCE_GUIDE_EPOCH_CHANGED` 虽在原位复核分支中，却没有自动恢复入口 | 只在试拍和科学曝光两个阶段允许一次既有恢复；先尝试同锁点复核，再查原运动余量。换纪元不会伪装成同锁点证明，其他阶段不继承此权限 |
| B08 | 原位复核的 catch-all 吞掉暂停栈重启、安全/身份门及不可变证据错误，随后继续重建 | 暂停丢弃旧栈，包括外层 physical-gate catch 内的调用；实际门失败保留原 gate；未知异常保留类型/原因并停止，不把证据失败当新增动作许可 |
| B09 | 仅缺光谱曝光档位的恢复也清除正在运行的同步测光任务句柄，后续误称没有测光任务，清理阶段也丢失该句柄 | 光谱阶段失效只清理光谱派生状态，保留测光句柄、尝试编号、健康检查/收尾入口及已累积帧计数 |
| B10 | 曝光跨越导星纪元时已生成 `GuidingStable=false`，但科学帧质量函数不检查它，最后一帧甚至可能直接完成任务 | 先保存原始帧和拒收标记，计入 retained 而不计入 accepted；有剩余次数时交给同一有界恢复，恢复后重新试拍。已授权的导星/入缝精度 warning 仍由原策略决定，不新增 2 px 硬门 |
| B11 | 科学尝试已耗尽仍可能先重建导星/做探针，再报告次数不足，显式恢复与预曝光失败也能走到这个状态 | 在阶段恢复前、自动恢复前、试拍前及拒收后检查同一科学次数上限。旧物理回程先按原规则结算；最后一个合格/警告合格帧完成目标时不误报失败 |

## 仍未通过猜值解决的边界

1. **旧精调余量与静态粗定位门限可能不匹配。**例如残差 18 px 已在 20 px 粗定位
   交接范围内，但继承后的精调余量不足；一次重新取场仍可能得到相同位置而停止。
   当前次数有界，不会无限循环或刷新预算。进一步修复需让所有粗定位成功出口共享
   一个基于剩余预算、只收紧的交接目标，并验证 WCS 实际可达性；不能只改一个出口
   或静默重置精调账本。本次未替现场猜测新的运动额度/门限。
2. **DEC Off/单向输出的诊断歧义。**本机保存的上游 PHD2 `scope.cpp` 表明，DEC
   模式可能在计算请求修正量后把实际脉冲清零。这与输出失效的部分特征相同。准确
   区分需要当前原生输出模式的可靠证据；本次没有忽略 DEC、抬高判定阈值或清除
   真实故障来掩盖它。
3. **真实恢复路径仍待验收。**新版本尚未安装；必须在另行获得设备操作授权后，
   用相同可见前台路径复测，记录原始帧、实际命令、质量警告及账本。一次普通成功
   曝光不能代替全部中断/恢复分支验收，也不能改写 .175 的失败或宣称无人值守合格。

本次不更新冻结设计、不修改科学依赖、不发布新默认观测门限，也不执行 Git 提交/
推送或任何安装操作。
