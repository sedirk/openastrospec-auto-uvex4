# 光谱项目库界面视觉验收

资料库的功能测试不能代替视觉验收。修改布局、主题、字号、共享预览控件或
弹窗后，需要同时运行真实 Tk 渲染回归并检查窗口截图。不能只检查隐藏控件
存在，就宣布深色界面、文字可读性和小窗口布局合格。

普通 `pytest -q` 默认不创建桌面窗口。真实 Tk 窗口与渲染矩阵仅在显式传入
`--run-ui-tests` 后运行；在操作员正在使用的桌面上，先安排不会打扰操作的时段。
CI 的独立 Windows runner 显式启用完整 UI 回归，不能用默认跳过结果声称视觉已验收。
直接运行 `library_visual_fixture` 同样会显示测试窗口，不属于静默检查。

## 边界与夹具

`reduction/src/uvex_reduce/library_visual_fixture.py` 创建临时、确定性的 12 张
合成 FITS，包含光谱、测光、盯缝、不同目标和人工筛片状态，以及配套日志和
SQLite 索引。窗口标题明确标记 `VISUAL TEST — synthetic data only`。

夹具不索引正式资料目录，不打开或连接设备，不启动观测，不导出或处理真实
科学数据，不修改正式筛片记录。测试结束正常关闭自己创建的窗口并清理自己的
临时数据。渲染夹具同步加载很小的合成预览，避免截图时机不确定；生产后台
工作线程、异步旧预览丢弃和选择切换另由 `test_library_ui.py` 覆盖。

## 自动渲染矩阵

在 `reduction/` 下使用现有固定环境，不升级依赖：

```powershell
.\.venv\Scripts\ruff.exe check src tests
.\.venv\Scripts\pytest.exe -q --run-ui-tests tests/test_library_visual.py tests/test_library_ui.py tests/test_library_projects_ui.py
```

| 客户区尺寸 | 显示缩放 | 主要用途 |
| --- | --- | --- |
| 1380 × 860 | 100% | 默认布局与预览空间 |
| 1100 × 720 | 100% | 最小支持窗口 |
| 1380 × 860 | 125% | 较大字号、弹窗和控件间距 |
| 1100 × 720 | 125% | 最紧凑的支持组合 |

每个组合使用独立进程和 Tcl 解释器，避免前一个 DPI 的字体缓存或 Tk 销毁
状态污染后一个组合。`--scale 1.25` 将 Tk 的 points/inch 显式设置为
`96 / 72 × 1.25`；它不修改 Windows 显示设置，也不等同于验收所有显卡、
非客户区或多显示器 DPI 行为。

以上矩阵同时检查 `--view files` 和 `--view projects`。项目页是生产默认入口，
文件页仍保留；不能只验收旧文件浏览页。项目页必须实际选中项目、加载光谱，
显示科学帧计数和完整来源路径，并分别切换到“项目文件”“后期与来源”验收
人工标记、关联文件浏览及已有工程入口。只有当前页签内的控件应被判为可见。

自动回归检查：

- 窗口已真正映射，合成 FITS 已加载到真实预览控件。
- 侧栏、浏览器、检查器、顶栏、底栏和预览均位于客户区内，有可用尺寸。
- 留片、弃片、撤销标记、星级/备注、目录与容量、选片篮和后期等必要按钮
  均存在、映射且未被裁切；不是只检查仍然可见的那部分按钮。
- 只读下拉框采用深色背景，文字对比度至少 4.5；界面显示中文标签，内部
  来源、通道、排序和角色枚举仍保持原有数据/API 契约。
- “更多筛选”“光谱后期选片篮”“星级与备注”“目录与容量”实际弹出，
  表单与按钮不裁切；容量概览、目录卡片和类型分布实际显示，技术 JSON 只在
  独立只读页签，不代替默认的人工浏览视图。长目录区域可滚动。
- 每轮弹窗检查只关闭自己新增的子窗口，不留下测试弹窗。
- 负对照确认原来的灰白只读框和越界按钮无法通过这些规则。

测试报告包含 `screenshot_review_required: true`。解析后的主题颜色、控件
几何和可见性是自动回归契约，不是屏幕像素比较，也不能证明视觉设计漂亮。

## 截图与交互检查

从 `reduction/` 启动保持打开的隔离窗口：

```powershell
.\.venv\Scripts\python.exe -m uvex_reduce.library_visual_fixture --size 1380x860 --scale 1.0 --report ..\tmp\library-visual-1380-100.json
```

项目页使用同一夹具，增加 `--view projects`；其数据依然只是合成数据，不能用
合成项目名称证明真实历史运行已被正确组织。

较小窗口和 125% 组合分别替换 `--size`、`--scale`。需要无人值守的几何报告时，
增加 `--exercise-dialogs --close-after-report`；该模式不保存截图，也不运行文件
删除、归档、后期处理或硬件动作。

操作员仍在使用上一版测试窗口时，不关闭或复用那扇窗口；可用
`--title-suffix 新版验收` 明确区分新窗口。

人工或受支持的 computer-use 截图验收至少检查：

1. 默认与最小窗口的整体画面：层级清楚，底部必要操作完整，没有密集白色
   线框、浅灰输入框或过度拥挤；预览不被无关配置占满。
2. 展开来源/通道下拉列表：弹出列表本身的背景、文字、悬停与选中颜色也清楚，
   不能只看收起的输入框。
3. 已选择与未选择状态：选中行可辨识，文件身份和通道明确；筛选掉当前项后
   不残留旧目标、旧备注、旧图像或可误操作的按钮。
4. 预览、元数据、日志标签切换：选中/未选标签可读，图像保持中性灰阶，
   图像/光谱内容不被工具栏、文件名或长状态文字遮挡。
5. 四个弹窗在 125% 下的标题、字段、按钮和关闭操作；“目录与容量”应可快速
   看见容量概览与登记目录，而不是要求操作员阅读整块机器 JSON。
6. 少量真实资料的只读回看与长目标名/文件名、零结果和多选状态；不以这一步
   授权真实删片、归档或设备操作。

截图、几何 JSON 和测试合成数据放在 `tmp/` 或其他忽略目录，不提交到 Git。
记录实际检查的尺寸、缩放、页面和剩余缺口；没有检查的真实显示器/DPI 组合
应明确注明。更新界面后，旧截图只能作对照，不能冒充本次改动后的验收结果。

### 光谱项目层追加验收

新增项目页四组合后，视觉回归为 22 项，覆盖项目和文件两个工作区。新增项目
交互测试检查项目切换时旧预览丢弃、零帧失败项目保留、明确来源状态、真实成员
过滤、精确科学帧交接以及打开已有工程不运行处理。文件是否存在与人工“不采用”
分别显示；后者必须注明该标记操作不删除、不移动、不送入回收站，释放空间 0 B。
不能据此推断文件从未经过其他清理；物理状态和最近清理回执必须独立显示。

实际截图检查了项目页 1380×860 / 100% 和 1100×720 / 125%，包括光谱预览、

`tmp/library-project-acceptance/`；正式历史资料的检查记录随该目录中的只读回放
报告保存。截图与几何检查并用，不将几何断言称作逐像素视觉比较。

正式库只读验收中，HD 18552 的历史原始光谱已在项目页显示，计数为科学帧
2 / 2、20.0 min；“定位源文件”已在 Windows 文件管理器选中对应 FITS。
没有给真实原片加人工标签。全套测试曾暴露各模块反复销毁/重建 Tk 根导致的
Windows Tcl 缓存初始化错误；现在功能测试使用 session 级唯一隐藏根，各例
只销毁自己的子窗，DPI 矩阵仍隔离为独立进程。没有用 skip 或重试掩盖失败。

项目层与来源迁移、重复项目区分标签修复后的最终完整 Python 回归为 **276 passed / 2 skipped**，
