# 目标定位策略：优先级、星图推荐与实际分支

## 用户入口

在“观测计划 → 目标”的“目标定位策略”中选择目标特征。原来的“目标在导星相机中的可观测类型”不再要求用户先猜相机是否看得见目标。页面分别显示：

1. **策略摘要**：本目标优先使用哪类定位依据。
2. **星图资料**：来源、天体类别和可用星等；没有资料时明确说明。
3. **本目标的尝试顺序**：每个候选方法及其先决条件。
4. **本轮实际执行**：当前正在执行、已切换或仍未执行的方法，以及触发原因。计划中的候选列表不是成功记录。

运行概览只保留紧凑的当前策略/实际执行摘要；详细条件放在目标页。目标页内容超高时可以滚动，标签与顶部运行控制条保持固定。后台桥读取的是同一组运行状态，不另行推断已执行分支。

### 可选策略

| 选择 | 优先依据 | 不代表什么 |
| --- | --- | --- |
| 恒星 · 优先实测星像 | 本轮正式 WCS 与同帧星像；必要时 SEP 短曝光复核 | 不保证星点圆形，也不允许选择另一颗最亮星 |
| 暗点源 / 类星体 · 目录定位 | 正式 WCS 中的计划目录坐标 | 不声称已经测到目标峰 |
| 紧致星云 / 行星状星云 · 目录定位 | 计划目录中心 | 不把星云的亮结节或邻近恒星当中心 |
| 扩展目标 · 指定坐标取样 | 用户计划的取样坐标 | 不自动寻找最亮区域，也不改变光谱验收算法 |
| 导星图中不可见 · 目录定位 | 正式 WCS、狭缝和当前导星/位置证据 | 不免除位置证明，不直接授予科学曝光 |
| **根据星图自动** | 本次导入的明确天体类别；星等作为说明 | 不凭名称猜类型，不把星等硬编码为相机可见性门限 |

“根据星图自动”保留在下拉列表最后，也可点击“使用星图自动策略”。该按钮只改变计划选择，不连接或移动设备。“从第三方星图导入”负责更新当前目标及其可得资料。运行期间目标、策略和导入入口锁定；需在旧运行结束后按新设置启动新一轮，不能热替换活动 runner。

## 条件优先级，不是错误屏蔽

恒星路线的条件顺序为：

1. **WCS + 本帧星像**：在正式解算给出的身份范围内确认唯一目标，不重新排名“最亮星”。
2. **SEP 短曝光复核**：长曝光目标区域过曝时，用既有有界短曝光取帧与主星对应逻辑复核。保留最多三帧的限制与每帧原始证据，不额外发放一组预算。
3. **正式 WCS 目录几何**：同帧正式 WCS、相机身份和赤道仪绑定已验证，目标在可用视场内，且长帧目标区域未过曝时，若没有可用的唯一局部星像，可保留该目录点的几何投影。局部多候选必须全部弃用，不应用任何候选的质心偏移；原歧义与切换原因仍保留。此状态不伪装成实测星心或精确入缝。
4. **已标定鬼影辅助**：仅在既有鬼影标定、同一目录目标的独立外部身份确认和显式开关都有效时可用，不用无关亮星或临时拟合代替标定。
5. **已标定亮星翼部**：仅在既有亮目标例外配置、同一目录目标的独立身份确认及焦点证据都有效时可用；仍需原生产流程的狭缝照明、安全关灯和位置验证。
6. **有界邻场解算**：仅限兼容的解算/视场获取失败，由共享 runner 重拍、重解并重新证明同一目录目标。它沿用本轮运动账本、次数、累计位移、耗时和回程责任。

暗点源与扩展目标从“正式 WCS 目录几何”开始，不先强迫目标满足恒星质心形态；其后仍列出上述有条件的鬼影、亮星翼部和有界邻场候选。候选出现在列表中不表示已经启用、适合该目标或必将执行；缺少标定、独立身份、焦点证据或显式配置时不能启用例外。自动策略不能补造这些权限。

所谓“切换”必须写出**从哪个方法、因为哪类证据不足、改试哪个兼容方法**。不能通过改目标类型、接受伴星、重置预算或跳过安全门来把失败改成成功。邻场重新获取也不是承认一个有歧义的星点；重新获取后仍须证明原计划目标。

这是一张带先决条件的分支图，并非“上一项失败就无条件执行下一项”的通用异常列表。尤其已经进入 SEP 短帧复核后，若短帧主星身份或位置复核失败，不能再用目录几何覆盖这项冲突；必须按该失败的原有规则暂停或执行明确兼容的恢复。

运行摘要用颜色区分处理中、已通过和阻断，保留文字结论；不能只凭绿色判断整轮成功。“尝试记录”折叠区显示同一运行中的方法与原因历史，新运行不能继承旧成功说明。

## 星图资料如何使用

星图元数据按目标名、目录 ID 和 J2000 坐标绑定，保留来源及读取时间。用户手工修改目标、导入另一个目标或元数据绑定不符时，不沿用上一颗星的类别。

- 恒星、双星、变星等：恒星优先，双星仍保留主星对应关系。
- 行星状星云：紧致扩展目标、目录中心优先。
- 类星体等暗点源：目录定位优先。
- 星系、星云、星团等：使用计划坐标取样。
- 缺失或尚未支持的普通天体类别：显示资料不足警告，暂按恒星优先，从新帧决定可用方法；不能自动推断“目标不可见”。
- 太阳系/移动天体：当前固定 J2000 路线不能替代独立星历和跟踪。只要与本目标绑定的资料明确标为不支持的移动天体，策略即拒绝这条路线；手动改成“恒星”也不能掩盖已知类别。

星等不是普适阈值：光路、曝光、增益、天光和云都会改变导星相机的实际可见性。星图分类只负责推荐优先级；新鲜原始帧、正式 WCS、设备身份、狭缝测量与导星证据继续负责实际定位和后续动作。

## 生产路径一致性

遵循 [ADR-0009](adr/0009-single-production-observation-route.md)，没有新增独立后台获取状态机：

| 环节 | 共享边界 | 验收要求 |
| --- | --- | --- |
| 星图/手工目标导入 | 同一目标草稿、绑定的元数据与前台命令 | 改目标不携带旧类型，不在运行中导入 |
| 策略决定 | `TargetAcquisitionStrategyPolicy` 与不可变运行配置 | 明确 requested/effective 类型和条件顺序 |
| Dockable / 原生高级序列 | 同一配置、计划、runner factory 和 coordinator | 入口不能私有化 fallback 或预算 |
| 实际定位与后备 | 共享 `RealObservationStageRunner`、正式 WCS/SEP/有界邻场 | 保留同一目标、预算和本轮原始证据 |
| LLM 后台 | 调用可见按钮绑定的同一 `ICommand` | 启动后不得由临时脚本选择移动方向、曝光档或身份后备 |
| 实际分支展示 | 同一生产事件与运行 ID | 新运行清除旧摘要；未执行不能显示成功 |
| 科学验收 / 收尾 | 原有光谱、温度、导星、设备与环境链 | 几何后备不直接授予科学成功或无人值守 |

后台测试入口参见 [大模型前端闭环接口](model-frontend-closed-loop.md)。仅 `UI_COMMAND_DISPATCHED`、截图中的进度条或单帧保存都不能表示完整成功；必须关联本轮 `ObservationRunId`、`Completed`、`FinalizeObservation`、接受科学帧和实际证据。
