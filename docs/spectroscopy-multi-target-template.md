# 光谱多目标高级序列模板

2026-10-09 创建，2026-10-10 更新 · 适配 N.I.N.A. 3.2 与 OpenAstroSpec Auto 0.4.0.263 或更新版本。
这是可导入的原生序列文件，不是另一套观测程序，也不是已经选好今晚目标的观测计划。

两份模板均在最后一个目标后加入“关顶与整夜收口（可选）”，默认开启普通收口。
需要测试后保持开顶时关闭该指令里的开关；设备确认停止后进入受天气保护的待机，
失败也遵守该选择。截止、晨光、Unsafe 和安全监视失联仍安全收口。
旧序列没有此指令时继续兼容原“保持开顶”选项；新指令存在时以它为准。
单次运行关顶设置不控制整夜序列。操作位置及边界见[原生序列说明](native-spectroscopy-night-sequence.md)。

## 先用哪个文件

- **第一次用，打开整份序列：**
  [OpenAstroSpec-Spectroscopy-MultiTarget.json](../config/sequences/OpenAstroSpec-Spectroscopy-MultiTarget.json)。
  在高级序列的打开/加载序列入口选这个文件；先另存当前未保存的工作。
- **已有序列，只需要拖入多目标块：**
  [OpenAstroSpec-Spectroscopy-TargetBlock.template.json](../config/sequences/OpenAstroSpec-Spectroscopy-TargetBlock.template.json)。
  将它复制到当前 N.I.N.A. Profile 设置的 **Sequencer Templates Folder / 序列模板目录**，
  在高级序列右侧“模板 → 用户模板”找到“三目标光谱块”，拖到目标区。
  保留 `.template.json` 后缀；普通 `.json` 不会作为用户模板被扫描。

**两种方式二选一，不要把同一批目标加载两次。** 整份序列是 root container，
N.I.N.A. 不把它列为右侧的块模板；这就是分别提供两种文件的原因。
这两个文件不需要 Target Scheduler、Sequencer Powerups、Ground Station 或额外插件。
不要在测光 worker 实例运行它们：这是光谱主控 N.I.N.A. 的序列。

## 打开后只改这些

默认 A、B、C 都是**模拟目标**，坐标 `0° / 0°` 是显式占位，不是推荐拍摄天区。
不要直接把占位目标切为真实运行。

展开**每张目标卡**编辑该目标，不在整夜容器里选择目标再改。名称、原生 HMS/DMS
坐标和高度图跟随目标卡；曝光、帧数、失败策略及强制校准也只属于这一目标。
整夜容器只放晨光、截止和收口等夜间设置。下面表格中的度数指 JSON 序列化单位，
不是要求在原生赤经小时输入框中填写度数。

| 每个 UVEX4 目标中的项目 | 模板值 | 你需要做的事 |
| --- | --- | --- |
| 目标名称、目录 ID、J2000 赤经/赤纬 | A/B/C 占位；目录空；坐标 0/0 | 填实际目标，逐个核对；JSON 赤经单位是度，不是小时（1 h = 15°） |
| 定位策略 | 可见恒星 / DirectStellar | 普通可见恒星可沿用；暗点源、不可见或扩展源应按实际类型改，不从名称猜 |
| 合格科学帧数 | 3 | 按目标所需总积分修改 |
| 最多科学尝试 | 6 | 保持不小于科学帧数；这是科学帧预算，不是重新定位次数 |
| 固定曝光 | 300 秒 | 可改 120、600 等；填 0 才是沿当前 Profile 的自动试拍阶梯选档 |
| 本目标失败策略 | 结束本夜并收口 | 如需继续下一目标，显式改成“质量失败且停止确认后跳过” |
| 本目标开始时强制 PHD2 校准一次 | 关闭 | 只有需要重校准的目标才打开；旧模板未写此字段也按关闭导入 |
| 本目标导星自动恢复 | 开启（.260 导入缺省值） | 弱星场等待、恢复后重选、仍失败才请求一次校准；不等于关闭安全检查 |
| 星点等待上限 | 300 秒（.260 导入缺省值） | 每目标可设 30–600 秒；不会增加原运动、回程或科学帧预算 |
| 观测时长预计 | 45 分钟 | 用于可观测性/地平线检查，按曝光、重试和准备开销估计；不是强制截断长曝的计时器 |
| 执行模式 | 模拟 | 晴夜实测前逐个检查；同一夜不能混合真实与模拟 |

不需要第三个目标就**删除整个目标块**，增加目标则复制整个 `UVEX4 目标观测`，
再修改名称、坐标与帧计划。不要复制/删除其内部单个阶段，也不要在其内部套“循环 N 次”。
按期望顺序拖动 A/B/C；可把合适的参考星放在首位或末位，但它仍是普通光谱目标，
模板不会自动执行科学定标或判断参考星是否合适。

本仓库已有模板明确保存了“结束本夜”策略，导入不会自动改为跳过；若要单目标失败后继续，
请在每张目标卡改为“质量失败且停止确认后跳过”。.260 新建空目标卡的缺省才是跳过。
星点恢复与校准次数在整个目标（含翻转）内共享；显式起始校准消耗同一校准额度。
具体恢复条件及未结运动边界见 [ADR-0024](adr/0024-bounded-adaptive-guiding-recovery.md)。

三个目标各 3 × 300 秒，对应计划合格积分共 45 分钟；实际夜间占用还包含定位、入缝、
试拍、读出、质量复核、可能的重试及翻转。合格末次试拍可按现有规则计入科学帧。
**300 秒只是这个模板的起步档，不代表所有目标都不过曝。** 固定曝光也须通过试拍和
科学质量检查；不会关闭饱和、温控、导星或真实入缝检查，也没有修改 Profile 的默认曝光阶梯。

## 模板的实际结构

```text
原生高级序列
├─ 开始：中文核对提示（只显示说明，无设备动作）
├─ 目标区
│  └─ OpenAstroSpec · 光谱整夜序列
│     ├─ 晨光停止：太阳高度 −12°；本机截止时间 05:00（无需日期）
│     ├─ 一个光谱中天翻转触发器：额外边界余量 120 秒
│     ├─ UVEX4 目标 A：3 张 × 300 秒，最多 6 次
│     ├─ UVEX4 目标 B：3 张 × 300 秒，最多 6 次
│     └─ UVEX4 目标 C：3 张 × 300 秒，最多 6 次
└─ 结束：提示核对各目标与整夜日志（不冒充收口动作或成功通知）
```

每个目标都保留同源生产编排器的十一阶段：本夜配置核验 → 目录转向 → 测光广域取场 →
广域见证/交接 → G3 取场与粗定位 → PHD2 入缝 → 导星/稳定复核 → 启动同步测光 →
ATR 试拍选档 → 科学帧及健康监测 → 目标收尾。

开场的实际设备核验/准备由首个目标的生产流程负责；下一目标仍重新核验其必要证据。
目标之间先停止并核对采集/导星，不反复关盖、关顶。最终收口由**光谱整夜容器内部**
统一执行，默认屋顶策略仍要求已标定 Park 与停止/停放确认后才关顶回读。只有按
[ADR-0021](adr/0021-station-attested-noninterfering-roof.md)验收并绑定的无干涉台站
可先确认停止、关顶，再独立完成可选有界 Home 和 Park；模板不自带此台站验收。
不能把外层“结束”注释误认为收口已经成功。普通“取消”只停止采集；需要主动收夜时
使用“结束本夜并收口”。测试保顶待机必须显式设置截止，仍服从 Unsafe、晨光和故障收口。

默认截止 `05:00`，可在整夜块改为 `00:30` 等本机时分，不必每天改日期；仍兼容带时区的
ISO-8601 绝对时刻。开始时间用前置原生“等待到时间”，本通用模板不强加一个开始钟点。
截止在整夜块启动时按中午至次日中午解析并锁定，同一观测夜已过的时间不自动顺延。
旧插件不会接受纯时间截止，须使用 .261 或更新版本。详见 [ADR-0025](adr/0025-reusable-night-clock-deadlines.md)。
晨光/普通截止在阶段和科学帧边界检查，不截掉已开始的正常长曝；安全事件另行即时停止。
模板没有“等到天黑才开始”：在白天点击运行，晨光条件可能立即结束模拟。
**只做白天离线演练**时可在所有目标仍为模拟的前提下临时关闭晨光停止并清空截止，演练后恢复。
模拟也检查站点/地平线，需选模拟时刻可见的坐标，不能用占位坐标保证任何时刻都通过。

## 同步测光、翻转和失败怎么处理

**同步测光：** 沿用光谱主控 Profile 的“同步测光”总开关，以及“高级设置 → 并行测光 /
双相机配对”的现有配置。开启后由目标内的同步测光阶段启动当前配置的拥有者；关闭后
运行纯光谱。不要再塞一组 QHY 原生曝光指令或启动第二个拥有者。
生产双实例路线是测光 worker 独占 QHY；尚在显式兼容路线的本机配置不会被模板静默迁移。
交接 worker 必须另按 [双实例说明](dual-nina-implementation.md)在空闲边界完成。

**中天翻转：** 专用触发器放在整夜块上，三个目标继承同一个；不在全局重复挂载。
翻转时机和镜筒侧检查取当前 N.I.N.A. 原生设置，模板不硬编码机器的翻转限位。
余量 120 秒不是允许越过赤道仪限位的权限。翻转后必须重新定位、测缝、入缝及导星，
只继续剩余科学帧；不是普通深空那种让 ATR 谱图直接居中的流程。
详见 [光谱中天翻转](native-spectroscopy-meridian-flip.md)。

**失败：** 默认结束本夜。选择质量失败跳过后，也只对现有明确代码白名单、采集停止已
确认且运动账本已结清的失败生效；丢星、身份不符、安全事件、写盘错误及未知异常不跳过。
不要用 N.I.N.A. 外层“忽略所有错误”、重复整个夜间块或无限重试来代替这个策略。
PHD2 校准由 PHD2 管理，模板默认不强制重新校准。按
[ADR-0023](adr/0023-explicit-per-target-phd2-calibration.md)，可在特定目标卡开启一次
强制请求；这会产生校准运动，之后仍需重新确认定位、入缝和导星，恢复/翻转不重复请求。

## 真实使用前的重要区别

这里沿用 [ADR-0019](adr/0019-native-spectroscopy-night-sequences.md)已有的整夜自动收口能力。
**仍采用“有人弱监督”的台站配置不能直接运行这个真实整夜块**，因为它不能承诺自动关顶。
真实整夜需要已验收的完整 N.I.N.A. 安全链、已配置的镜盖/屋顶和结束关盖/关顶，
默认要求 Park 姿态实际允许关顶；显式无干涉模式须满足上述 ADR-0021 的台站验收。
若采用 AIWeather 作为气象权威，还须满足
[ADR-0022](adr/0022-aiweather-site-weather-authority.md)的明确绑定和有效安全状态，
不能仅把气象适配器选“无”。不能只改一个布尔开关就声称安全链已经验收。
若暂时仍采用人工收口，继续原单目标有人模式；本次模板不新增未经验证的有人多目标执行路线。

开始区与结束区刻意不放普通的“连接所有设备 / 制冷 / Unpark / Warm / Park / 关顶”指令：
那些外层指令不会服从目标的模拟开关，也可能越过本项目的唯一拥有者和统一收口边界。
主镜对焦请在启动本夜前通过现有专用入口完成；不对 ATR 光谱图使用深空 HFR 自动对焦。

模板**不保存**站点、设备稳定 ID、Night Setup、校准包、端口、服务地址、凭据、日志、
FITS 或真实控制授权。导入时由当前 Profile 的目标原型提供本地绑定；模板覆盖的只有
公开计划字段，并清空旧目录元数据。导入后若更换 Profile 或更新绑定，应重新载入并核对，
不能把已保存序列的旧快照当成会实时更新的绑定。N.I.N.A. 另存后的个人序列可能含本机
身份和站点数据，应留本机，不要提交到仓库。

## 搜索参考与光谱适配

2026-10-09 查阅以下原始来源；参考的是组织方法，文件内容为本项目重新编写，
没有复制第三方自动开关顶脚本、通知凭据或设备数值，也没有执行下载的序列。

| 参考来源 | 借鉴的结构 | 本项目的替换 |
| --- | --- | --- |
| [N.I.N.A. 官方：从简单到高级序列](https://nighttime-imaging.eu/docs/master/site/sequencer/advanced/simpletoadvanced/) | 开始/目标/结束，顺序执行和每目标容器 | 原生三分区 + UVEX4 同源十一阶段目标 |
| [Patriot Astro 模板目录](https://patriotastro.com/nina-advanced-sequence-downloads/)及其 BASIC_STARTUP_PA / LOOPED_STARTUP_PA JSON | 整份启动序列与可重用块分开，内嵌说明，便于复制目标 | 完整 `.json` + 可拖入 `.template.json`；不照搬循环同一批目标 |
| [astroced 的 Target Scheduler 序列](https://github.com/astroced/nina-sequence-target-scheduler) | 准备、目标组、集中收尾与故障边界 | 使用已有光谱夜间容器；不引入动态调度器、外部通知和开关设备插件 |

这不是 Target Scheduler：不会自动选最佳高度目标、绕过不可观测目标等待升起、无限等待云散，
也不会自动拍暗场/平场/灯谱。需要这些能力时应单独设计，不能把深空模板直接拼进去。

回归直接读取上面的两个分发文件，使用 N.I.N.A. 的 `SequenceJsonConverter` 验证导入，
连续三次保存/重载及块克隆；检查每目标只有十一阶段、只有一个继承翻转触发器、
无旧运行状态/机器绑定、真实 Profile 下仍默认模拟，且不写回 Profile。

被测试桩禁止。测试只在内存副本中将模拟目标放到天顶并取消晨光，以避免白天/地平线干扰。
