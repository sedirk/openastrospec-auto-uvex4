# 观测流程职责与状态边界重构（0.4.0.277）

## 目的与共同入口

承接 [0.4.0.276 代码审计](2026-10-11-code-audit-and-deduplication.md)。本轮不新建
另一条观测路线，也不将旧大类简单拆成更多 partial：把阶段的决策循环及其状态写入权
交给独立 workflow，通过有限接口使用原运行会话的设备、安全、证据和持久化服务。

单次观测与高级序列仍共用 `RealRunConfiguration`、canonical plan、
`RealObservationStageRunnerFactory`、同一个 runner 和 `ObservationCoordinatorHost`。
两个入口不各自拥有一套试拍、入缝、超时或失败清理实现。本轮不改变 ADR-0009、
ADR-0031、设备 owner、序列格式、commissioning JSON 或冻结设计的含义。

## 职责与状态的归属

| 组件 | 负责的决策/状态 | 不负责什么 |
| --- | --- | --- |
| `G3AcquisitionWorkflow` | 所有重新取场入口先检查未结回程，再取新帧；根据当前证据选择接受取场、WCS 粗居中或有界邻场搜索 | 不接受光谱帧，不把入框当作入缝，不生成另一份运动预算 |
| `G3AcquisitionReturnWorkflow` | 原持久化 G3 回程状态机；返回完整路径、逐段预扣/写入、到位和稳定读回 | 不清零原时钟/累计运动，不把命令已发出当作回位成功 |
| `Phd2SlitConvergenceWorkflow` | 首次导星完成后的新帧窗口、精调循环、残差判定、移锁意图与局部迭代状态；输出严格通过或已有授权的 warning 试拍资格 | 不曝光 ATR，不重新连接设备，不管理整夜屋顶策略 |
| `AtrProbeWorkflow` | 试拍档位访问、过曝回退/弱信号延长、选定曝光档、需要重试拍标记和试拍计数 | 不直接增加科学合格帧；失效选档不重置本轮计数 |
| `AtrScienceWorkflow` | 科学尝试数、留存/接受/警告帧、积分时长、最终试拍复用记账和剩余时长 | 不重新取场或重校准；拒收帧保存但不冒充合格帧 |
| runner 的 `WorkflowPorts` 适配器 | 把上述有限请求接入现有设备客户端、即时安全门、证据、日志和持久化 | 不复制 workflow 的循环和科学判断，不获得新设备所有权 |

`AtrProbeWorkflow` 与 `AtrScienceWorkflow` 各有唯一状态写入者。runner 的既有计数
名称改为只读投影，保留 manifest/进度字段，不维护第二份可漂移的计数。最终试拍
由科学模块通过 `IAtrFinalProbeConsumer` 接受，引用同一个不可变文件且只计入一次；
一帧计划可由最终合格试拍完成，三帧计划仅补足缺少的科学帧。

PHD2 收敛接收同一会话、原账本、初始窗口、截止时间和恢复深度的请求对象；
G3 回程接收原持久化状态与路径，不由新 workflow 创建新的运动责任。用于测试的
可注入时钟在生产默认为系统时钟。所有 workflow 构造函数均不连接设备或执行 I/O。

### 保留的安全及连续性

- 即时天气、晨光、地平线、屋顶/镜盖、身份、设备所有权、导星输出与停止检查，
  仍通过原运行实例执行；不把科学质量 warning 变成安全豁免。
- G3 回程仍在实际运动前持久化完整预扣意图；校验目标镜筒侧、到位读回和稳定性。
  失败、取消和时间耗尽保留原账本；不重发预算或伪造回程完成。
- PHD2 的一张滚动新帧仍更新完整三帧窗口，不能用最后一张好帧覆盖前两张失败。
  原生 settle 超时与新帧实测分离；真实丢星、无修正输出、身份/拓扑改变不降级。
- 原有 warning 后 ATR 试拍仍可达；已用完精调运动额度但当前实测已具备试拍资格时，
  不新增运动也不凭运动额度耗尽反向否决该无运动路径。失效账本仍拒绝。
- 科学采集先检查剩余尝试预算，再考虑重试拍；恢复/翻转不会重置已接受数与积分。
  每帧保存后才判断接受，保存时温度不合格不能被误计为科学合格。
- 目标质量耗尽与整夜安全失败继续分开。原生双目标测试仍检查停止清理后跳至下一目标，
  停止未确认、天气 Unsafe、未知异常、取消和明确 EndNight 不借此继续。

## 行为测试，而不只是文件检查

增加 42 项 workflow 行为用例：ATR 17 项、G3 取场/回程 14 项、PHD2 收敛 11 项。
测试使用严格的有限接口替身，任何意外调用立即失败；不创建真实设备客户端。
覆盖实际循环、调用先后、重复调用、计数、失败和取消，不仅断言源码含有某个方法名。

既有安全顺序源码检查同步指向实际 workflow 与适配器。首次插件回归发现 43 处旧检查
仍查找原 runner 内的方法体/私有状态，全部逐项迁移；未通过删除安全断言来压低失败数。
两个前端入口一致性、原生失败跳目标、完整三帧更新的既有行为测试继续保留。

## 规模与仍需处理的债务

对比本轮开始的 0.4.0.276 工作区；统计生产 C#，排除 bin/obj，含注释与空行。
不把此前多轮未提交的更改算成本轮成果。

| 指标 | 重构前 | 重构后 |
| --- | ---: | ---: |
| 生产 C# 文件数 | 317 | 329 |
| 生产 C# 行数 | 93,123 | 93,626 |
| runner 主文件行数 | 16,981 | 16,073 |
| PHD2 入缝 partial 行数 | 5,127 | 4,506 |
| runner 所有 partial 合计 | 28,166 | 26,751 |

runner 减少 1,415 行，但**生产代码净增加 503 行**，主要是显式接口与适配器。
本轮收益是状态写入权、职责、可独立行为验证和故障边界，不冒称总行数减少。
删除了迁移后不再使用的旧辅助实现，没有为了减行压缩格式或降低可读性。

这还不是对整个 runner 的彻底解耦：WCS 粗居中/邻场搜索的低层实现、PHD2 初始
身份/选星/导星准备、跨阶段恢复及图像分析仍在共享 runner。下一步应沿现有有限
接口提取这些职责，而不是继续增加万能接口，或让新模块直接获得原始设备客户端。
本轮没有改变试拍算法、门限、运动预算和已发布数据格式来追求“更容易通过”。
