# 傍晚被误判为晨光停止（2026-10-21，0.4.0.301）

## 证据与原因

HD 219937 在 18:00:32（UTC+08:00）以 `NIGHT_DAWN_REACHED` 结束。
原运行 `UVEX-20261021T100031Z-c3d6f421095c440` 只有计划清单，没有开始采集；
停止发生在设备初始化之前。原序列的晨光高度为 −12°，截止为次日 00:30。

共享 `NativeSequencePlan.StopGate` 原先只判断太阳高度是否达到晨光阈值，
没有区别傍晚下降和清晨上升。因此日落后、尚未降到 −12° 的傍晚也会被当成
“天亮了”，与操作员观察到天色已经适合尝试拍摄并不矛盾。这不是目标太暗、
解算失败或截图所能证明的天气拒绝。

附带的 ATR/赤道仪“停止未确认”来自尚未连接的设备状态，不证明设备正在运动，
也不能反过来当作停止证明。原独立待机进入 `CloseoutFailed`，没有执行机械收口；
本次不将其描述为有效的软件安全看护。

## 最小修复与边界

- 在原晨光阈值上方，使用当前与一分钟前的 N.I.N.A. 太阳位置；仅当太阳已经
  低于地平线且仍在下降时，允许傍晚继续通过这个时间门。不是按本地钟点猜测，
  也不要求进程先见过黑夜，避免重启于晨光之后反而漏停。
- 上升到原阈值时仍产生 `NIGHT_DAWN_REACHED`；太阳在地平线上时即使下降也
  不放行。原绝对截止优先级不变，不延长本夜、目标或动作预算。
- 非有限太阳位置不能作为放行证据，返回既有 `NIGHT_SAFETY_READ_FAILED`；
  日志包含有效判定的当前高度、上一分钟高度及原阈值。
- 原生目标、运行期间和独立安全待机仍复用同一个门，没有增加第二套时间逻辑。
  天气、屋顶/镜盖、设备所有权、机械限位、取消、真实停止确认均未放宽。
- 设备未连接与设备明确忙碌的诊断文字分开；仅澄清含义，不伪造连接或停止状态。

这是晨光语义的实现纠错，不变更冻结设计、观测能力或设备授权。原始清单、日志、
照片与计划文件均未修改；没有通过关闭晨光保护、放宽阈值或修改截止规避问题。

## 回归

- 太阳上升/下降、阈值相等、白天下降、首次启动已到晨光、不同保存阈值、
  无效太阳位置、原截止优先和 UTC/本地时间等价。
- 2026-10-21 18:00 的代表性华东站点与次日清晨，用安装的 N.I.N.A. 星历进行
  日期复现。测试进程只读星历，采用固定 0.1 秒 DUT1 夹具避免依赖运行实例的
  地球自转数据库初始化；该夹具不是生产回退，也不写用户数据库。
- 真实调用两个原生目标容器：傍晚首目标质量失败并完成停止确认后，第二目标
  实际执行；结束策略、停止未确认、晚到 Unsafe、取消、截止和晨光仍拒绝下一目标。
- 独立安全待机在下降的傍晚等待、不误收口；随后晨光、原截止、Unsafe 或太阳
  信息不可用时执行一次正常收口路径。夹具不连接设备、不产生真实收口动作。
- 定向测试 63 项通过；发布构建零编译警告/错误，全部 3,826 项 .NET（插件
  2,376 项）、75 项 Python 和 Ruff 通过。历史指标对照 15 轮/38 张接受帧通过，
  沿用既有回放边界，不伪称重现全部设备/天空动力学。
- 四份冻结设计散列、严格发布审计、`git diff --check` 通过。169 个离线 UI
  PNG 与 .300 全部散列一致；离线星历/数据库未配置的既有 harness 日志不作为
  真实实例验收结果。离线通过不代表新版已成功完成实天观测。
