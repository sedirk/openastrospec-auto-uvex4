# 四类失败跳目标修复与安全监视器启动卡（0.4.0.286）

## 范围与结论

根据失败跳目标链路审计修复四类普通目标失败误升级为整夜停止的问题。
遵循 ADR-0031，未修改冻结设计、物理停止要求、独占所有权或设备/天气安全策略。
本轮安装重启不授权启动观测、重连设备、机械动作或自动续跑。

| 位置 | 原问题 | 修复 |
| --- | --- | --- |
| PHD2 回程/丢锁后的 G3 重新取场 | 两个通用包装码抹掉原始质量分类 | 只追加上下文，保留原码、scope、metrics、证据；真实安全失败也原样保留 |
| ATR 试拍选档 | 无可用饱和回退档被当成 Run 故障 | `NO_SAFE_SATURATION_BACKOFF` / `NO_SAFE_EXPOSURE_TIER` 明确为目标质量失败；不再拍必然削顶的科学帧，不丢已有试拍 |
| 严格旁星导星选择 | 有界原生选择耗尽且已停止仍是 Run 故障 | 两个严格分支在 checked stop 后给出目标质量结果；不强制切直导、不凭插件排名发导星命令 |
| G3 无星点阶梯 | 正常无星与坏像素/异常混用一个错误码 | 完整有效阶梯中的无星点保留三次原有有界重试，然后按目标策略跳过；缺帧/坏像素/采集或解算异常保留独立 Run 故障 |

目标质量结果不等于“已经停止”，也不等于“成功观测”。原生整夜容器继续要求：
保存的失败跳过策略、同一 coordinator 已完成退出、终态码一致、各所有者空闲、
运动账本清理确认、没有人工取消/Unsafe/截止。任一项不满足都不能启动下一目标。
重试和失败不重发运动、曝光或时间预算；下一目标正常取得自己的新证据。

## 安全监视器启动卡

名称统一为“OpenAstroSpec · 自动启动安全监视器”，描述与中英文模板同步。
仅通过 N.I.N.A. 原生 mediator 连接当前 Profile 已选择的监视器，不替换设备、不
打开网络天气源。保留主控实例、根开始区域、REAL 目标范围和运行互斥检查；已连接
则不重复连接。前后核对 Profile 与设备身份，取消不遗留后台 Connect 任务。

连接成功不等于 Safe：后续“等待到安全”、锁定调试配置、安全读回与运行期完整安全
链继续独立判定。AIWeather 仍可使用；通用连接不授权未经调试的适配器进行生产观测。
卡片类型、序列序列化字段、启用开关不变；已有序列无需重建。

## 回归方式

`TargetFailureContinuationTests` 新增 26 个案例：

- 四类生产结果（重新取场含两个入口）进入两个真实原生目标容器与同一 coordinator，
  断言第一个失败后第二个确实运行至 FinalizeObservation，不只测试分类函数。
- 每类同时验证 cleanup-failure 和 EndNight 不执行下一目标。
- 原始停止未确认、所有权/天气/未知故障不能被上下文包装变成可跳过。
- 混有坏像素、采集/解算异常、缺少内容证据、设备位置绑定或缺档的 G3 阶梯，以及
  ATR 非有限指标，不能伪装为普通光学失败。G3 三次重试上限不变。
- 原有取消、Unsafe、截止、停止/账本、终态事件和 coordinator 退出竞态回归继续执行。

安全卡同时覆盖 AIWeather 与通用适配器、幂等连接、未选/空白、身份不符、连接失败、
连接中改选择及取消；Unsafe 状态不会因连接被改成 Safe。
