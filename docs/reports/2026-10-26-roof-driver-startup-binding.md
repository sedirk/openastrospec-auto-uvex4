# 屋顶驱动更换导致的启动阻断（0.4.0.318）

## 原因与边界

本次未进入目标曝光或解析。在同一个光谱主控 Profile 中，屋顶选择从
`RRCIAdvanced.Dome` 变为 `RRCI.Dome`，但安装标定仍绑定旧驱动。
静态校验正确拒绝沿用“所有赤道仪位置均无干涉”的旧确认；随后真实模式
启动卡失败。原生预检查只显示“未完成调试”和模拟模式提示，掩盖了真正原因。
这不是本轮满月解析问题，也不表示光学标定全部失效。

操作员明确确认：只有驱动变化，仍为同一物理屋顶、同一赤道仪，原净空条件
未变。据此生成新的本机派生标定包，不覆盖旧包。原 Night Setup、测量证据、
光学参数、对焦与赤道仪运动限额、天气门和观测预算保持不变。新的屋顶身份
和本次确认来源写入派生记录，通过原有 commissioning builder 校验；没有
把两个不同驱动自动认作同一设备，也没有直接将调试确认开关写成通过。

## 软件修复

- 原生真实模式卡与目标预检查显示当前进程、当前 Profile 最近的标定校验原因，
  给出“主控台 → OpenAstroSpec → 自动准备”入口，不再用派生的模拟模式错误
  代替未通过的标定原因。
- 屋顶身份错误列明原绑定和当前选择，并说明同一物理设备更换驱动的确认路径。
- 只读桥增加标定确认状态、加载结果及详细问题，避免日志缺项时只能逐页找。
- 诊断缓存不能授予权限；跨 Profile 不复用，重新校验清除旧错误。
- 尚未完成操作员要求的“一站式设备变更前端”。本版解决当前绑定及诊断可达性；
  就地确认/重绑交互将在解析问题验证后处理，不能把此报告当成该前端已完成。
