## 生产行为

只读 Windows Update Agent 的 [ISystemInformation.RebootRequired](https://learn.microsoft.com/en-us/windows/win32/api/wuapi/nf-wuapi-isysteminformation-get_rebootrequired)。
不扫描更新，不用下载、商店更新、重命名队列或仅有更新通知代替明确的待重启状态。
开顶准备前和真正发出 OpenShutter 前都要新读；整夜、单目标及独立安全待机约每 5 秒复查。
单次读取最多等 2 秒；底层查询未返回不再并发增加 COM 调用。读取失败不是待重启证据，
不会仅因此发起机械收口，但不放行新的无人开顶。模拟不读操作系统，不操作设备。

| 原绑定屋顶 / 运行边界 | 明确待重启后的处置 |
| --- | --- |
| 尚未开始，已读回静止且 Closed | 不开顶、不开始目标、不为此执行 Home/Park。只确认屋顶，不声称完成其他目标。 |
| 正在观测 | 停止开始新工作，中断并等待本轮采集退出；已保存原片保留。不等待整张长曝光，不自动续拍。 |
| 已开，且原所有者、停机、联锁和屋顶权限有效 | 由原所有者调用已有的关盖/屋顶/停放流程；顺序仍取决于已标定的台站净空模式；只做一次，核对终态。 |
| 屋顶正在动 | 在原屋顶过渡时限内只读等待；已在关顶的不重复下令。读不出终态仍需报警。 |
| 选错设备、持续 Error、断连、停止未知或仅人工监管 | 不猜屋顶位置，不强行关顶。提示现场处理；独立监控不升级成机械权限。已要求收口的旧待机不能被新目标抢占。 |

正常天气危险、晨光、原截止和回程/所有权责任仍独立有效。提前机械收口前，重新核对原 ATR（含手动预览）、
原赤道仪转向/脉冲和 PHD2/调焦的停止状态；已启用同步测光或有作业责任时，还向原测光所有者只读核对全局空闲，
不从新建对象的空作业表推断设备已停。本功能只在 N.I.N.A. 主控进程存活时工作；
重启不根据旧日志自动连接设备、补发动作或启动观测。Windows [使用时段](https://learn.microsoft.com/en-us/windows/deployment/update/waas-restart)
不是硬件联锁，也不能覆盖[系统强制截止](https://learn.microsoft.com/en-us/windows/deployment/update/wufb-compliancedeadlines)或人工重启。

## RRCI / USB 的初步排查

截至这次检查，在当前保留的 N.I.N.A. 日志中，24 个日期、73 份日志共有 74 条
`Invalid ASCOM shutter state 5`，每条之后 1 秒内同一日志都报告 `RRCI.Dome` 连接成功。
11 月 15 日 04:51:45.700 返回 5，04:51:45.722 报连接成功。此前 01:30 的同一现象之后，
HD 18552 实际通过了要求屋顶开的 Night Setup 并取得 G3 图像。因此 5 **既不证明屋顶关闭，
也不证明 USB 一直掉线**。ASCOM 定义的[屋顶状态为 0–4](https://ascom-standards.org/help/html/T_ASCOM_DeviceInterface_ShutterState.htm)；
N.I.N.A. 将 5 映射成 Error 是正确的。在首次准备期间，同一绑定刚返回 Error 时最多只读复核
3 秒，保存首次/末次状态及耗时；持续 Error 或换设备不放行，不重连、不重复开顶。

04:46–04:54 所查 System / Kernel-PnP 配置、设备管理与驱动看门狗日志没有同时段 USB/PnP 事件。
这无法排除瞬时掉电、串口响应超时、控制器/限位信号、过长链路等问题。当前机器的 32 位 ASCOM
配置中有一个保存的屋顶串口，而检查时该端口并不在 Windows 的当前串口映射中；这是**不同时间**
的线索，不能据此改绑、认定线路接法或推断凌晨掉电。

再发生时，若现场安全允许，先记时间与物理限位/指示灯、电源管理器供电读数、Windows 当时是否仍枚举
原串口、RRCI 本身是否也读不出终态；保留 N.I.N.A. 当次日志，再按现场流程处理。重启程序可能同时
重置串口句柄/控制器握手，重启电脑也会重新枚举 USB，单凭哪种重启后恢复不能定位根因。插件不扫描端口，
不重启电源、驱动、电脑或切换屋顶所有者。实物布线和电压未测量。
