# 0.4.0.283 — 校时后优先继续当前目标

## 原因与设计

.282 的时钟修复位于原目标 coordinator/原生子项都退出后的边界；该边界只有
“完成 / 跳过 / 停止”结果，校时成功只能跳过。并不是校时本身要求放弃目标。
按用户本次要求，[ADR-0035](../adr/0035-clock-repair-same-target-continuation.md)
增加一次同目标新分段，沿用唯一生产 runner，不在旧导星/曝光中重连。

1. 保留旧失败 manifest 和全部原始文件，确认停止/退役，再执行 .282 的有界校时。
2. 校时读回成功且原预算有余量时，持久化续拍意图、分段关联和累计账目。
3. 原生目标卡重走定位、取场、测缝、选星导星及 ATR 试拍，只补缺少的科学帧。
4. 成功只计一次目标完成；取场/入缝等目标质量失败，停止确认后执行下一卡。

目标计数从中天类提取为共享 `NativeTargetSession`；翻转与校时共享计数、尝试、
积分与导星恢复额度。`ClockContinuationBudget` 只携带数值消耗和上限，不携带可执行
旧坐标/锁点/帧权威。G3 新原点只来自新回读，所有原消耗、时间和上限继续生效。
独立精调累计次数/距离和起始时间同样继承。校时不再经新 runner 隐藏第二次启动重连。
一次原生目标最多一次校时续拍，整夜校时修复仍最多一次。

已合格帧继续计入；错误或未验收帧只保留，不追认为合格。旧最终试拍不重复复用。
原运动时钟已耗尽时不能续发动作；原目标时间到期是目标跳过，不误作整夜截止。
Unsafe、晨光、整夜截止、取消、所有权与未知停止仍优先。

## 自动关顶语义（本轮保存配置与代码核对）

本轮 `HoldOpenAfterTargets=true`，截止为当地 05:00，晨光停止启用、太阳高度 −12°。
结束/目标故障/普通取消只让观测退出并将看护交给独立待机，不因此立即关顶；
到原截止、晨光达到设定高度、AIWeather Unsafe 或监视器断连/绑定改变，会由同一
安全链尝试一次有超时的核验收口。单纯天气数值变化而 AIWeather 仍 Safe 不关顶。
停止或设备回读未确认时保留错误，不把“下发收口”写成“屋顶已关闭”。

ADR-0033 明确独立待机只独立于**观测序列**，不是独立 Windows 服务。退出 N.I.N.A.
会结束它，重启不会从旧日志自动恢复，也不自动连接设备/启动观测。故本次安装重启
后，旧 05:00 截止与软件天气收口不能被假定仍执行；必须人工/独立保护持续接管，
直至显式新序列重新建立保护。本次不授权或主动执行关顶、Home、Park 或新观测。
