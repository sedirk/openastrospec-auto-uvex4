# 2026-10-07 准备页简化与安装记录误阻塞

## 报告与证据

用户报告安装方案列表混入大量工程试验名，设备候选指向历史“测光” Profile，
准备页只显示两个泛化阻塞项，无法理解或处理。

本机只读检查确认了三个独立问题：

1. 设备候选按扫描顺序去重，历史 Profile 的来源标签可压过当前光谱 Profile。
   此标签不等于设备实际所有权，但旧文案没有说清。
2. 光谱主控的原生 Profile 实际选择了 QHY 相机及测光滤镜轮，和已保存的 ATR 绑定不一致。
   这不是仅靠改标签可以解决的问题；应保留所有权检查并纠正原生选择。
3. 当前选择为旧试验安装包；已经验证的后续 USB 重绑定包在用户级 commissioning 目录，
   旧目录扫描只发现系统级目录和记住的单个路径。切换旧包后会漏掉后续包。
   下拉选择立即持久化、下次启动加载以及只给失败计数的旧行为又放大了混乱。

此外，标定自动确认把目标及原生设备启动条件与标定文件校验混在一起，
导致完整标定被另一类准备问题标成未确认。

## 软件修改

- 日常核对从七卡合并为三块：目标与曝光、当前设备与光学配置、具体待处理项。
  目标、计划、设备维护仍有直接入口；不增设第二个参数编辑器或准备执行引擎。
- 安装包显示日期、狭缝和导星曝光摘要；说明明确其是安装记录，不是目标/曝光方案。
  默认隐藏历史调试项，提供显式显示开关，不删除历史文件。
- 同时扫描系统级、用户级 commissioning；当前 Profile 优先解释重复设备 ID。
  来源标签不再暗示所有者。已有有效设备选择优先；只有空值且候选唯一才自动填入。
- 下拉浏览不持久化、不应用。只有显式加载才记录已应用包；默认不在启动覆盖明确选择。
- “重新检查当前配置”验证已应用包，不重载旧运行参数，也不应用未加载的下拉选择。
  即使旧 Profile 关闭自动确认，显式重新检查仍可执行完整文件验证。
- 标定校验在隔离快照中完成；通过原 preset/锁定本夜配置加载器的哈希、引用和身份检查后
  才写通过状态，不暂时给可变 Profile 授权。确认标记只读，不能勾选绕过验证。
- 目标及原生相机/滤镜轮要求继续在启动条件中检查，失败具体展示。

没有修改冻结设计、运动预算、入缝/导星/光谱验收门、设备单一所有者或真实会话授权。
没有凭候选发现声称硬件连接成功。
