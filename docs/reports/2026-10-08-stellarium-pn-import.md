# 2026-10-08 Stellarium 无常用名深空目标导入修复

## 现场问题与根因

本次仅处理用户第二张截图中的目标导入失败；第一、第三张是重复的历史
PHD2 入缝问题，不作为当前故障或新的实机观测授权。

Stellarium 当前选择为 IC 2149。同一只读接口响应具有：

```json
{
  "name": "",
  "localized-name": "",
  "designations": "IC 2149 - PGC 2902418 - PK 166+10.1 - PN G166.1+10.4",
  "type": "行星状星云",
  "object-type": "planetary nebula",
  "vmag": 10.7799997
}
```

旧导入器在读取目录编号前强制要求非空 `name`，产生
`Selected object has no stable name`，外层将其显示成
`STELLARIUM_COORDINATE_CONVERSION_FAILED`。这不是 PN 类型不受支持，
也不是已证明坐标本身损坏，而是遗漏了只有目录身份的深空目标。

## 0.4.0.233 的改动

- 同次响应内读取 `name`、`localized-name`、`designation` 和 `designations`。
  没有常用名时，使用目录编号作为目标名，并独立保留目录 ID。
- 多目录列表只按 ` - ` 分隔，不破坏 PK、PN、BD 等编号内部的正负号。
- 导入前后复核完整身份、类型、选择状态与坐标；目标切换或坐标不一致仍拒绝。
  不借用上一次目标的显示名，不降低现有坐标标准化和来源核验要求。
- 确实没有名称和目录身份时，报告 `STELLARIUM_TARGET_IDENTITY_MISSING`，
  保持已有目标草稿不变，不再冒充坐标换算问题。
- 未改变 PN 的目录位置/WCS 优先策略、导星、曝光或运动预算。
