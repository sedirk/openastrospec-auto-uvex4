# 移锁稳定终态与独立收口接口（0.4.0.263）

日期：2026-10-10。范围为用户报告的 `PHD2_LOCK_RETURN_EPOCH_CHANGED`、
“失败不关顶未生效”，以及明确要求分离单次运行和序列运行的可选收口接口。

## 原始证据与根因

20:29 开始的 WR 134 运行在 20:33:46 提交一次约 25 px 移锁，原锁点
`(947.92, 454.01)`，新锁点约 `(967.2346, 469.8828)`。账本已经计入一次动作，
当时连接纪元为 1、导星纪元为 109；没有取得光谱科学帧。

PHD2 的原生稳定要求为 3 px / 5 秒，超时 18 秒。20:34:06 的 SettleDone
返回失败：7 帧、0 dropped，原生应用仍为 Guiding。本地 guide 请求已经推进导星
纪元，而旧实现只在稳定成功之后更新持久化移锁账本。失败分支先抛出异常，回程检查
因而把同一次本地请求的 109 → 110 误判为外部会话变化。

这里有两个不同事实：**原生稳定超时是真实失败；随后纪元不匹配是本地账本交接错误**。
本次不把失败稳定判为成功，不声称星已稳定入缝，也不追溯修改原记录。

20:35 的整夜记录已启用保持开顶且截止仍为次日 00:30，没有收到 Unsafe、普通取消或
结束本夜请求。目标失败后虽确认了物理空闲，但未结回程阻止后续目标；旧条件把
`StopFollowingTargets` 同时当作不能待机，跳过待机直接进入 finally 关顶。

## 修复

1. 在判断 settle 成败前，先验证并绑定本次本地请求的终态身份：连接未变、应用仍
   Guiding、请求已接受、操作 ID 与终态匹配、新事件存在、没有校准变化、实际锁点仍
   匹配刚验证的锁点。失败稳定仍失败，回程仍受原预算约束；断连、丢星、暂停、输出
   失败、未知纪元或锁点变化均不能借此放行。新增终态证据明确不重置预算、不证明到位。
2. 按 ADR-0026，保持开顶时，物理停止已独立确认的阻断目标也进入受保护待机。
   未结运动记录仍保留，后续目标不继续；待机不发曝光、移锁、Home、Park 或屋顶动作。
3. 待机保留整夜预约、截止和安全订阅，并只读复核安全监视器连接/状态/身份及环境
   绑定。Unsafe、监视失联、截止、晨光或明确结束本夜仍转入已有受检收口路径。
   普通取消仍不发机械收口命令，由操作者接管。

## 两类收口选择

- 独立自动观测：高级设置 → 站点与模拟中显示“单次完成后关顶”和“单次普通失败后
  关顶”，绑定已有 Profile 设置。只影响下一轮独立运行快照；关闭是人工接管，不是
  无人值守待机。完整安全链运行中 Unsafe 不受普通失败开关控制。
- 原生序列：新增 `OpenAstroSpec · 关顶与整夜收口（可选）`，只能作为光谱整夜容器
  的最后一个直接子项，最多一个。开关在启动时锁定，开启普通结束/失败后收口，关闭
  则在确认空闲后保持受保护待机。目标提前失败、未走到该条目也按已锁定选择处理。
- 新条目只是可序列化的策略入口，不直接拥有屋顶。实际动作仍由同一整夜所有者调用
  `CloseSequenceNightAsync`，不引入第二个设备控制端。
- 有条目时优先使用它；没有时兼容原 `HoldOpenAfterTargets`。两份分发模板已加入
  默认开启的新条目；本机前后半夜十目标文件本次未覆盖，原保持开顶设置仍适用。
