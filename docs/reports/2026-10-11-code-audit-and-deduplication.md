# 观测核心代码审计与去重（0.4.0.276，未安装）

后续按职责提取与 .277 安装记录见
[观测流程职责与状态边界重构](2026-10-11-observation-workflow-boundaries.md)。

## 结论与范围

单次运行和高级序列是两个入口，**不是两套独立的观测执行算法**。两者都使用
`RealObservationStageRunnerFactory`、`ObservationCoordinatorHost`、
`ObservationRunCoordinator` 和 `RealObservationStageRunner`。高级序列增加的
`SequencerStageBridge` 负责让 N.I.N.A. 的指令、条件和触发器参与阶段调度，
不再实现一份取场、入缝或光谱采集算法。

```text
单次运行面板 ───────────────────┐
                               ├─ 同一计划/配置工厂 ─ 同一 host/coordinator ─ 同一 runner
高级序列目标容器 ─ 阶段调度桥 ───┘
```

夜间容器自己的多目标调度、目标失败跳过、截止时间和整夜收口仍有独立职责。
PHD2 移锁与独立标定的赤道仪像素映射也是不同的设备运动能力，不是多余的第二套
整夜执行器；本次没有擅自删除任何已支持、仍可达的观测能力。

本次对 `src/` 的 320 个生产 C# 文件做规模和重复片段扫描，重点人工追踪双入口、
标定契约、导星窗口及 G3 回程的调用关系。删除候选核对生产、测试及相关配置引用，
不因某个 WPF 回调没有普通 C# 调用就将其删除。这是**有明确范围的可维护性审计**，
不是逐行覆盖整个仓库的安全认证，也不证明所有实天故障已经消失。

## 发现及处理

| 发现 | 影响 | 本轮处理 |
| --- | --- | --- |
| 标定工具与插件复制了 PHD2 入缝及鬼影标定记录、验证代码 | 同一文件在生成端和消费端可能出现规则漂移 | 合并为共享类型和共享验证器 |
| 导星 warning 上限验证已发生实现漂移 | 非法 preferred 值与禁用 ceiling 的组合，两个验证器返回的错误集合不同 | 使用原生产验证器；有效配置的接受范围不变 |
| 已停用的精度拒绝异常仍保留 catch 和停止处理器 | 看代码会误以为精度仍会硬停止；维护者可能修错分支 | 删除没有生产 throw 的异常及其不可达处理分支；保留历史错误码识别 |
| 旧的无持久化账本 G3 回程函数仍占 181 行 | 与真正使用的持久化回程并存，增加误用和阅读成本 | 删除已标记编译期禁止调用、且没有调用者的旧函数 |
| 旧暗缝叠帧、时间共识、重试、稳定等待及 epoch 重绑定策略只被测试引用 | 测试通过并不代表实际生产路径被验证 | 删除失去生产调用的实现；将连续性、坏帧及停止检查测试对齐实际路径 |
| 解析器运行快照构建复制了相同字段映射 | 增减字段时容易漏改其中一处 | 用同一个 `CaptureCore` 构建，两种调用保留各自锁定值 |
| 真实执行器仍是超大共享可变对象 | 改一个阶段容易影响其他阶段的状态和恢复逻辑 | 本轮削减死代码，记录后续按职责提取的边界；未冒充已完成全面解耦 |

这些死代码原本就不可达，**不能把它们说成之前连续观测失败的直接原因**。
此前已确认的科学质量选项与安全模式耦合、单帧/三帧契约和目标失败分类问题，见
[0.4.0.275 回归记录](2026-10-11-science-quality-and-window-regression.md)。

### 共享契约及兼容性

- `UvexAdv.Phd2.Phd2SlitPlacementCommissioning` 是工具与插件共同使用的定义；
  纯数学交接半径策略也放到 `UvexAdv.Phd2`，不让下层反向引用 N.I.N.A. 插件。
- `UvexAdv.Observatory.GhostAssistanceCommissioning` 和 `GhostRuntimeFingerprint`
  是鬼影标定的共同定义；仍由原验证器核对政策散列和安装/光路指纹。
- 保留已发布 JSON 字段、数字枚举及默认值。三个仅运行时计算的 PHD2 属性使用
  `JsonIgnore`，不会变成新的标定输入；旧 JSON 带这些额外计算字段仍可读取。
- 在修改前保存两种旧工具 DTO 的固定测试样本序列化 SHA-256，重构后逐字节
  对照。PHD2 样本为 `230AB8BDAE3CEFB12DEA24399ACE77A36BF711F79FD901F7BB6DFC31A90D5E8C`，
  鬼影样本为 `77F8A67A8D8FABFC6BA65775A1DCE9A4780876D5936778DEB97225297F3E1DB6`。
  这是固定样本的兼容性证据，不是声称对所有可能 JSON 输入作了形式化证明。
- 没有重写现有标定文件、Profile、观测数据或散列。C# 内部/工具类型名称调整后，
  本仓库所有消费者一起编译；以后部署必须安装整套构建产物，不能只替换主 DLL。

### 删除的是旧实现，不是安全检查

仍使用 `ReturnDurableG3AcquisitionToOriginAsync` 做真实 G3 回程，原有持久化意图、
完整预扣运动预算、地平线、镜筒侧、停止证明及到位读回没有改变。
`CompletePendingG3SearchReturnAsync` 仍能识别并核对旧内存回程标记，不伪造回位。

当前导星实测仍使用 `G3RunLedSlitGeometryPolicy`、`Phd2FreshTargetWindow`、
`CaptureConsecutiveWindowAsync`、`BeginFreshResidualObservation` 和
`Phd2MeasuredReturnWindow`。天气、屋顶、晨光、设备所有权、真实修正输出、
目标身份和物理停止检查不变。完整安全链下的 warning 试拍、滚动一帧更新完整
三帧窗口，以及停止确认后跳过目标，保留 0.4.0.275 的行为。

`PHD2_PRE_MOTION_GUIDE_WINDOW_REJECTED` 仅作为历史兼容代码保留，用于旧结果的
展示、分类和回归，不再保留一个没有任何生产调用的精度停止实现。

解析器的 `CaptureCurrent` 仍规范化当前运行已锁定的 implementation 和 downsample，
避免解析器临时回写 downsample 被误认为人为改配置；其他实时 Profile 字段的漂移
仍会被发现。专门测试初始捕获、运行期捕获和字段变化，不只比较源码文本。

## 量化结果

计数范围为生产 `src/**/*.cs`，包含空行/注释，排除 `bin/obj`；不把测试和文档
删减计入生产代码收益。比较基准是**本轮开始的工作区**，不是含有多轮尚未提交
更改的 Git HEAD，因而不会把前几轮修改冒算成本次精简。

为候选，再人工判读；这不是完整的语义克隆检测或维护成本评分。

## 尚未解决的结构性债务

1. **高优先级：runner 的职责和共享状态仍太多。** 主文件仍近 1.7 万行，所有
   partial 合计约 2.8 万行。后续适合依次提取 G3 取场/回程、PHD2 入缝、ATR 试拍
   与科学采集，但每一步需要保持同一设备 owner、取消边界、时钟和运动账本。
   只将大类搬到更多 partial 文件不能解决这一点；再写一套新 runner 也会重造重复。
2. **中优先级：部分回归仍高度依赖源码字符串。** 保留这类测试检查“安全门在命令
   前”的边界，同时优先增加实际工厂/host/阶段桥的行为测试。不能只靠 `Assert.Contains`
   推断设备流程能成功，更不能用单测数量代替覆盖有效性。
3. **中优先级：仍有短片段重复。** 例如不同运动账本的原子写入和配置/哈希载荷字段。
   它们有不同 schema、兼容性和故障语义，不能为了少几十行先塞进一个不透明的
   通用持久化框架。本轮优先消除了已经发生漂移的长验证器复制。
